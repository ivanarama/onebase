## Что нового

`v0.9.9` — большой релиз про **безопасность, поиск и надёжность данных**. База
получила единый полнотекстовый поиск (шапка, страница результатов, REST и DSL),
второй фактор (TOTP) и единый вход через внешнего провайдера (OIDC), управление
секретами с мастер-ключом и поколоночное маскирование персональных данных.
Схему прикладной конфигурации теперь можно безопасно перестраивать —
переименование, смена типа и удаление реквизитов отслеживаются по устойчивому id
поля, а не по имени колонки. Добавились сервисные команды `onebase doctor` и
`onebase vacuum`, а формы, отчёты и лаунчер закрыли длинный хвост шероховатостей.

## Безопасность и доступ

- **Второй фактор (TOTP) и единый вход (SSO/OIDC)** — «Профиль → Второй фактор»
  включает 2FA с резервными кодами; политики базы могут требовать второй фактор
  от администраторов и заданных ролей. Единый вход настраивается для Keycloak,
  Google Workspace, Microsoft Entra ID и любого совместимого провайдера
  (Authorization Code + PKCE, проверка `id_token`, маппинг ролей по claim'ам).
  Привязка второго фактора на входе теперь требует **одноразового кода от
  администратора** — по одному паролю чужой фактор не закрепить.
- **Управление секретами и мастер-ключ** — единый резолвер ссылок `env:` / `file:`
  / `enc:`, шифрование секретов конфигурации мастер-ключом, команда
  `onebase secret` (keygen/encrypt/set/list/rotate) и линт гигиены секретов с
  предупреждением о копии.
- **Поколоночное маскирование ПДн** — отчёты, AI-доступ, запросы и модули
  маскируют скрытые пользователю реквизиты вместо отказа; закрыты обходы через
  алиасы, объединения и поиск (совпадение по скрытому значению не превращает
  поиск в оракул).
- **Строковые политики (RLS) в запросах** — фильтр политики не теряется при `ИЛИ`
  в собственном `ГДЕ` и в запросах с `ОБЪЕДИНИТЬ`.

## Полнотекстовый поиск

- **Единый поиск по всей базе** — строка в шапке и страница результатов, REST
  `/api/v2/search`, встроенная функция `ПолнотекстовыйПоиск` в DSL. Индекс
  обновляется на всех путях записи; пагинация отдаёт непрозрачный курсор, а не
  сырое смещение. Команда `onebase reindex` пересобирает индекс.
- Права накладываются единым слоем: объектный RBAC, строковые политики и
  маскирование реквизитов — выдача поиска совпадает с тем, что показали бы списки.

## Схема и данные

- **Безопасная реструктуризация схемы (план 81)** — реквизиты отслеживаются по
  устойчивому `id`, поэтому переименование сохраняет данные (не «поле исчезло,
  другое появилось»), а смена типа и удаление применяются осознанно. `onebase
  migrate --dry-run` показывает план, `--allow-destructive` разрешает потери.
  Весь план одной таблицы и запись карты полей идут в одной транзакции — сбой
  посреди плана откатывается целиком.

## Диагностика и обслуживание

- **`onebase doctor`** — проверка и (по явному разрешению) исправление базы по
  нескольким осям; страница диагностики в администрировании вместо одной кнопки
  очистки.
- **`onebase vacuum`** — сжатие базы после массового удаления.

## Формы и отчёты

- **Отчёт открывается свёрнутым** — `appearance.collapse_to`: видны верхние группы
  с итогами, глубже — по клику (раскрытие ровно на один уровень).
- **`Объект.Записать()` в обработчике управляемой формы** — команда формы может
  записать ещё не сохранённую карточку; версия и поля-результаты корректно
  доезжают до клиента, а табличные части перечитываются после обработчика, не
  затирая правки пользователя в гриде.
- **Картинки в управляемой форме** — поле типа `image` грузит и показывает
  изображение (раньше рендерилось как текст); `onebase check` теперь отклоняет
  выдуманные виды элементов формы.
- **Команды и пикеры формы без ручной разметки** и **своя подпись кнопки
  «Провести»** (`post_caption`).

## Лаунчер

- **Открыть базу в локальную сеть** — карточка базы получила выбор «Доступ по
  сети» (127.0.0.1 по умолчанию / 0.0.0.0 — все интерфейсы): базу можно открыть
  с другой машины, флаг `--host` пробрасывается в запуск.
- **Быстрое переключение баз** — статус живости и данные `app.yaml` кэшируются и
  пробуются параллельно, список больше не тормозит на каждом переключении.
- **Кириллица в путях (Windows)** — диалоги выбора папки/файла корректно
  возвращают пути с русскими каталогами.
- Форма списка сущности создаётся как список, состав форм сохраняется в
  конфигурацию в БД.

## Прочее

- Управляемая форма: снятый флажок и правки шапки не откатываются перечитыванием;
  нередактируемые поля-результаты не отстают на шаг; команда формы не виснет,
  если модуль открывает транзакцию.
- Браузерный autofill больше не смешивает значения «Наименование» всех
  справочников.

## Установка

### Windows
1. Скачайте `onebase-windows-amd64.zip`
2. Распакуйте в любую папку, например `C:\onebase\`
3. Запустите `onebase-gui.exe`

### Linux / macOS
```bash
tar xzf onebase-linux-amd64.tar.gz
./onebase-linux-amd64/onebase start
```

### Требования
- PostgreSQL 14+ нужен только для многопользовательского режима
- Для SQLite-режима дополнительных зависимостей нет
