# Чтение связей объектов: storage-контракт (план 171, срез A)

`CheckRefs` и граф используют единую физическую инвентаризацию ссылок:
реквизиты шапок/ТЧ, измерения, ресурсы и атрибуты накопления, измерения и
ресурсы сведений, ресурсы и нумерованные субконто бухгалтерии. `CheckRefs`
сохраняет сигнатуру, порядок `RefInfo`, подсчёт физических строк и отказ при
ошибке любого COUNT, включая независимые регистры и сирот.

`ReferenceSources(rootName, registry)` возвращает логические ключи источников.
Он не читает БД и не проверяет права. `ReferenceSourceKey` содержит направление
(`incoming` / `basis`), семейство/имя, ТЧ/поле и тип проецируемого узла.
Для каждого поля регистра создаётся отдельный поток для каждого документа:
JOIN проверяет существование регистратора и точное `recorder_type`.
Независимый инфорегистр не имеет навигационного потока. Синтетический,
неизвестный, пустой или осиротевший регистратор не создаёт узел.

Включение `ReferenceRead` — явное разрешение читать конкретное поле источника.
Отсутствие источника в списке означает, что SQL для него не исполняется; nil
`Predicate` внутри включённой записи разрешает все его строки. **Вызывающий код
обязан до включения проверить объектное/полевое право и полный доступ к обеим
компонентам пары регистратора.** Предикат строки компилируется через
`PredicateSQLQualified`: для ТЧ он относится к владельцу, для регистра — к
соответствующей synthetic metadata. Strict RLS для сущностей и владельцев ТЧ
требует `RowFilterEvaluated`, как существующий List. Storage не вычисляет
root/target RBAC/RLS и не создаёт подписи или URL.

`ReadReferencePage(ctx, rootName, rootID, registry, read, pageSize, cursor)`
возвращает DISTINCT-ключи одного источника. Размер страницы — 1…1000, cursor
непрозрачный, связан с корнем, источником и скомпилированным предикатом. SQL
сортируется по UUID и продолжает строго после последнего UUID, без OFFSET.
Один поток имеет постоянные kind/entity; межтиповая сортировка выполняется
в Go, поэтому локальная collation PostgreSQL не меняет порядок типов.
`NextCursor == ""` означает исчерпание потока. Каждая SQL-выборка ограничена
`pageSize + 1`; SQL-курсор закрывается и `rows.Err()` проверяется до возврата.
При ошибке вся страница отбрасывается.

`NewReferenceIterator(rootName, rootID, registry, reads, pageSize)` проверяет
источники и компилирует все политики до чтения. `Next(ctx)` выполняет k-way
merge страниц по `(kind, canonical entity, UUID)` и возвращает один уникальный
`ReferenceCandidate` со всеми отношениями и происхождениями. Его нужно читать
до `nil, nil`; ошибка делает итератор непригодным для дальнейшего чтения.
Память ограничена числом выбранных потоков × размером страницы. Итератор не
держит SQL-курсор между вызовами. Метаданные и предикаты не следует менять
во время обхода; это чтение живых данных, без обещания снимка между страницами.
Для согласованного снимка вызывающий может использовать существующий контекст
транзакции. Удаление ранее прочитанной строки не сдвигает последующие страницы.

Для направления `basis` берутся только реально сохранённые ссылки шапки/ТЧ
текущего документа на типы из `BasedOn`; совпадение разрешённых типов само по
себе не создаёт ребро. Входящие ссылки документа такого типа получают отношение
`based_on`, остальные ссылки сущностей — `reference`, движения — `register`.
Отношения агрегируются до возврата ключа, в том числе на границе страниц.

Следующий срез B проверяет доступ к каждому target и продолжает `Next`, пока
не найдёт достаточное число доступных уникальных узлов. Storage-page size
не является HTTP-лимитом: скрытый target не расходует видимую сотню. Если
обход закончился ошибкой, вызывающий обязан отбросить накопленный ответ целиком.
Защитные пределы времени/объёма обхода также относятся к срезу B.
HTTP, UI, миграции, родительская #1411 и срезы B–D в этот контракт не входят.
