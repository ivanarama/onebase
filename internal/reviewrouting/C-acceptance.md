# Срез C: диагностика, Dashboard и операторская приёмка

Кодовая задача OneBase #1910 после совместной приёмки B (#2453 / PromptPilot #228).
Парная кодовая часть — PromptPilot #153, родительский план — 195 / #1836.

Health дополнительно описывает категории и evidence, получателя, попытку/лимит,
точные PR/HEAD и время перехода. Parser, маршрутизация, бюджет и полномочия
стадий A/B не реализуются повторно. Product/safety, insufficient data и
operational tool_error не объединяются в один запрос продуктового решения.

Публичные CLI fixtures и API/UI проверки PromptPilot должны отличать эти
состояния, сохранять неизвестную полноту и не интерпретировать произвольную
прозу или needs-decision как категорию. Существующие очереди остаются прежними.

Для кода обязательны build ./..., count=1 test/vet затронутых пакетов, lint,
восемь CI, независимое ревью и общая приёмка точной пары. Отдельная manual-задача
учитывает immutable релиз, staging, ограниченный пилот и управляемую установку.
Родитель #1836 не закрывается до фактической общей приёмки этого остатка.

## Дополнительный health-формат

`pipelinehealth -json -technical-handoff` добавляет `routing_observation`
версии `routing-observation-v1`. Это только представление: прежние очереди,
контракты допуска и mutation gates не меняются. При выключенном флаге новое
поле отсутствует. Старый потребитель может его проигнорировать.

Каждая строка связывает PR/current HEAD, фактический маршрут и получателя,
расход lifetime reservations/лимит, ссылку на immutable publication/completion
и SHA256 отчёта. Блокеры и product options берутся из последнего канонического
completed REVIEW только при совпадении текущего epoch, identity и автора.
Старый HEAD/epoch показывается как `older_head_or_epoch`, без текущих блокеров;
непроверяемая история — `unknown` и `budget_used: null`, а не ноль.

`transition_at` — время последней проверенной completion/reservation/phase/
settlement; `transition_kind` называет именно это событие. Это не выдуманное
время появления метки. Конкретный executor показывается только для связанной
с текущим HEAD технической попытки; остальные получатели — роли.

Вывод ограничен 128 PR и 64 блокерами на PR. Усечение PR явно снимает complete;
число пропущенных блокеров сохраняется отдельно, полный отчёт остаётся по source.
Категории всех блокеров сохраняются и при усечении подробностей.

Операционные ошибки исполняющего инструмента приходят из task/run history
PromptPilot, а не угадываются из REVIEW или метки needs-decision.

Публичные Go CLI тесты сохраняют точные source, HEAD, категорию и lifetime
расход в восьми исторических сценариях. JSON для парного API/UI произведён
на immutable checkpoint `38f96937fa7afc416c087fb64c76f542a5e441f1` с теми же
фактическими исходниками checker; SHA256 данных
`8ecb3121a817bfe1d38a9dd435241a7d438b460e34325552f789cf3fdf0946e4`.
Офлайн fixtures не являются полномочием на выполнение или результатом пилота.

## Операторский остаток

Установка и фактический пилот отслеживаются отдельно в #2455. Этот документ
описывает формат, а не объявляет их исполненными. Рабочие флаги и
установленные snapshot не меняются до гейтов staging/пилота. Метрики недели и
двух недель снимаются по настоящим данным; календарь не заменяется fixtures.
