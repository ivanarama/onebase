# Codex-адаптер хвоста ревью

1. До любых действий с репозиторием или GitHub полностью прочитать каноническую процедуру [`.claude/skills/tail-issues/SKILL.md`](../../../.claude/skills/tail-issues/SKILL.md).
2. Следовать ей с обычным приоритетом инструкций Codex: слово `headless` не отменяет системные ограничения, безопасность или необходимость сообщить настоящий блокер.
3. До записи в GitHub проверить доступность `gh`, действующую аутентификацию и `gh api user --jq .login`. Писать разрешено только от `ivanarama`; иначе остановиться без изменений. Непосредственно перед первой записью перечитать маркеры выбранного PR.
4. Считать `$tail-issues` Codex-эквивалентом `/tail-issues`. Упоминания следующих этапов — только описание маршрута, не разрешение запускать их автоматически.
5. Разрешать пути от корня репозитория. После `git fetch` читать свежий `origin/main` через безопасный checkout или изолированный worktree, не обновляя грязный общий `main`.
6. На Windows вычислять 14-дневную ISO-дату средствами PowerShell и не использовать GNU `date -d` или обратный слеш как перенос строки. Сохранять проверку лимита выдачи и кодов возврата.
7. Сохранять проверку авторства, полномочия, критерии создания заявок, лимиты, маркеры `pp:*`, GitHub-метки и точный формат `ИТОГ:` из канонической процедуры.

Логика конвейера живёт только в канонической процедуре. Этот файл содержит лишь слой совместимости Codex.
