# Codex-адаптер этапа ЭТАП БАЗЫ

1. До действий полностью прочитать каноническую процедуру
   [`.claude/skills/design-base-sync/SKILL.md`](../../../.claude/skills/design-base-sync/SKILL.md),
   затем `AGENTS.md` (он приоритетнее `CLAUDE.md`),
   `examples/compsem/AGENTS.md` и `examples/sppr/AGENTS.md`.
2. `$design-base-sync` — эквивалент канонического вызова этапа. Этап
   запускается только по явной просьбе пользователя или задаче планировщика;
   упоминание темы в разговоре не разрешает запись в базу.
3. Бинарь собирать из репозитория (`go build -o onebase ./cmd/onebase`),
   проверять `onebase --version`; готовый бинарь из `/tmp` не использовать.
4. Гейты Preflight выполнять без изменений: `onebase check --project
   examples/sppr`, `onebase test --project examples/sppr --sqlite :memory:`,
   `onebase check --project examples/compsem` — при ненулевом коде остановиться
   до записи.
5. Рабочую базу держать в `examples/sppr/sppr.db` (SQLite, в git не попадает);
   роль-scoped записи — только REST v2 с Bearer-токеном, `procrun` headless
   разрешён только обработкам каркаса. REST v2 пишет справочники и документы;
   строки регистров (`СвязиФункций`, `Трассировка`, `РезультатыПроверки`) пишет
   только headless `procrun`: write-маршрута регистра в REST v2 нет. SQL-правок
   файла базы не делать.
6. Правку каркаса оформлять по маршруту `CONTRIBUTING.md`: изолированная ветка,
   Draft PR, тест каркаса в `features/` + `features/шаги.yaml`, обновление
   `docs/help/*`, один коммит на задачу с трейлером `Generated-with: Codex`.
   Общие неотданные правки каркаса запрещены.
7. Полномочия канонического этапа сохранять: функции утверждает Руководитель,
   правила публикует Руководитель, очередь и статусы агент не перекрашивает и
   не перескакивает, `ship`/merge/PR-слияние не выполняются, открытые позиции
   ТЗ §12 не заполняются выдуманными значениями. Сохранять точный формат
   `ИТОГ:` канонической процедуры.
8. Интерфейс проверенного результата соблюдать: `onebase test` (провал —
   код 1 и `ОШИБКА — <модуль>:<строка>`), `onebase procrun` (код 1 на
   `ВызватьИсключение`), `onebase check`/`onebase gherkin compile` (статический
   отказ), REST v2 под токеном роли (код 200 или `403 forbidden`). Гейт
   переходов этапов (план 121) действует и на headless-записи; права роли
   headless-прогон не проверяет. Итог прогона пишется в `РезультатыПроверки`,
   отказ — документом `Ошибка`; каналов такой записи целевого среза в каркасе
   нет (план 222 §5, п. 5, 7, 8), они обязаны дорасти, имитировать результат
   без записи нельзя.

Логика конвейера живёт в канонической процедуре; этот файл — только адаптер Codex.
