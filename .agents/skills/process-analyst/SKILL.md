# Codex-адаптер аналитика процессов

1. До любых действий с репозиторием или GitHub полностью прочитать каноническую процедуру [`.claude/skills/process-analyst/SKILL.md`](../../../.claude/skills/process-analyst/SKILL.md).
2. Следовать ей с обычным приоритетом инструкций Codex: слово `headless` не отменяет системные ограничения, безопасность или необходимость сообщить настоящий блокер.
3. До записи в GitHub проверить доступность `gh`, действующую аутентификацию и `gh api user --jq .login`. Писать разрешено только от `ivanarama`; иначе остановиться без изменений. Непосредственно перед первой записью перечитать fingerprint находки и открытые ишью, чтобы не создать дубль.
4. Считать `$process-analyst` Codex-эквивалентом `/process-analyst`. Упоминания других этапов — описание маршрута, не разрешение запускать их.
5. Разрешать пути от корня, найденного через `git rev-parse --show-toplevel`. Не обновлять грязный или общий `main` поверх пользовательских изменений; после `git fetch` использовать изолированный worktree от `origin/main`.
6. На Windows использовать PowerShell-эквиваленты команд, сохраняя семантику и проверку кодов возврата. До сборки тестов `internal/pipelinecontract` проверить доступность `go`; отсутствие обязательного инструмента не маскировать успешным результатом.
7. Сохранять полномочия, классы находок, fingerprint, маркер `pp:analyst-claim`, GitHub-метки, лимит 5 и точный формат `ИТОГ:` из канонической процедуры. Запись в проектную базу под любой ролью запрещена.

Логика конвейера живёт только в канонической процедуре. Этот файл содержит лишь слой совместимости Codex.
