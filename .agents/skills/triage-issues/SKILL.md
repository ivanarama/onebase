# Codex-адаптер триажа

1. До любых действий с репозиторием или GitHub полностью прочитать каноническую процедуру [`.claude/skills/triage-issues/SKILL.md`](../../../.claude/skills/triage-issues/SKILL.md).
2. Следовать ей с обычным приоритетом инструкций Codex: слово `headless` не отменяет системные ограничения, безопасность или необходимость сообщить настоящий блокер.
3. До записи в GitHub проверить доступность `gh`, действующую аутентификацию и `gh api user --jq .login`. Писать разрешено только от `ivanarama`; иначе остановиться без изменений. Непосредственно перед первой записью перечитать метки и маркеры кандидата, чтобы не пересечься с параллельным прогоном.
4. Считать `$triage-issues` Codex-эквивалентом `/triage-issues`. Упоминания следующих этапов — только описание маршрута, не разрешение запускать их автоматически.
5. Разрешать пути от корня, найденного через `git rev-parse --show-toplevel`. Не обновлять грязный или общий `main` поверх пользовательских изменений; после `git fetch` использовать уже синхронный checkout либо изолированный worktree от `origin/main`.
6. На Windows использовать PowerShell-эквиваленты команд, сохраняя семантику и проверку кодов возврата. До сборки или тестов проверить доступность `go`; отсутствие обязательного инструмента не маскировать успешным результатом.
7. Сохранять полномочия, критерии, лимиты, маркеры `pp:*`, GitHub-метки и точный формат `ИТОГ:` из канонической процедуры.

Логика конвейера живёт только в канонической процедуре. Этот файл содержит лишь слой совместимости Codex.
