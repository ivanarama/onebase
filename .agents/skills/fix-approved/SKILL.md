# Codex-адаптер фикса заявок

1. До любых действий с репозиторием или GitHub полностью прочитать каноническую процедуру [`.claude/skills/fix-approved/SKILL.md`](../../../.claude/skills/fix-approved/SKILL.md).
2. Следовать ей с обычным приоритетом инструкций Codex: слово `headless` не отменяет системные ограничения, безопасность или необходимость сообщить настоящий блокер.
3. До записи в GitHub проверить доступность `gh`, действующую аутентификацию и `gh api user --jq .login`. Писать разрешено только от `ivanarama`; иначе остановиться без изменений. Непосредственно перед первой записью перечитать метки и маркеры кандидата.
4. Считать `$fix-approved [N]` Codex-эквивалентом `/fix-approved <N>`. Упоминания следующих этапов — только описание маршрута, не разрешение запускать их автоматически.
5. Сначала применять `AGENTS.md`, затем совместимые проектные соглашения из `CLAUDE.md`. В коммите использовать `Generated-with: Codex` вместо `Generated-with: Claude Code`.
6. Разрешать пути от корня репозитория. Создавать worktree только по уникальному проверенному абсолютному пути и удалять лишь worktree текущего прогона; не трогать общий `main`.
7. На Windows использовать PowerShell-эквиваленты команд, сохраняя семантику и проверку кодов возврата. До обязательных сборок и тестов проверить доступность `go`.
8. Сохранять приоритеты очереди, полномочия, критерии, лимиты, маркеры `pp:*`, GitHub-метки и точный формат `ИТОГ:` из канонической процедуры.

Логика конвейера живёт только в канонической процедуре. Этот файл содержит лишь слой совместимости Codex.
