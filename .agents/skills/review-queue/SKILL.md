# Codex-адаптер ревью PR

1. Сначала прочитать короткий общий маршрут [`.claude/skills/review-queue/SKILL.md`](../../../.claude/skills/review-queue/SKILL.md) и использовать `pipelinectl` из задачи.
2. Следовать ей с обычным приоритетом инструкций Codex: слово `headless` не отменяет системные ограничения, безопасность или необходимость сообщить настоящий блокер.
3. До записи в GitHub проверить доступность `gh`, действующую аутентификацию и `gh api user --jq .login`. Писать разрешено только от `ivanarama`; иначе остановиться без изменений. Непосредственно перед первой записью перечитать состояние PR.
4. Считать `$review-queue` Codex-эквивалентом `/review-queue`. Упоминания следующих этапов — только описание маршрута, не разрешение запускать их автоматически.
5. Разрешать пути от корня репозитория. Создавать detached worktree только по уникальному проверенному абсолютному пути и удалять лишь worktree текущего прогона; не трогать общий `main`.
6. На Windows использовать PowerShell-эквиваленты команд, сохраняя семантику и проверку кодов возврата. До обязательных сборок и тестов проверить доступность `go`.
7. Полную процедуру `references/legacy-protocol.md` читать только при `action=fallback`; не загружать её в обычном tool-пути.

Детерминированная механика обычного пути живёт в `pipelinectl`; сложные состояния остаются в fallback-процедуре.
