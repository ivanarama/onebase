# Браузерные smoke-тесты

Проверяют критические пользовательские пути настоящим браузером: вход, работа
со справочником, проведение документа и движения, отказ по правам, вложения.
До них ни одна проверка приложение не открывала — Go-тесты смотрят на функции и
обработчики, фронтенд-гейт только на синтаксис JS.

## Запуск

```bash
cd e2e
npm ci
npx playwright install chromium     # один раз, ~115 МБ
npx playwright test
```

Сервер поднимать не нужно: `playwright.config.js` делает это сам через
`scripts/e2e-server.sh` — чистая база, известные пользователи, демо-данные.
Без `OB_BIN` скрипт сначала собирает бинарник. В CI сборка выполняется
отдельным шагом до запуска Playwright, а абсолютный `OB_BIN` указывает на
готовый бинарник вне очищаемого `OB_WORK`. Явно заданный неисполняемый
бинарник завершает подготовку ошибкой. Локально этот режим можно повторить:

```bash
go build -o /tmp/onebase-e2e ../cmd/onebase
OB_BIN=/tmp/onebase-e2e npx playwright test
```

В журнале отмечены фазы подготовки, сборки, миграции, пользователей, ролей,
демо-данных и сервера; завершение фазы содержит код и длительность. Бюджет
ожидания `/healthz` в Playwright остаётся 120 секунд.

Полезное:

```bash
npx playwright test posting          # один файл
npx playwright test --headed         # видеть браузер
npx playwright test --debug          # пошагово
npx playwright show-trace test-results/<...>/trace.zip   # разбор падения
```

## Что делает фикстура

`scripts/e2e-server.sh` каждый раз собирает базу заново:

1. `migrate` — схема;
2. `user add admin --admin` и `user add user` + роль «Кладовщик»;
3. `procrun --proc ЗаполнитьТестовуюБазу` — демо-данные;
4. `run` на порту 18080.

Два момента, которые выглядят необязательными, но таковыми не являются.

**Пользователя обязательно завести.** Пока в базе нет ни одного пользователя,
аутентификация выключена целиком (`internal/auth/middleware.go`, ветка
`hasUsers == false`). На пустой базе сценарий входа был бы зелёным, не проверив
ничего.

**Роль назначается до старта сервера.** Права разбираются при загрузке, и
назначение роли работающему серверу подхватывается только после перезапуска.

## Селекторы

Цепляемся за атрибуты, а не за подписи: тексты кнопок переводятся (#960), и
селектор по слову «Записать» отвалился бы при смене языка интерфейса — тест
сломался бы там, где приложение работает.

| Что | Селектор |
|---|---|
| поля входа | `input[name="login"]`, `input[name="password"]` |
| выход | `[data-ob-toggle-target="sysd"]` → `form[action="/logout"] button` |
| создать в списке | `[data-ob-list-create]` |
| записать / провести | `button[name="_action"][value=""]` / `[value="post"]` |
| реквизит объекта | `input[name="<ИмяРеквизита>"]` |
| вложения | `#att-file-input`, `#att-list` |

Ещё одна деталь: переход всегда с `waitUntil: 'domcontentloaded'`. Страница
регистрирует PWA-манифест и service worker, поэтому ожидание полной загрузки
(`load`) на ней зависает.

## Что не покрыто

Конфигуратор (сохранение и перезагрузка конфигурации) — он живёт в лаунчере,
это отдельный интерфейс со своим жизненным циклом. Вынесено из этого набора
намеренно, чтобы не тянуть его в первый заход.

## Приёмка зависимого подбора (план 170, #2093)

После установки npm-зависимостей и Chromium, из корня репозитория:

```bash
ONEBASE_BROWSER_ACCEPTANCE=1 go test -count=1 -v ./internal/ui ./internal/launcher -run 'TestChoiceFilter(Configurator)?BrowserAcceptance$'
go test -count=1 ./internal/cli -run '^TestSchemaFormPublishesChoiceFilterContract$'
go run ./cmd/onebase check --project e2e/fixtures/choice-filter
```

Этот набор обязателен в CI `e2e`. Обычный `go test` пропускает браузерные
сценарии без `ONEBASE_BROWSER_ACCEPTANCE=1`; при включённом флаге отсутствие
Node, Playwright или браузера завершает проверку ошибкой. `acceptance.config.js`
вызывается Go-фикстурами, которые владеют временными БД, копией проекта и
loopback-серверами; напрямую запускать его без этих серверов не нужно.
Трассы и снимки падений лежат в `e2e/test-results/choice-acceptance-*`.

Публичная YAML-фикстура — `e2e/fixtures/choice-filter`. Runtime-фикстура
использует 51 видимый лист в корне A и дочернем A.1, отдельную ветку B,
группу, скрытый RLS лист, сохранённое legacy-значение B при направлении A
и допустимый выбор за первой страницей. Middleware задаёт одного тестового
пользователя `anna` с реальными правами и row-policy; вход и создание сессии
проверяет основной smoke-набор. Ответы endpoints и `selected_allowed` не
подменяются: Playwright сначала получает настоящий ответ сервера, затем
удерживает его доставку явным барьером.

Проверяются A→B→A с обратным порядком ответов, с AbortController и без него;
гонка в уже открытом picker, сохранение актуального выбора, legacy open/save и очистка после актуального
ответа; проверка выбранного ID независимо от страницы и поиска; AND из
иерархии, `eq`, `is_folder` и RLS в select/picker; отказ для лишнего источника
и отсутствие полного списка при сетевой ошибке. Второй сервер — настоящий
лаунчер с временным registry: браузер создаёт условия в панели свойств,
меняет `eq`/`in_hierarchy`, переставляет строки, сохраняет и открывает форму
заново. Go дополнительно перечитывает сохранённый YAML через загрузчик и
проверяет порядок и булев тип `value: false`.

Набор подтверждает этот срез приёмки; глубокие пути плана 183 и весь родитель
#1303 остаются отдельной работой.

При локальном запуске можно явно задать путь к установленному Chromium через
`OB_ACCEPTANCE_BROWSER=/абсолютный/путь/к/браузеру`; CI использует Chromium из
`playwright install` и этот параметр не задаёт.

Чувствительность гонки проверена мутационно: без sequence и snapshot guard
в `obRefreshChoiceSelect` сценарий без AbortController теряет новый выбор A
(ожидаемый ID превращается в пустую строку) и падает. В итоговом коде эти
проверки сохранены. Отдельное отключение sequence/snapshot guard picker
заменяет 50 актуальных строк A двумя строками B и также роняет тест. Работа
добавляет отсутствовавшую приёмку, а не
повторную реализацию feature.

## Закрытие новой формы после записи обработчиком

Изолированный стенд поднимает настоящий HTTP-сервер и сессию, открывает
управляемую форму в оболочке `/ui/app` и исполняет DSL-обработчик записи.
Playwright задерживает доставку ответа `form-event`, пока команда
`ui.закрытьФорму` не придёт по настоящему SSE. Проверяются однократное закрытие,
граница 14999/15000 мс, отказ `ПередЗакрытием`, отмена и подтверждение сохранения,
сохранность другой и повторно открытой формы и запоздалое сообщение старого
Document после навигации того же iframe. Функции runtime не подменяются.

После установки зависимостей и Chromium:

```bash
ONEBASE_BROWSER_ACCEPTANCE=1 go test -count=1 -v ./internal/ui -run '^TestTabsCloseBrowserAcceptance$'
```

Команда запускается из корня репозитория; она также включена в обязательный
джоб `e2e`. Для готового локального браузера можно задать
`OB_ACCEPTANCE_BROWSER=/absolute/path/to/chromium`.
