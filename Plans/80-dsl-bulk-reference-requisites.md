# План 80: безопасное массовое чтение реквизитов ссылок в DSL

**Статус:** запланировано.

## Контекст

Ранее в плане 34 F3 предлагался автодоступ к реквизитам ссылок через `X.Y`:

```bsl
Единица = Стр.Номенклатура.БазоваяЕдиница;
```

От этого подхода осознанно отказываемся: такой синтаксис выглядит как обычное
чтение поля, но фактически может выполнять скрытый запрос к БД. В цикле по
строкам табличной части это легко превращается в N+1 запросов и ухудшает
предсказуемость runtime.

Нужен явный, массовый и кэшируемый способ получить реквизиты связанных объектов.
Он расширяет язык, но не меняет поведение существующих функций.

## Цель

Добавить DSL builtin:

```bsl
Реквизиты = ЗначенияРеквизитовОбъектов(
  Ссылки,
  "Номенклатура",
  ["БазоваяЕдиница", "Наименование"]
);
```

Функция одним batch-запросом читает указанные поля по набору ссылок и возвращает
структуру/соответствие, удобное для дальнейшего использования в цикле.

## Не цели

- Не делать скрытое `this.X.Y` / `Стр.X.Y` разыменование.
- Не менять существующие функции и методы доступа к объектам.
- Не добавлять автоматический prefetch "за спиной" интерпретатора.
- Не решать row-level security в этом плане.
- Не делать JOIN-движок внутри DSL. Для сложных выборок остаётся язык запросов.

## DSL API

Основная форма:

```bsl
Реквизиты = ЗначенияРеквизитовОбъектов(Ссылки, "Номенклатура", Поля);
```

Где:

- `Ссылки` - `Массив` ссылок/UUID-строк или `ТаблицаЗначений`/колонка, если
  такая форма уже поддерживается вызывающим кодом;
- `"Номенклатура"` - имя справочника или документа;
- `Поля` - `Массив` строк или литерал массива, если он поддерживается DSL;
- результат - `Соответствие`: ключ ссылка, значение `Структура` с полями.

Пример:

```bsl
Ссылки = Новый Массив;
Для Каждого Стр Из this.Товары Цикл
  Если ЗначениеЗаполнено(Стр.Номенклатура) Тогда
    Ссылки.Добавить(Стр.Номенклатура);
  КонецЕсли;
КонецЦикла;

Поля = Новый Массив;
Поля.Добавить("БазоваяЕдиница");
Поля.Добавить("Наименование");

Реквизиты = ЗначенияРеквизитовОбъектов(Ссылки, "Номенклатура", Поля);

Для Каждого Стр Из this.Товары Цикл
  Р = Реквизиты.Получить(Стр.Номенклатура);
  Если Р <> Неопределено Тогда
    Стр.Единица = Р.БазоваяЕдиница;
    Стр.ПредставлениеНоменклатуры = Р.Наименование;
  КонецЕсли;
КонецЦикла;
```

Если DSL поддерживает литералы массивов, желаемая короткая форма:

```bsl
Реквизиты = ЗначенияРеквизитовОбъектов(
  Ссылки,
  "Номенклатура",
  ["БазоваяЕдиница", "Наименование"]
);
```

## Поведение

1. Пустой список ссылок возвращает пустое `Соответствие`.
2. Дубликаты ссылок дедуплицируются до SQL-запроса.
3. Порядок результата не важен, доступ идёт по ключу-ссылке.
4. Несуществующие ссылки просто отсутствуют в результате.
5. Неизвестное имя объекта или поля - ошибка DSL с понятным текстом.
6. Reference-поля возвращаются в том же формате, что и обычные значения в DSL
   сейчас: без дополнительного скрытого разыменования.
7. Максимальный размер batch на один SQL-запрос ограничить внутренним chunk size,
   например 500 или 1000 id, чтобы не упереться в лимиты параметров.

## Совместимость

- Существующие функции не меняются.
- `ЗначениеРеквизитаОбъекта(...)`, если используется в конфигурациях, остаётся
  рабочей и не меняет семантику.
- Новый builtin только добавляет явный batch-вариант.
- Старый план автодоступа `X.Y` помечается как отклонённый в скрытой форме и
  заменён этим планом.

## Изменения в коде

### Storage

Добавить batch-метод, например:

```go
func (db *DB) GetFieldsByIDs(
  ctx context.Context,
  entityName string,
  entity *metadata.Entity,
  ids []uuid.UUID,
  fields []string,
) (map[uuid.UUID]map[string]any, error)
```

Требования:

- валидировать поля через metadata;
- использовать физические имена колонок через `metadata.ColumnName`;
- читать только запрошенные поля;
- chunk по `ids`;
- возвращать normalized values как `RunQuery`.

### Interpreter builtin

Файл-кандидат: `internal/dsl/interpreter/builtins.go` или соседний файл для
storage-aware builtins.

Задачи:

- распарсить `Ссылки`;
- распарсить имя объекта;
- распарсить список полей;
- получить entity из registry;
- вызвать storage batch-метод;
- собрать DSL `Соответствие` значений `Структура`.

Если текущие builtins не имеют прямого доступа к storage/registry, добавить
тонкий интерфейс в runtime context интерпретатора, не протаскивая UI-зависимости.

### Lint

Добавить неошибочное предупреждение:

```text
dsl.ref-get-in-loop: одиночное чтение реквизита ссылки внутри цикла;
рекомендуется ЗначенияРеквизитовОбъектов(...)
```

Это предупреждение должно быть best-effort:

- не блокировать CI;
- не срабатывать на одиночный вызов вне цикла;
- не требовать сложного dataflow анализа в первом PR.

## RBAC и безопасность

Правило первого этапа: builtin работает в тех же server-side контекстах, где
сейчас выполняется DSL-код. Он не вводит row-level security и не должен
подменять объектную модель доступа.

Если в контексте есть пользователь и текущий контур уже проверяет объектное
право `read`, использовать эту проверку. Если код выполняется как внутренняя
процедура проведения или регламентное задание, не добавлять внезапный запрет,
который сломает существующие конфигурации.

## Тесты

- Пустой список ссылок возвращает пустое соответствие.
- Дубликаты ссылок дают один результат.
- Несколько полей читаются одним batch-методом.
- Reference-поле возвращается как ссылка, без скрытого второго чтения.
- Неизвестное поле даёт понятную ошибку.
- Chunking работает на списке больше chunk size.
- DSL e2e: табличная часть собирает ссылки, batch читает реквизиты, цикл
  использует кэш.
- Lint warning на одиночное чтение реквизита внутри цикла, если существующий
  одиночный getter найден в AST.
