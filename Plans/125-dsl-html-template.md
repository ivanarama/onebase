# План 125 — HTML-шаблоны в DSL (с автоэкранированием)

Дата проектирования: 2026-08-17.
Статус: ⬜ **Проект** (не начато).
Ветка: `feature/125-dsl-html-template`.
Часть группы «веб-примитивы» (124–128). Самостоятельная ценность вне CMS:
HTML-письма клиентам (план 20), тело ответа HTTP-сервиса, генерация писем
уведомлений — всё, что сегодня собирается конкатенацией строк.

## Контекст

Любой HTML, который конфигурация отдаёт наружу, сегодня склеивается вручную:

```
Результат = Результат + "<div class='card'><h3>" + Стр.Наименование + "</h3></div>";
```

Два следствия, оба плохие:

1. **XSS.** В DSL нет ни одной функции экранирования — проверено грепом по
   `internal/dsl/interpreter/` (коммит `3350679f`): ни `ЭкранироватьHTML`, ни
   `html.EscapeString` в builtins. Наименование товара с `<` ломает вёрстку, а
   с `<script>` — исполняется в браузере посетителя. Для внутреннего письма это
   неприятно, для публичного сайта (план 129) — дыра по умолчанию.
2. **Нечитаемость.** Сборка страницы в присланной CMS-конфигурации
   (`СобратьМакет`, `КарточкаТовара`) — 650 строк конкатенаций, где вёрстка
   перемешана с логикой; править её глазами тяжело, а править не программисту
   невозможно.

Платформа при этом уже умеет ровно то, что нужно: `html/template` из stdlib
слинкован в бинарь (используется в `internal/auth/handlers.go`,
`internal/launcher/configurator_tmpl.go` и ещё десятке файлов), а санитайзер
HTML есть в `internal/richtext` (`Sanitize(htmlStr string) string`,
`richtext.go:69`, на bluemonday).

## Что мешает в текущем коде (проверено по `3350679f`)

1. **Нет типа и нет функций.** Аддитивная фича, ломать нечего.
2. **Конвертер DSL→Go есть, но заточен под JSON.** `valueToJSONSeen`
   (`internal/dsl/interpreter/json_builtins.go:88`) обходит `Array`/`Struct`/`Map`,
   защищён от циклов (стек `jsonValueVisit`) и от глубины. Он приводит даты и
   decimal к JSON-представлению — для шаблона это неверно (нужен `time.Time`,
   чтобы работало форматирование). Нужен отдельный обход с той же защитой от
   циклов, но с сохранением родных типов.
3. **`evalNew`** (`internal/dsl/interpreter/interpreter.go:625`) — точка
   регистрации типа, см. решение 1 плана 124 (регистрируем в switch, не
   фабрикой окружения, иначе объект будет доступен не во всех контекстах).

## Синтаксис

```
Шаблон = Новый ШаблонHTML(
    "<div class=""card"">
       <h3>{{.Наименование}}</h3>
       <p>{{.Цена}} ₽</p>
       {{if .Активен}}<span class=""ok"">в наличии</span>{{end}}
       {{range .Свойства}}<li>{{.Имя}}: {{.Значение}}</li>{{end}}
     </div>");

Данные = Новый Структура;
Данные.Вставить("Наименование", Товар.Наименование);   // экранируется автоматически
Данные.Вставить("Цена", Товар.Цена);
Данные.Вставить("Активен", Истина);
Данные.Вставить("Свойства", МассивСвойств);

HTML = Шаблон.Заполнить(Данные);
```

Готовый HTML (richtext-описание товара, содержимое блока) вставляется явно:

```
Данные.Вставить("Описание", БезопасныйHTML(Товар.Описание));
```

`БезопасныйHTML(Строка)` пропускает строку через тот же санитайзер, что и
richtext-поля (`internal/richtext.Sanitize`), и помечает результат как готовый
HTML — теги остаются тегами, `<script>`/`onerror`/`javascript:` вырезаются.

Английские имена: `New HTMLTemplate(text)`, метод `Fill(data)`, builtin
`SafeHTML(s)`.

### Синтаксис самого шаблона

Синтаксис Go-шаблонов (`{{.Поле}}`, `{{if}}`, `{{range}}`, `{{with}}`, `{{end}}`)
— **не переводится на русский**. Причины: это внешний общеизвестный формат с
документацией, транслировать его — значит поддерживать свой парсер и объяснять
пользователю несуществующий диалект. Русскими остаются имена полей данных
(`{{.Наименование}}`) — их даёт конфигурация.

Доступные в шаблоне функции (фиксированный набор, `template.FuncMap`):

| Функция | Назначение |
|---|---|
| `дата`/`date` | `{{дата .ДатаДокумента "02.01.2006"}}` — формат по образцу Go |
| `число`/`number` | `{{число .Сумма 2}}` — фиксированное число знаков, разделитель тысяч — пробел |
| `атрибут`/`attr` | безопасная вставка в значение атрибута (обёртка контекстного экранирования) |

Произвольные DSL-функции в шаблон не пробрасываются — шаблон остаётся вёрсткой,
а не вторым языком внутри языка.

## Принятые решения

1. **Основа — `html/template`, не `text/template`.** Экранирование
   **контекстное**: одно и то же значение экранируется по-разному в тексте
   узла, в значении атрибута, в URL (`href="{{.Ссылка}}"`) и внутри `<script>`.
   Это ровно то, чего нельзя добиться ручным `ЭкранироватьHTML` — поэтому
   отдельной функции «экранировать строку» план не вводит: она провоцирует
   ручное экранирование в неправильном контексте.
2. **`БезопасныйHTML` санитайзит, а не просто помечает доверенным.** Прямая
   обёртка `template.HTML(s)` без очистки = дыра с русским названием: любой
   конфигуратор напишет `БезопасныйHTML(ПолеИзФормы)` и получит XSS. Санитайзер
   `richtext.Sanitize` уже применяется к richtext-полям при выводе, поведение
   совпадает — «безопасный» значит проверенный, а не объявленный таковым.
3. **Ошибка разбора шаблона — в момент `Новый`**, `RaiseUserError` с текстом
   Go-парсера и номером строки шаблона. Ошибка исполнения (`Заполнить`) — тоже
   `RaiseUserError`; частичный вывод не отдаём (иначе в браузер уедет
   полустраница, выглядящая как рабочая).
4. **Отсутствующее поле — пустая строка, а не ошибка.** `{{.НетТакого}}` на
   `Структуре` в Go даёт ошибку исполнения; включаем `Option("missingkey=zero")`
   и конвертируем данные в `map[string]any`, чтобы пропуск необязательного поля
   не ронял всю страницу. Это осознанный размен: опечатка в имени поля даст
   пустоту вместо ошибки, поэтому в документации — совет держать шаблон под
   тестом конфигурации.
5. **Кэш скомпилированных шаблонов — не делаем.** Разбор шаблона на каждый
   HTTP-запрос дороже, чем хотелось бы, но кэш — это разделяемое состояние
   между сессиями с инвалидацией по тексту шаблона. Правильный ответ на
   «страница пересобирается на каждый запрос» — кэш ответа целиком (план 126),
   он снимает и разбор шаблона, и запросы к БД. Возвращаемся к вопросу только с
   замерами.
6. **Лимиты:**
   - текст шаблона ≤ 1 МиБ;
   - результат `Заполнить` ≤ 16 МиБ (защита от `range` по 100 000 строк, который
     съест память процесса);
   - глубина конвертации данных ≤ 32 уровней, циклические ссылки обрываются —
     как в `valueToJSONSeen`.
   Превышение — `RaiseUserError`.
7. **Песочница не ограничивается** — шаблон не имеет доступа ни к файлам, ни к
   БД, ни к сети. `{{template}}`/`{{block}}` с внешними файлами недоступны, так
   как шаблон разбирается из строки, а не из файловой системы.
8. **Тип регистрируется в `evalNew`** — по тем же причинам, что в плане 124:
   доступность во всех контекстах (форма, регламентное задание, HTTP-сервис,
   `procrun`) без правки точек инжекции.

## Тесты

Файл `internal/dsl/interpreter/htmltemplate_test.go`, проверка через исполнение
DSL-кода (публичная точка входа).

1. `TestHTMLTemplate_Escaping` — `<script>alert(1)</script>` в данных приходит
   в вывод экранированным; тег в вывод не попадает. **Это главный тест плана.**
2. `TestHTMLTemplate_ContextEscaping` — то же значение в `href="{{.U}}"` и в
   тексте узла экранируется по-разному; `javascript:` в URL-контексте
   обезвреживается (`#ZgotmplZ` — поведение `html/template`).
3. `TestHTMLTemplate_SafeHTML` — `БезопасныйHTML("<b>ок</b>")` даёт живой `<b>`;
   `БезопасныйHTML("<img src=x onerror=alert(1)>")` теряет `onerror`;
   `БезопасныйHTML("<script>…</script>")` теряет скрипт целиком.
4. `TestHTMLTemplate_Struct_Map_Array` — данные из `Структура`, `Соответствие`,
   `Массив` (в том числе вложенные) доступны как `{{.Поле}}` и в `{{range}}`.
5. `TestHTMLTemplate_MissingField` — `{{.НетТакого}}` даёт пустую строку, не
   ошибку (решение 4).
6. `TestHTMLTemplate_Funcs` — `дата`, `число`, `атрибут` дают ожидаемый вывод;
   `число` с 2 знаками не теряет копейки на decimal.
7. `TestHTMLTemplate_ParseError` — битый шаблон (`{{if}}` без `end`) роняет
   `Новый` с внятным текстом, ошибка ловится `Попытка/Исключение`.
8. `TestHTMLTemplate_Limits` — шаблон > 1 МиБ и результат > 16 МиБ дают ошибку,
   а не молчаливое усечение и не OOM.
9. `TestHTMLTemplate_Cycles` — структура, ссылающаяся на себя, не вешает
   конвертацию (обрыв по глубине/циклу).
10. `TestHTMLTemplate_AvailableEverywhere` — объект создаётся в контексте без
    инжектированных фабрик (голый `Interp.Run`), фиксирует решение 8.

## Границы (чего не делаем)

- Не переводим синтаксис Go-шаблонов на русский (решение из раздела «Синтаксис»).
- Не поддерживаем подключение шаблонов из файлов (`{{template "имя"}}` с
  файловой системой) — шаблон приходит строкой из справочника/модуля.
  Композиция шаблонов (общий «скелет» + вставки) решается на уровне
  конфигурации: заполнить внутренний шаблон, результат передать во внешний
  через `БезопасныйHTML`. Если понадобится настоящий набор шаблонов с
  наследованием — отдельный план.
- Не даём пробрасывать произвольные функции конфигурации в `FuncMap`.
- Не вводим шаблоны для не-HTML (текстовые письма, XML): `text/template` без
  экранирования — отдельная история, и она НЕ нужна для sitemap.xml (там XML
  собирается тем же html/template или строками с ручным экранированием — см.
  план 129).
