# План 193 — Регистр бухгалтерии v2: виды субконто на счёте, раздельная аналитика Дт/Кт

Дата проектирования: 2026-09-29. Основание — пробел P1-1 ревью ERP-готовности
([план 188](188-erp-readiness-review.md)); владелец 29.09.2026 включил его в первую
очередь планов. Заявки нет: маршрут плана 188.

## Контекст

Регистр бухгалтерии сейчас — демонстрационного уровня:

- **Счёт** — код, имя, вид (активный/пассивный/активно-пассивный) и родитель
  (`internal/metadata/account.go`). Ни видов субконто, ни количественного и валютного
  учёта, ни признака забалансового счёта.
- **Субконто — один список на регистр**, общий для Дт и Кт
  (`internal/metadata/accountreg.go`, колонки `субконто<N>` в `акк_<имя>`). В проводке
  «Дт 41 — Кт 60» примера `examples/accounting` остаток 41 режется по контрагенту, а
  60 — по номенклатуре: обе стороны получают обе аналитики.
- **Ресурсы** — только общие для обеих сторон: нет «Количество Дт/Кт», «Валюта Дт/Кт».
- **Виртуальные таблицы** — `Остатки` и `Обороты` по коду счёта без иерархии: остаток
  по «60» не включает «60.01»; нет корреспондирующего счёта, `ОборотыДтКт`,
  `ДвиженияССубконто`, развёрнутого сальдо (`СуммаОстатокДт`/`СуммаОстатокКт`).
- **План счетов** синхронизируется из YAML в `_accounts` (`SyncAccounts`); в интерфейсе
  только просмотр (`/ui/accounts/{plan}`), субсчёт пользователь не заведёт.

Эталонная торговая конфигурация PuT бухгалтерию не ведёт — выгружает её в 1С:БП3, и ни
одна живая конфигурация регистр бухгалтерии не проверяет (план 188, п. 18).

## Выбранный вариант

Модель 1С, в объёме, достаточном для хозрасчётного плана счетов:

- **виды субконто** объявляются в плане счетов, у каждого счёта — свой упорядоченный
  список видов (до `max_subconto`, по умолчанию 3); число слотов проводок и итогов
  задаётся этим параметром, а не фиксированным числом 3;
- **аналитика хранится раздельно** для Дт и Кт: слот `i` стороны несёт вид субконто и
  значение;
- **признаки счёта:** количественный, валютный, забалансовый, «запрещено использовать в
  проводках» (группа);
- **ресурсы и измерения** бывают балансовыми (одна колонка) и небалансовыми (своя
  колонка на Дт и на Кт);
- **виртуальные таблицы** с параметром `ВидыСубконто`, корреспонденцией и иерархией
  счетов;
- **субсчета**, которые заводит пользователь, рядом с предопределёнными из YAML.

Модель v2 включается **на регистре** (`version: 2`). Регистр без неё работает как
сейчас: v1 не удаляется и не меняет поведения.

## Синтаксис

План счетов:

```yaml
name: Хозрасчётный
title: План счетов бухгалтерского учёта
max_subconto: 3
subconto_kinds:
  - name: Контрагенты
    type: reference:Контрагент
  - name: Договоры
    type: reference:Договор
  - name: Номенклатура
    type: reference:Номенклатура
  - name: Склады
    type: reference:Склад
accounts:
  - code: "41"
    id: Товары                    # имя предопределённого счёта для DSL
    name: Товары
    kind: active
    posting: forbidden            # группа: проводки только на субсчета
  - code: "41.01"
    id: ТоварыНаСкладах
    parent: "41"
    name: Товары на складах
    kind: active
    quantity: true
    subconto: [Номенклатура, Склады]
  - code: "60"
    name: Расчёты с поставщиками
    kind: active_passive
    currency: true
    subconto: [Контрагенты, Договоры]
  - code: "001"
    name: Арендованные основные средства
    off_balance: true
```

`children:` — вложенная форма той же иерархии — разворачивается в `parent` при загрузке
(#1802, партия 3 плана 188); v2 её не меняет.

Регистр:

```yaml
name: Хозрасчётный
accounts: Хозрасчётный
version: 2
dimensions:
  - name: Организация
    type: reference:Организация      # балансовое: одна колонка
  - name: Валюта
    type: reference:Валюта
    balanced: false                  # ВалютаДт / ВалютаКт
resources:
  - name: Сумма
    type: number(15,2)
  - name: Количество
    type: number(15,3)
    balanced: false                  # КоличествоДт / КоличествоКт — только на счетах с quantity
  - name: ВалютнаяСумма
    type: number(15,2)
    balanced: false                  # только на счетах с currency
```

DSL:

```
Дв = Движения.Хозрасчётный.Добавить();
Дв.СчётДт = ПланыСчетов.Хозрасчётный.ТоварыНаСкладах;   // или код "41.01"
Дв.СчётКт = "60";
Дв.СубконтоДт.Номенклатура = Стр.Номенклатура;
Дв.СубконтоДт.Склады       = this.Склад;
Дв.СубконтоКт.Контрагенты  = this.Поставщик;
Дв.СубконтоКт.Договоры     = this.Договор;
Дв.Сумма = Стр.Сумма;
Дв.КоличествоДт = Стр.Количество;
```

Запрос:

```
ВЫБРАТЬ Счёт, Субконто1 КАК Номенклатура, КоличествоОстатокДт, СуммаОстатокДт
ИЗ РегистрБухгалтерии.Хозрасчётный.Остатки(&НаДату, Счёт В ИЕРАРХИИ (&Счёт41),
     &ВидыСубконто /* [Номенклатура] */, Организация = &Организация)
```

## Наблюдаемая семантика и инварианты

1. **Проводка проверяется при записи:** оба счёта есть в плане счетов регистра и не
   запрещены к проводкам; вид субконто, присвоенный стороне, есть у её счёта;
   забалансовый счёт — только на одной стороне, вторая пуста; балансовая проводка —
   обе стороны заполнены. Нарушение — ошибка проведения с кодом счёта и именем вида.
2. **Небалансовые ресурсы и измерения** стороны, чей счёт их не ведёт (нет `quantity`/
   `currency`), не хранятся — как в 1С: общий код проведения может заполнять их для
   любого счёта. Линт предупреждает о явном присваивании константы такому счёту.
3. **Вид хранится вместе со значением** в каждом слоте. Изменение списка видов счёта в
   конфигурации не переинтерпретирует прежние проводки: значение остаётся при своём
   виде, а виртуальные таблицы выбирают слоты по виду, а не по номеру.
4. **Остатки по счёту включают субсчета.** Условие `Счёт В ИЕРАРХИИ` и выборка по
   счёту-группе суммируют его субсчета; счёт, запрещённый к проводкам, своих движений
   не имеет по построению.
5. **Развёрнутое сальдо.** `…ОстатокДт`/`…ОстатокКт`: активный счёт — сальдо в Дт,
   пассивный — в Кт, активно-пассивный — по знаку в каждой строке разреза (развёрнуто
   по субконто, как ОСВ в 1С).
6. **Забалансовые счета** не участвуют в итогах баланса ОСВ, но видны в своих строках.
7. **Предопределённые и пользовательские счета.** Счета из YAML — предопределённые: код,
   вид и признаки меняются только выпуском конфигурации. Субсчёт пользователя хранится
   в `_accounts` с признаком «не предопределённый», наследует виды субконто родителя
   (может сузить список) и переживает синхронизацию и восстановление из копии.

## Хранилище

Таблица `акк_<имя>` регистра v2:

| Колонки | Смысл |
|---|---|
| `id`, `period`, `регистратор`, `регистратор_тип` (+ `регистратор_порядок` плана 189) | как в v1 |
| `счётдт`, `счёткт` (TEXT, код; `NULL` для пустой стороны забалансовой проводки) | счета |
| `<измерение>` / `<измерение>дт`, `<измерение>кт` | балансовые / небалансовые измерения |
| `<ресурс>` / `<ресурс>дт`, `<ресурс>кт` | балансовые / небалансовые ресурсы |
| `видсубконтодт<i>`, `субконтодт<i>_id`, `субконтодт<i>_type`, то же для `кт` | слот `i` стороны: вид и значение-пара плана 191 |

Индексы: `(счётдт, period)`, `(счёткт, period)`, `(регистратор)` — как в v1; плюс
`(счётдт, субконтодт1_id, period)` и то же для Кт — разворот по первому субконто.

`_accounts` получает колонки `id_name`, `quantity`, `currency`, `off_balance`,
`posting_forbidden`, `subconto` (список видов), `predefined`. `SyncAccounts` обновляет
только предопределённые строки; восстановление из копии (`backup/universal.go`,
где `_accounts` сейчас очищается и выводится из конфигурации) переносит строки
пользователя.

Итоги `итоги_акк_<имя>` v2 — помесячно. Ключ строки: месяц, счёт, все балансовые
измерения, значения всех небалансовых измерений **соответствующей стороны**
(включая `ВалютаДт` для Дт и `ВалютаКт` для Кт) и `max_subconto` слотов
«вид, значение (`_id`, `_type`)» этой стороны. Имена колонок измерений и слотов
в итогах общие: сторона определяет, из каких колонок проводки брать значения;
дебетовые и кредитовые ресурсы накапливаются отдельно. Незанятые слоты и
измерения, которые счёт не ведёт, имеют единое пустое представление в ключе,
отличное от заполненных значений. Число слотов в схеме, группировке, записи, пересчёте и
чтении итогов равно `max_subconto`; при значении 4 четвёртый вид и его значение
сохраняются и различают строки.

USD и EUR одного счёта с одинаковыми субконто образуют разные строки итогов:
`ВалютнаяСумма` суммируется только внутри одной валюты. Отбор и группировка
виртуальных таблиц сохраняют валютный разрез; запрос без отбора по валюте тоже
не складывает валютные суммы разных валют в одно число. Балансовая `Сумма`
может суммироваться по валютным строкам при свёртке этого разреза.

Балансовая проводка даёт вклад каждой заполненной стороны: Дт и Кт. Забалансовая
проводка даёт **только один** вклад заполненной стороны; сторона с `NULL` в
счёте пропускается до группировки, без строки с пустым или фиктивным счётом.
То же правило действует при полном пересчёте итогов и построении опорных
проводок свёртки. Забалансовые строки хранятся под своим счётом для запросов,
но исключаются из общего итога баланса ОСВ согласно инварианту 6.

## Совместимость и перевод v1 → v2

- Регистр без `version: 2` не меняется. Смешанная конфигурация (один регистр v1, другой
  v2) допустима.
- Перевод существующего регистра — объявить v2, переписать модули проведения на
  `СубконтоДт`/`СубконтоКт` и перенести данные командой
  `onebase accountreg migrate-v2 --register X --map "Контрагент=Контрагенты,…"`: для
  каждой проводки значения v1 раскладываются по видам счёта Дт и счёта Кт; значения,
  которых счёт не ведёт, отбрасываются и перечисляются в отчёте команды. Это и есть
  исправление «41 по контрагенту»: после перевода аналитика стоит там, где её ведёт
  счёт. Альтернатива — перепровести документы (групповое перепроведение, P1-5 плана 188).
- До перевода команда проверяет, что все коды проводок есть в плане счетов, и
  отказывает со списком неизвестных кодов.

## Срезы

Каждый срез — отдельный PR; тесты — через публичные точки входа: загрузка и
`onebase check` конфигурации, проведение через DSL-модуль (`procrun`, `onebase test`),
`onebase query`, HTTP-страницы бухрегистра, `ForEachDialect` для SQL.

1. **План счетов v2.** Виды субконто, признаки счёта, `id`, колонки `_accounts`,
   проверки конфигурации (вид субконто из списка плана, `max_subconto`, у группы нет
   собственных видов). Проверки плана v1 — вид счёта, повтор кода, родитель,
   `accounts:` регистра — уже делает `onebase check` после #1802.
   Тесты: счёт с неизвестным видом субконто не проходит `check`; субсчёт наследует
   виды родителя; `describe` отдаёт виды и признаки.
2. **Запись проводок v2.** Колонки регистра, DSL `СубконтоДт`/`СубконтоКт`,
   `ПланыСчетов.X.<id>`, проверки инварианта 1, небалансовые ресурсы и измерения.
   Тесты: «Дт 41.01 — Кт 60» пишет номенклатуру и склад только в Дт, контрагента и
   договор только в Кт; проводка на неизвестный счёт, на группу, с чужим видом
   субконто, двусторонняя по забалансовому счёту — ошибка проведения;
   `КоличествоКт` на счёте без количественного учёта не сохраняется.
3. **Виртуальные таблицы.** `Остатки`, `Обороты` (с `КорСчёт`), `ОборотыДтКт`,
   `ОстаткиИОбороты`, `ДвиженияССубконто`; `ВидыСубконто`; иерархия; развёрнутое
   сальдо. Тесты: остаток по «60» равен сумме «60.01» и «60.02»; разворот 41.01 по
   номенклатуре не содержит контрагентов; корреспонденция 90.01 ↔ 62; развёрнутое
   сальдо активно-пассивного 76 по контрагентам; права на регистр и RLS — как у v1.
4. **Итоги v2 и свёртка.** Тесты через проведение и запросы виртуальных таблиц,
   на обоих диалектах (`ForEachDialect`): остатки из итогов совпадают с расчётом по
   проводкам на случайном наборе из 10 тыс. проводок; свёртка v2 даёт опорные
   проводки по видам. Обязательные отдельные сценарии:
   - один счёт и одинаковые субконто, но USD и EUR: отдельные валютные остатки,
     отбор по каждой валюте и разрез без отбора совпадают с расчётом по проводкам;
     `ВалютнаяСумма` разных валют не складывается;
   - `max_subconto: 4`: две проводки отличаются только значением четвёртого
     субконто; два остатка остаются раздельными, четвёртый вид и значение доступны
     запросу;
   - забалансовый счёт только в Дт, затем отдельный случай только в Кт: есть
     остаток заполненной стороны, нет строки пустого счёта и вклада в общий
     итог баланса ОСВ.
   Каждый сценарий проверяется до и после полного пересчёта итогов и свёртки:
   значения, валютные разрезы и все `max_subconto` слотов сохраняются.
5. **Интерфейс.** Субсчёт пользователя на странице плана счетов (наследует виды
   родителя, предопределённые счета только для чтения); проводки и остатки v2 на
   страницах бухрегистра; перенос субсчетов через универсальную копию. Проверка в
   браузере до готовности.
6. **Перевод и пример.** `onebase accountreg migrate-v2`, `examples/accounting` на v2 с
   тестами (`onebase test` в CI, как после #1790), документация.

## Зависимости

- **План 191** (составные типы): значение субконто — пара `_id`/`_type`. Срез 2 ждёт
  среза 1 плана 191 и хранения пар в регистре бухгалтерии.
- **План 189** (порядок документов): `регистратор_порядок` входит в таблицу v2 сразу,
  если 189 реализован раньше; иначе v2 получает колонку вместе с 189.
- **План 194** (язык запросов): `В ИЕРАРХИИ` для счетов реализуется здесь для условия
  счёта виртуальной таблицы; общая конструкция языка — там.
- **Дефекты v1 без развилки** — отдельными PR до этого плана (партия 3 плана 188):
  проводка на код, которого нет в плане счетов (#1801); счета чужого плана в
  виртуальных таблицах (#1800); `children:` из `DEVELOPER.md`, которого загрузчик не
  знал, и проверки плана счетов в `check` (#1802). Проверка кода счёта при записи
  (#1801) — основа инварианта 1: v2 добавляет к ней группы, виды субконто и
  забалансовые счета.

## Риски и откат

- **Объём виртуальных таблиц** (срез 3) — самый большой; параметры
  `Остатки/Обороты/ОборотыДтКт` в 1С многочисленны, план берёт подмножество из примеров
  выше и расширяет его по мере появления сценариев.
- **Производительность разворота по видам** — выбор слота по виду (`CASE` по `max_subconto`
  слотам) не использует индекс по значению; индекс по первому субконто плюс итоги
  (срез 4) закрывают частые случаи, замер — в срезе 4.
- **Откат.** v2 — новый режим регистра; откат среза отключает `version: 2` в
  проверке конфигурации. Данные v1 не трогаются ни одним срезом, кроме явной команды
  перевода, которая работает в транзакции и пишет отчёт.

## Критерии завершения

- проводка «Дт 41 — Кт 60» ведёт номенклатуру только на 41, контрагента только на 60;
- количественный, валютный и забалансовый учёт, субсчета пользователя, иерархия и
  корреспонденция доступны в запросах;
- `examples/accounting` работает на v2 и проверяется в CI; документация описывает v2 и
  перевод с v1.

## Эстимейт

Срез 1 — 2–3 дня, 2 — 3–4, 3 — 4–6, 4 — 2–3, 5 — 3–4, 6 — 2–3; всего 16–23 дня (без
плана 191).
