# План 183 — choice_filter v2: источник через ссылку и отбор в табличной части

Дата проектирования: 2026-09-25.
Статус: 📋 **проектирование**, продуктовый код в этом PR не меняется.
Заявка-сценарий: [#1552](https://github.com/ivanarama/onebase/issues/1552).
Развивает план [170](170-dependent-reference-choice-filters.md) (v1 влит срезами
#1626/#1627/#1628): те же `eq` / `in_hierarchy` / `is_folder`, расширяются только
**источники** и **место применения**.

## Контекст

Сценарий колл-центра (#1552, конфигурация oneservice-cc_v2): каскад
«Филиал → Направление → Товарная группа → Неисправность» и «Филиал → Реклама».
Равенства через реквизит v1 покрывает; за границей остались ровно два случая,
отложенные решением по развилке в #1552:

1. **Глубокий источник.** У выбранного Направления реквизит
   `ГруппаНеисправностей`; поле `Неисправность` должно фильтроваться по
   `Неисправность.Группа = Направление.ГруппаНеисправностей`. В v1 `from`
   ограничен `Объект.<Поле>` / `Форма.<Поле>` без углубления.
2. **Табличная часть.** Ссылочная колонка строки ТЧ выбирается с отбором:
   v1 не давал выборке TP-колонки никакого контекста вообще.

Обход без кода (реквизит-посредник, заполняемый обработчиком) работает, но
плодит денормализацию и забывается при доработках.

## Объём и нецели

В объём: оба случая выше, первая серверная отрисовка, picker, live-refresh
зависимых контролов, `List`/`CountList`, `onebase check`, документация.

Не входят: произвольные выражения и DSL; пути глубже одного перехода по ссылке;
фильтрация TP-колонки значением другой ТЧ (row-local внутри одной строки — да,
чужая строка/чужая ТЧ — нет); проверка при сохранении; REST/язык запросов;
автоподчинение справочников из `Owners`.

## Публичный YAML-контракт

### Глубокий источник — ровно один переход по ссылке

```yaml
- id: Неисправность
  kind: ПолеВвода
  data_path: Объект.Неисправность
  choice_filter:
    - field: Группа
      op: eq
      from: Объект.Направление.ГруппаНеисправностей
```

Правила:

1. Форма пути: `Объект.<Поле>.<Реквизит>` или `Форма.<Поле>.<Реквизит>` — ровно
   три сегмента. Двухсегментный путь v1 и трёхсегментный v2 различимы
   однозначно; глубже трёх — ошибка check.
2. `<Поле>` — ссылочный элемент этой формы; `<Реквизит>` — реквизит того вида
   объекта, на который ссылается `<Поле>`. Если `<Реквизит>` сам ссылочный —
   допустим `eq` при совпадении вида с `field`; для `in_hierarchy` источник
   обязан быть ссылкой на иерархию, в которой живёт `field`.
3. Семантика исполнения: сервер читает атрибут выбранного значения `<Поле>`
   отдельным запросом (RLS на промежуточной записи обязателен), затем
   фильтрует цель как в v1. Недоступное/несуществующее промежуточное значение
   и пустой выбор дают пустую выдачу — fail-closed, без различения причин.
4. Live-refresh: смена `<Поле>` пересчитывает и зависимые через глубокий путь —
   тот же fingerprint механизм плана 170/C, в источник добавляется путь.

### Табличная часть — колонка с отбором

```yaml
- kind: ТабличнаяЧасть
  name: Строки
  columns:
    - id: НаправлениеСтроки
      kind: ПолеВвода
      data_path: Объект.Строки.Направление
      choice_filter:
        - field: Филиал
          op: eq
          from: Объект.Филиал            # уровень формы — для всех строк
    - id: Исправность
      kind: ПолеВвода
      data_path: Объект.Строки.Исправность
      choice_filter:
        - field: Направление
          op: eq
          from: Строки.Направление        # та же строка — row-local
```

Правила:

1. `from` колонки ТЧ: `Объект.<Поле>` / `Форма.<Поле>` (глобальный — общий для
   всех строк отбор) либо `<ИмяТЧ>.<Колонка>` (row-local: значение той же
   строки). Префикс ТЧ обязан совпадать с ТЧ, в которой лежит колонка.
2. Row-local источник читается из данных строки, которую редактируют: запрос
   опций несёт идентификатор строки формы (не записи БД) и значение источника
   проверяется сервером как обычное значение фильтра.
3. Условия с row-local источником не участвуют в первой серверной отрисовке
   новой пустой строки: пустой источник даёт пустую выдачу до заполнения
   ведущей колонки (как пустой фильтр v1).
4. `id` обязателен у колонки так же, как у элемента формы; идентичность
   контракта: форма + сущность + `<имя ТЧ>.<id колонки>`.

## Права и границы доверия

- Значение глубокого источника читает сервер отдельным запросом под RLS; в
  выдачу попадает только признак «допустимо/нет», сами значения посредника
  клиенту не возвращаются.
- Все значения — bind-параметры существующего компилятора; текст SQL не
  переписывается. Никаких новых точек приёма произвольных строк: путь и оп
  читаются из метаданных, значение — из проверенного параметра.
- Row-local отбор не ослабляет права колонки: те же ref-options, RLS, маски.

## Хранилище и SQL

Новых таблиц нет. Глубокий источник — один `GetByID` посредника (RLS) +
bind-параметр предиката v1. Row-local — параметр из тела запроса формы. Матрица
`dbtest.ForEachDialect`: SQLite и PostgreSQL, включая апострофы в значениях
посредника и пустые NULL-реквизиты.

## `onebase check`

- путь не 2 и не 3 сегмента, неизвестное `<Поле>`/`<Реквизит>`, несовпадение
  видов объекта для `eq`, не-иерархия для `in_hierarchy` — ошибки;
- префикс ТЧ не совпадает с ТЧ колонки, отсутствие `id` — ошибки;
- `notify_changes`-стиль предупреждений здесь не нужен: контракт строго
  серверный, «издателя» нет.

## Тесты

- публичный HTTP: первая отрисовка, picker, `List`/`CountList` с глубоким
  источником; row-local опции колонки ТЧ; RLS: закрытый посредник даёт пустую
  выдачу; лишние/поддельные параметры — 400;
- матрица диалектов: eq через ссылку, in_hierarchy через ссылку, NULL-реквизит
  посредника, апострофы;
- check-набор ошибок выше; behavior: смена ведущего поля пересчитывает
  глубокого источника и row-local колонки без устаревших ответов.

## Срезы

- **B1** — глубокий источник: метаданные/check, серверное чтение посредника,
  live-refresh, тесты;
- **B2** — TP-колонка с глобальным источником: маршрут опций с контекстом
  формы, отрисовка, тесты;
- **B3** — row-local источник TP: идентификация строки, серверная проверка,
  behavior-тесты.

## Критерии завершения

- исходный каскад #1552 собирается декларативно без реквизитов-посредников;
- закрытый по RLS посредник даёт пустую выдачу без различения причин;
- матрица диалектов зелёная; check ловит все перечисленные ошибки;
- сценарий «быстрая смена направления во время загрузки» не показывает чужой
  выдачи.

## Оценка

B1 ~2–3 дня, B2 ~1–1.5 дня, B3 ~1.5–2 дня. Итого **4.5–6.5 дней**.
