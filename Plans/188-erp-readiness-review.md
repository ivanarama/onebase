## Контекст

Вопрос ревью: чего не хватает OneBase как ERP-платформе — и чего при этом нет ни в
заявках, ни в PR. Сверка шла с 662 заявками, 1101 PR и 200 планами. Каждая находка
проверена полнотекстовым поиском GitHub и прогоном: сборка апстрима, миграция
`examples/trade`, пробы через `onebase query` и `procrun`, замеры на SQLite.

По ширине платформа уже зрелая: формы, СКД, RLS и маскирование, обмены, HTTP-сервисы,
ИИ-конфигуратор, оборудование. Отстаёт **учётное ядро** — то, что делает систему ERP:
модель данных (составные типы, виды субконто), целостность проведения, язык запросов для
отчётности и поведение на объёмах.

Маршрут работ: дефекты — сразу PR-ами без заявок (конвейер перегружен заявками), каждый
PR сначала Draft, после зелёного CI — Ready. Развилки и крупные функции — решение
владельца, затем отдельные планы.

## Развилки для владельца

### Д3. Порядок документов одной секунды

`МоментВремени` сейчас — `(period < P OR (period = P AND recorder != doc))`: документы одной
секунды видят движения друг друга, итог ФИФО и резервов зависит от порядка проведения,
перепроведение по порядку не детерминировано. С датой без времени (#1169) это все
документы дня.

1. Порядок `(period, регистратор)` по UUID — как `МоментВремени` в 1С. Минимальная правка,
   но порядок внутри секунды случайный; в конфигурациях с датой без времени появятся
   отказы «недостаточно остатков».
2. Порядок `(period, порядок создания)`: у документов — монотонный номер записи (служебная
   колонка при первой записи; существующим строкам — детерминированно по `(period, id)`).
   Понятно пользователю, но это изменение схемы всех документов.
3. Оставить и описать границу; групповое перепроведение (P1-5) тогда недетерминировано.

Рекомендация — **2**, вместе с P1-5.

### Д7. Надёжная доставка веб-хуков

Очередь веб-хуков — в памяти: при переполнении событие отбрасывается, при перезапуске
теряется. Рядом есть надёжная `_job_queue` (план 130). Рекомендация: постановка события в
`_job_queue` в транзакции записи (outbox), доставка исполнителем с повторами и карантином.
Цена — задержка доставки на цикл очереди.

### P1 — без этого ERP не построить (каждый пункт — свой план)

1. **Регистр бухгалтерии под реальный план счетов:** раздельные субконто Дт/Кт, виды
   субконто на счёте, валютный и количественный учёт, забалансовые счета, корреспондирующий
   счёт в оборотах, `ДвиженияССубконто`, субсчета от пользователя.
2. **Составные типы и «любая ссылка»** — конвертер 1С сейчас сводит их к `string`.
3. **Планы видов характеристик, дополнительные реквизиты, характеристики номенклатуры.**
4. **Закрытие периода:** дата запрета отдельно от свёртки, по организации/роли, запрет
   правки, отмены проведения и удаления.
5. **Групповое перепроведение и последовательности документов** (после Д2 и Д3).
6. **Язык запросов:** `ПОМЕСТИТЬ`/пакет, `ИТОГИ ПО`, `В ИЕРАРХИИ`, `ЗНАЧЕНИЕ()`, ссылка
   второго уровня, табличная часть и журнал как источник, `ДОБАВИТЬКДАТЕ` и родственные.

### P2 — важно для внедрений

7. Доступ по данным: назначение пользователю наборов значений доступа (организации, склады)
   без выпуска конфигурации; редактор политик.
8. Средства интеграции в DSL: хеши/HMAC, ZIP, `ДвоичныеДанные`, электронная подпись, приём
   почты IMAP/POP3, клиент AMQP/Kafka, CSV, FTP/SFTP; в REST — запись регистров сведений,
   чтение регистров накопления и бухгалтерии, пакетные операции, лента изменений.
9. Печать: массовая печать из списка, штрихкоды/QR/DataMatrix в макетах, шаблоны DOCX.
10. Отчёт как API из DSL и рассылка по расписанию; группировка по иерархии в компоновке.
11. Перенос данных из 1С: справочники, начальные остатки, документы.
12. `SECURITY.md` и приватные сообщения об уязвимостях.
13. Объёмы: индексы ссылочных колонок, `COUNT(*)` списков, первичный ключ периодического
    регистра сведений, построчная вставка движений.

### P3 — стратегия и удобство

14. Расширения конфигурации (слой доработок поверх поставки).
15. Объекты 1С без аналога: функциональные опции, определяемые типы, общие реквизиты
    (разделение данных), подписки на события, хранилища настроек, регистры расчёта.
16. Интерфейс: настройка списков пользователем, избранное, групповое изменение, календарь.
17. Инструменты ИИ-конфигуратора: форматтер `.os` и `check --fix`, профилировщик DSL.
18. Эталон PuT в CI платформы: PR движка проверять на живой конфигурации.
