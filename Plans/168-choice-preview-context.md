# Этап 168 — Пояснение в форме выбора с безопасным контекстом

## Контекст

План подготовлен для [issue #1391](https://github.com/ivanarama/onebase/issues/1391).
Сейчас универсальный picker в `internal/ui/static/ui.js` получает страницу
`/ui/_ref-options/<entity>` и строит строки только из `id` и `_label`. Оператор
видит наименование, но не памятку, нужную для решения до выбора. Endpoint уже
проверяет право `read`, применяет row filter и маскирует поля, однако не знает,
из какой формы и для какого реквизита его вызвали.

Выбран вариант 2 из triage: сначала отдельный технический план, затем три части
одного контракта — статическое пояснение, пакетная функция конфигурации и явно
ограниченный `choice_context`. Полноценные пользовательские формы выбора
(`kind: choice`) в этот этап не входят: это другой, существенно более широкий
движок форм.

Целевой сценарий: справочник «Направления обслуживания» хранит общую памятку, а
общий модуль за один вызов уточняет её для всех строк текущей страницы с учётом
филиала из ещё не записанной формы звонка. Ни функция, ни чтение памятки не
должны обходить объектный RBAC, строковые политики и маскирование полей.

## Синтаксис / YAML

Статический и динамический источники объявляются у выбираемой сущности:

```yaml
name: НаправленияОбслуживания
kind: catalog
fields:
  - name: Наименование
    type: string
  - name: Памятка
    type: string

choice_preview: Памятка
choice_preview_proc: ПамяткиВыбора.Сформировать
```

`choice_preview` — имя собственного строкового реквизита сущности. Значение
после применения полевой политики становится базовым пояснением строки.
`choice_preview_proc` — строго квалифицированное имя экспортной функции общего
модуля в формате `<Модуль>.<Функция>`; неквалифицированное имя и обработчик
формы не допускаются. Ключи независимы: разрешены только статический preview,
только функция или оба сразу.

Контекст задаётся только на ссылочном `ПолеВвода` управляемой формы:

```yaml
schema: onebase.form/v1
form:
  entity: Звонок
  name: ФормаОбъекта
  kind: object
elements:
  - kind: ПолеВвода
    name: ПолеНаправление
    data_path: Объект.Направление
    choice_context:
      Филиал: Объект.Филиал
      Канал: Объект.Канал
```

В первой версии правая часть — только `Объект.<Реквизит>` той же сущности, без
разыменования (`Объект.Филиал.Город`), табличных частей, реквизитов формы и
выражений. Левая часть — непустое уникальное имя поля структуры `Контекст`.
Такой предел делает серверную проверку однозначной и не превращает YAML в ещё
один язык выражений. Контекст ячейки табличной части — отдельное развитие.

Объявленная функция вызывается как функция, не процедура:

```os
Функция Сформировать(Ссылки, Контекст) Экспорт
    Результат = Новый Соответствие;
    Для Каждого Направление Из Ссылок Цикл
        // Один пакет: Ссылки содержит только текущую видимую страницу.
        Результат.Вставить(Направление, ТекстДля(Направление, Контекст.Филиал));
    КонецЦикла;
    Возврат Результат;
КонецФункции
```

`Ссылки` — массив типизированных ссылок уже разрешённых строк текущей страницы;
`Контекст` — структура из разрешённых и типизированных значений. Результат —
`Соответствие`, где ключом служит одна из переданных ссылок (также принимается
её UUID-строка), а значением — строка или `Неопределено`. Запись для строки
переопределяет статический preview; отсутствующая запись оставляет статическое
значение. Ключ не из `Ссылки` игнорируется.

## Наблюдаемая семантика и инварианты

1. Без `choice_preview*` форма выбора, её старый GET, локальный fallback и JSON
   остаются побайтно совместимыми с текущим поведением.
2. При наличии preview сервер сначала получает одну страницу обычным путём:
   object `read` → row filter → field masking → `_label`. Лишь затем строятся
   ссылки и статические пояснения и ровно один раз вызывается функция.
3. Функция вызывается один раз на HTTP-запрос страницы, а не один раз на строку.
   Поиск сбрасывает `offset` в ноль; переход «назад/далее» вызывает функцию
   заново только для новой страницы. Hover и движение стрелками сервер не зовут.
4. Сервер возвращает минимальный DTO строки `{id, _label, _preview}`. В ответ не
   попадают остальные поля записи, значения контекста и имя функции.
5. Preview всегда обычный текст. Клиент записывает его через `textContent` и
   показывает с `white-space: pre-wrap`; HTML, Markdown и `template.HTML` не
   интерпретируются. Вводится предел, например 4 KiB UTF-8 на одну строку и
   100 строк на страницу; превышение считается ошибкой контракта.
6. Браузер не присылает имя функции или поля preview. Он передаёт только
   идентичность исходных entity/form/element и значения объявленных alias;
   сервер заново находит форму и элемент, проверяет его ссылочный `data_path` и
   сам восстанавливает allowlist `choice_context`.
7. Значение контекста не является доказательством полномочий. Оно проходит
   разбор по типу поля; скрытое или доступное только под маской поле запрещено,
   ссылка требует object `read` и допуска строки. Все DSL-запросы функции идут
   в контексте текущего пользователя через существующие query/row/field gates.
8. Для функции строится отдельное окружение `buildChoicePreviewVars`, а не
   полное `buildDSLVarsWithMessagesTx`/`dslvars.Common.Build`. Это позитивный
   allowlist: guarded `Запрос`, чтение разрешённых реквизитов переданных ссылок,
   `Перечисления`, `Константы`, `Предопределённые`, текущий пользователь и
   чистые функции локализации/вычислений. Ссылки страницы остаются непрозрачными
   значениями без выхода к manager/object API. Вызванные из preview общие
   модули наследуют то же окружение и не получают полный набор переменных заново.
   `CallSandboxed` с запретами сети/файлов/exec и лимитами остаётся вторым слоем,
   но не считается границей read-only сам по себе.
9. Preview не получает возможности создания, изменения, проведения и удаления
   справочников/документов, записи регистров и движений, управления
   транзакциями/блокировками, blob/вложениями и их публикацией, аудита, обмена,
   WebSocket/уведомлений, сброса кэша, запуска или постановки фоновых и
   регламентных заданий, а также HTTP/email/ИИ/file/exec. Сервер открывает для
   вызова собственную транзакцию чтения и всегда откатывает её независимо от
   результата; DSL-функции `НачатьТранзакцию`/`ЗафиксироватьТранзакцию` в
   allowlist отсутствуют. Поэтому `finishDSLExecution`, который откатывает лишь
   оставленную открытой DSL-транзакцию, не используется как доказательство
   отсутствия стойких эффектов.
10. Если preview сконфигурирован, его нельзя тихо потерять: ошибка валидации,
   RBAC, timeout или неверный результат показывает в диалоге «Пояснение
   недоступно», отключает выбор и предлагает повторить запрос. Fallback к старым
   локальным option разрешён только сущностям без `choice_preview*`.
11. Статический и динамический preview не меняют состав/порядок строк, `total`,
    `limit` и `offset`. Функция не может добавить закрытую строку или изменить
    `_label` и выбранный UUID.

## HTTP-контракт

Старый `GET /ui/_ref-options/{entity}?q=&limit=&offset=` остаётся как есть.
Для нового UI добавляется `POST /ui/_ref-options/{entity}/page` с JSON-телом:

```json
{
  "q": "ремонт",
  "limit": 50,
  "offset": 0,
  "source": {
    "entity": "Звонок",
    "form": "ФормаОбъекта",
    "element": "ПолеНаправление"
  },
  "context": {
    "Филиал": "7f5d3f9b-2f69-4ee1-bf7b-6b06074345b0",
    "Канал": "Телефон"
  }
}
```

`source`/`context` можно опустить, если у элемента нет `choice_context`.
Параметры пагинации имеют текущие пределы 50/100. POST выбран намеренно:
значения незаписанной формы не должны попадать в URL, access log и историю
браузера. Маршрут остаётся read-only по эффекту за счёт отдельного
allowlist-окружения и безусловного rollback серверной транзакции из инвариантов
8–9, использует ту же сессию и защиту same-origin, что другие POST UI.

Ответ сохраняет общую форму текущего endpoint:

```json
{
  "items": [
    {"id": "...", "_label": "Ремонт стиральных машин", "_preview": "НЕ ВЫПОЛНЯЕМ: ..."}
  ],
  "total": 73,
  "limit": 50,
  "offset": 0
}
```

Ошибки самого контракта дают 400, отсутствие object/row/field access — 403,
перегрузка — 429, ошибка/timeout функции — контролируемый 422 с безопасным
пользовательским сообщением. Трассировка получает вид операции
`choice.preview`, entity и число строк, но не содержимое.

## Хранилище / SQL

Схема БД и миграция данных не меняются. `choice_preview` читает уже выбранные
`storage.List` строки; запрещён второй `GetByID` на каждую строку. Динамическая
функция получает ссылки пакетом и при необходимости делает один запрос DSL с
параметром-массивом либо иной пакетный запрос конфигурации.

Row filter должен участвовать и в `List`, и в `CountList`, как сейчас в
`referenceOptionsPage`. Preview строится только после `maskRecords`; перенос
извлечения до маскирования запрещён тестом. PostgreSQL-специфичного SQL этап не
добавляет, поэтому отдельная миграция не нужна; тест общей семантики запускается
на SQLite, а RLS/query contract покрывается существующими публичными входами.

  `GetModuleNamespacedProc`, без нового глобального поиска по короткому имени;
- новый `internal/ui/choice_preview_dsl.go` — единственная сборка позитивного

  `ChoicePreviewProfile` с network/file/exec и ресурсными запретами как
  дополнительный слой; профиль не подменяет allowlist возможностей;
- `internal/ui/handlers.go`, `internal/ui/handlers_entity.go` — выбор страницы,
  минимальный DTO, типизация контекста и пакетный вызов;
- `internal/ui/field_access.go`, `internal/ui/row_access.go`,
  `internal/ui/dsl_row_access.go` — переиспользование текущих object/row/field
  gates, без параллельной реализации прав;
- `internal/ui/ops.go` — `choice.preview`, request timeout и общий processor
  concurrency key;
- `internal/ui/templates.go`, `internal/ui/templates_managed.go` — безопасные
  `data-*` с режимом preview и server-resolvable source identity;
- `internal/ui/static/ui.js` — двухпанельный picker, hover/keyboard, страницы и
  fail-closed ошибка; `internal/ui/static/managed.js` не должен заводить второй
  независимый контракт, его редактор продолжает вызывать общий picker;
- `internal/ui/activity_test.go`, новые `choice_preview*_test.go` и Node-тест
  поведения picker — публичные HTTP/UI регрессии.

Конфигуратор в первом релизе сохраняет новые YAML-ключи как текст, но отдельные
визуальные редакторы полей не обязательны. Импорт/экспорт форм 1С не синтезирует
`choice_context`: у него нет однозначного соответствия этому контракту.

## Совместимость и миграция

- Все ключи opt-in; существующие проекты и базы не требуют миграции.
- Старый GET и его consumers не получают обязательных новых полей. Новый
  JavaScript использует POST только когда серверная разметка пометила target как
  preview-enabled; иначе выполняется прежний GET и прежний fallback.
- Добавление `_preview` — additive только в новом DTO. Пустая строка означает
  «для этой строки пояснения нет», а не ошибку.
- При одновременных ключах функция дополняет/переопределяет статический текст,
  поэтому внедрение можно начать с `choice_preview` и позже без смены формы
  добавить контекстную функцию.
- Удаление `choice_preview_proc` немедленно возвращает статический режим;
  удаление обоих ключей возвращает старый диалог.
- `kind: choice` не активируется и не меняет смысл. Это сохраняет текущую
  совместимость форм, где этот kind пока только описан в метаданных.

## Последовательность небольших PR-срезов

### Срез A — контракт метаданных и fail-fast проверка

Добавить три YAML-поля, schema/lint и cross-reference validation. Проверять
статический string field, точный формат квалифицированной функции, наличие
экспортной функции с двумя параметрами и ограниченную грамматику
`choice_context`. Обновить `DEVELOPER.md`/`docs/forms.md` с примером.

Публичные тесты: `onebase check --project <fixture>` принимает полный пример;
опечатка поля, `Модуль` без функции, процедура вместо функции, неверная арность,
вложенный путь и context на нессылочном элементе дают диагностические ошибки с
файлом и element name. JSON schema принимает новые entity-ключи, lint формы не
объявляет `choice_context` неизвестным.

### Срез B — безопасная статическая страница

Добавить POST page DTO и статический `_preview` после существующих list/RLS/mask
гейтов, не включая пока DSL-функцию. Старый GET не менять.

Публичные HTTP-тесты: поиск/limit/offset/total и `hide_from_choice` совпадают со
старым endpoint; object read даёт 403; row policy удаляет строку; `read: hide`
не отдаёт preview, `mask_*` отдаёт ровно замаскированное значение; JSON содержит
только три поля строки; 101 запись подтверждает границу страниц и отсутствие
N+1 по счётчику запросов. Fixture без ключей получает прежний GET JSON.

### Срез C — пакетная функция и ограниченный контекст

На POST разрешить server-resolved source/context, собрать типизированные ссылки,
вызвать `GetModuleNamespacedProc` один раз через отдельный
`buildChoicePreviewVars` и `ChoicePreviewProfile`, затем нормализовать
`Соответствие`. Вызов целиком выполняется в открытой сервером транзакции,
которая всегда откатывается; commit/rollback-функции DSL в окружение не входят.
Добавить `choice.preview` в deadline/concurrency/metrics.

Публичные тесты: функция-счётчик получает 50 ссылок и вызывается один раз;
страница 2 получает другой набор; отсутствующий ключ сохраняет static fallback;
лишний/off-page UUID игнорируется; HTML остаётся текстом; неверный тип/размер
результата даёт 422. Подмена function/source/element/context alias, скрытое поле,
закрытая reference-строка и DSL-запрос за пределами RLS не раскрывают данные.
Timeout и saturation возвращают 422/429, а открыть или зафиксировать
DSL-транзакцию функция не может. Отдельный набор публичных HTTP-тестов вызывает
preview-функции, которые пытаются создать/записать/провести/удалить объект,
записать регистр, управлять транзакцией, сохранить или опубликовать файл,
записать аудит, поставить/запустить задание, послать WebSocket/уведомление и
обратиться к HTTP/email/ИИ/file/exec. Каждый запрос fail-closed с 422; повторное
чтение через публичный API подтверждает неизменность объектов и регистров, а
fake-адаптеры внешних эффектов имеют нулевые счётчики. Тот же тест вызывает
запрещённую возможность через вспомогательную функцию общего модуля и после
присваивания под другим именем, доказывая, что вложенный вызов и alias не
обходят границу. Отдельная тестовая capability, намеренно выполняющая запись
внутри host-owned транзакции, подтверждает безусловный rollback и при успешном
возврате, и при ошибке/timeout.

### Срез D — диалог и сквозной пример

Передать source identity из auto/managed templates, собрать только объявленные
текущие значения формы и сделать picker из списка и панели preview. Активная
строка едина для мыши и клавиатуры; добавить «Назад/Далее», отмену устаревших
ответов и блокировку выбора при обязательной ошибке preview. Включить небольшой
пример конфигурации с филиалом, статическим fallback и пакетной функцией.

Публичные тесты: Node/DOM-тест двигает active row мышью и стрелками и видит тот
же preview; Enter выбирает активную строку; поиск сбрасывает offset; stale
response не меняет страницу; строка `<img onerror=...>` попадает только в
`textContent`; ошибка динамики отключает выбор. Сквозной `httptest` открывает
managed form, передаёт незаписанный филиал, получает разные памятки для двух
контекстов и неизменный legacy picker у сущности без новых ключей.

   fallback остаётся у строк, которых нет в `Соответствие`.
5. Проверить поиск и «Далее/Назад»: `total/offset` устойчивы, функция получает
   только текущие видимые UUID.
6. Войти ограниченной ролью: закрытые RLS-строки отсутствуют, скрытое поле
   контекста блокирует preview, маскированная памятка не раскрывается.
7. Сломать функцию и превысить timeout: диалог показывает безопасную ошибку,
   выбор недоступен, сервер продолжает обслуживать обычный picker другой
   сущности.
8. Подставить конфигурацию с попытками записи объекта/регистра, commit,
   постановки задания, публикации файла и сетевого вызова: POST возвращает
   безопасную ошибку, повторный GET не видит изменений, а тестовые внешние
   адаптеры не фиксируют ни одного вызова.
9. Удалить новые ключи и подтвердить прежний GET, внешний вид и выбор без
   миграции базы.

Команды реализации: `go test ./internal/metadata ./internal/configcheck
./internal/ui`, Node-тесты `internal/ui/static`, затем `go test ./...` и
`onebase check` для добавленного примера.

## Риски и откат

- **Утечка через контекст или preview.** Снижается server-side allowlist,
  полной полевой видимостью context source, повторным row access для ссылок,
  запуском DSL от текущего пользователя и минимальным DTO.
- **Побочный эффект автоматически вызываемой функции.** Снижается отдельным
  позитивным allowlist без manager/write/job/file/network capabilities,
  наследованием границы во вложенных общих модулях и безусловным rollback
  host-owned транзакции; публичные HTTP-тесты проверяют состояние БД и счётчики
  внешних адаптеров после каждой запрещённой попытки.
- **N+1 и задержка интерактивного поиска.** Один вызов на страницу, максимум
  100 ссылок, общий concurrency budget, deadline и slow-operation metric.
- **Preview используют как обязательное бизнес-правило.** Ошибка не должна
  молча возвращать старый список; configured preview работает fail-closed.
- **XSS из НСИ/DSL.** Только JSON string → DOM `textContent`; тест с вредоносной
  строкой остаётся постоянным гейтом.
- **Разрастание контракта в произвольную форму выбора.** Первый этап запрещает
  произвольную разметку, nested expressions и table-part context.
- **Регрессия общего picker.** Старый GET и ветка без preview остаются; новый
  POST включается явным marker в server-rendered DOM.

Откат по срезам: сначала удалить UI marker (все формы мгновенно используют
старый GET), затем отключить `choice_preview_proc`, оставив статический режим,
либо удалить оба YAML-ключа. Схема БД не менялась, data rollback не нужен.

## Критерии завершения

- статический и контекстный сценарии issue #1391 работают до выбора элемента;
- функция вызывается ровно один раз на видимую страницу и не меняет её состав;
- динамический preview не может оставить стойкое изменение БД или вызвать
  внешний эффект; это доказано публичными HTTP-тестами каждой запрещённой
  capability, вложенного вызова/alias и rollback при success/error/timeout;
- object RBAC, row filter, field masking и source-context access подтверждены
  публичными HTTP-тестами;
- поиск, пагинация, keyboard/mouse selection и legacy-диалог покрыты тестами;
- preview не исполняет HTML и не попадает вместе с context в логи;
- `onebase check`, schema/lint, документация и пример описывают один контракт;
- продуктовый код поставлен отдельными небольшими PR после принятия этого плана.

## Эстимейт

- срез A, метаданные/валидация/документация: 1–1.5 дня;
- срез B, статический page endpoint и access-тесты: 1–1.5 дня;
- срез C, sandboxed batch-функция и контекст: 2–3 дня;
- срез D, UI/пагинация/сквозной пример: 1.5–2 дня.

Итого: **5.5–8 дней**, без полноценных `kind: choice` форм и контекста строк
табличной части.
