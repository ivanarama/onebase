# Этап 157 — Схлопывание панели объектов на широком экране

## Контекст

Из обсуждения #1108, заявка #1122: «открыл нужные вкладки — скрыл меню —
получил дополнительно место для просмотра / редактирования». Автор на прямой
вопрос уточнил: не хватает именно **ширины**, а не высоты, — значит источник
проблемы и есть левая панель.

Левая панель объектов `#ob-nav` — жёсткая колонка `aside{width:210px}` внутри
`.app-body{display:flex}`. На широком экране убрать её было нечем. Во вкладочной
оболочке она к тому же теряет смысл после того, как нужные объекты уже открыты:
навигация идёт по полосе вкладок, а панель продолжает есть ширину у формы.

Механика была написана наполовину — и только для мобильного:

- кнопка `.nav-toggle` объявлена `display:none` и оживает лишь внутри
  `@media (max-width:820px)`, где панель работает выезжающей шторкой;
- обработчик `window.obNavToggle` переключает `body.nav-open` — класс, который
  на ширине ≥821px не адресован ни одним правилом CSS.

То есть на десктопе переключатель существовал, но не значил ничего.

## Синтаксис / YAML

Изменений нет: фича целиком в оболочке UI, настройки конфигурации не касается.
Для пользователя это кнопка «☰» слева в топбаре, видимая на любой ширине.

## Хранилище / SQL

Изменений в схеме нет. Состояние — в `localStorage` браузера, ключ
`obNavCollapsed` (`'1'` — схлопнуто).

## Изменения в коде

### `internal/ui/templates.go` (партиал `head`, CSS)

1. `.nav-toggle` выносится из `@media` — базовое правило `display:inline-flex`
   действует на любой ширине; `display:none` убрано.
2. Новый блок:

   ```css
   @media (min-width:821px){
     html.nav-collapsed #ob-nav{display:none}
   }
   ```

Разведение по брейкпоинту здесь несущее, а не косметика. На узком экране ширину
панели забирает сама шторка, и `nav-collapsed` там не должен вмешиваться в
`nav-open`. Пока каждый класс адресован только своей стороной границы, они
свободно сосуществуют — и сценарий «схлопнул на десктопе → сузил окно» не даёт
ни запертой шторки, ни открытой без спроса. Сбрасывать класс на ресайзе не
нужно: сбрасывать нечего.

Селектор от `html`, а не от `body`, — следствие пункта ниже.

### `internal/ui/static/ui.js`

3. Восстановление класса — синхронно, в начале файла (ui.js подключён в `<head>`),
   рядом с детектом `ob-embedded`:

   ```js
   window.OB_NAV_COLLAPSED_KEY = 'obNavCollapsed';
   try {
     if (localStorage.getItem(window.OB_NAV_COLLAPSED_KEY) === '1') {
       document.documentElement.className += ' nav-collapsed';
     }
   } catch (e) {}
   ```

   Это принципиально: режим открытия форм по умолчанию — «Страницы»
   (`DefaultFormOpenMode = FormModePages`), то есть каждый переход это полная
   перезагрузка страницы. Класс, поставленный после `DOMContentLoaded`, давал бы
   мигание панелью на каждом переходе. В `<head>` `document.body` ещё `null`,
   поэтому класс идёт на `documentElement` — отсюда и селектор `html.…` в CSS.

   Внутри фреймов оболочки код тоже отработает, но там `#ob-nav` и так скрыт
   правилом `.ob-embedded #ob-nav{display:none!important}` — вреда нет.

4. `obNavToggle` получает развилку по `matchMedia('(max-width:820px)')`: узкий
   экран переключает `nav-open` (как раньше), широкий — `nav-collapsed` с
   записью в `localStorage`.
5. `aria-expanded` считает `syncNavExpanded()` — по классу, актуальному для
   текущей ширины. Вызывается при переключении, один раз на `obReady` (в
   разметке атрибут статически `false`, а на широком экране панель по умолчанию
   раскрыта) и на событии `change` медиазапроса — иначе после ресайза через
   границу атрибут врал бы скринридеру.

Разметку дублировать не надо: панель рисуется одним партиалом `nav`, вкладочная
оболочка вставляет его тем же `{{template "nav" .}}` (`tabs.go`). Кнопке добавлен
`title` с уже существующим ключом «Меню» — на десктопе она новая, и подсказка
избавляет от угадывания.

## Тесты

`internal/ui/nav_collapse_test.go`:

- `TestNavToggle_VisibleOnWideScreen` — `.nav-toggle{display:none}` исчезло,
  базовое правило видимости есть, а внутри `@media (max-width:820px)` `.nav-toggle`
  больше не переопределяется (тело `@media` вырезается со счётом скобок, чтобы
  отличить правило внутри блока от одноимённого снаружи);
- `TestNavCollapsed_ScopedToWideScreen` — правило скрытия лежит в
  `@media (min-width:821px)`, в узком блоке `nav-collapsed` не упоминается,
  мобильная шторка (`body.nav-open aside`) на месте;
- `TestNavToggle_Markup` — кнопка и её `aria-controls` есть в партиале;
- `TestNavCollapsed_RestoredSynchronously` — чтение `localStorage` стоит в файле
  **до** `obReady(`, класс ставится на `documentElement`, переключатель разводит
  экраны.

`internal/ui/static_test.go` — маркеры новой логики в списке ассертов о том, что
`ui.js` отдаётся целиком.

`e2e/tests/nav.spec.js` (джоб `e2e`, обязательный) — единственная проверка,
которая реально жмёт кнопку в браузере:

- на 1280×720 панель схлопывается, `<html>` получает класс, `aria-expanded`
  переключается; состояние переживает переход на другую страницу (то самое
  «Страницы» = перезагрузка) и снимается тем же переключателем;
- схлопнутая на десктопе панель не запирает мобильную шторку после сужения окна
  до 390px: шторка закрыта (уехана за левый край, а не `display:none`),
  открывается кнопкой и закрывается по Escape.

Go-тесты по природе проверяют текст CSS и текст `ui.js` — «применится ли это
браузером», знает только `e2e`.

## Verification

1. `go build ./... && go test ./internal/ui/`.
2. `./onebase run --project examples/trade --sqlite /tmp/x.db --port 8080`,
   открыть в браузере шире 821px: слева в топбаре «☰», клик — панель уходит,
   форма занимает её 210px.
3. Перейти на другую страницу — панель осталась схлопнутой и **не мигнула** при
   загрузке.
4. Сузить окно до мобильной ширины — та же кнопка выдвигает шторку поверх
   контента, Escape и клик мимо закрывают.
5. Режим «Вкладки» (`/ui/app`) — то же поведение в оболочке, внутри вкладок
   ничего не поехало.

## Осознанно за рамками

- **Узкая полоса с иконками** вместо полного скрытия: у пунктов меню объектов
  иконок нет, полоса была бы столбиком безымянных заглушек.
- **Полноэкранный режим** (скрыть топбар и полосу подсистем) — отдельный вопрос,
  как возвращаться, когда скрыт весь хром. Заявкой #1122 не закрывается;
  понадобится — заводится отдельно.
- **Горячая клавиша** — решением по #1122 в первой итерации не делаем: Ctrl+B
  занят редактором Quill («жирный») в режиме «Страницы», а любой другой
  кандидат надо проверять на конфликты с вводом в формах.

Полоса подсистем при схлопнутой панели остаётся: свёрнутое меню не должно
запирать пользователя в текущем разделе.
