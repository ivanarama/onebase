# План 124 — Регулярные выражения в DSL

Дата проектирования: 2026-08-17.
Статус: ✅ **Реализовано** 2026-08-17 (PR #972).
Ветка: `feature/124-dsl-regex`.
Часть группы «веб-примитивы» (124–128), поднятой разбором ТЗ на CMS
(`129-cms-site-configuration.md`). Самостоятельная ценность вне CMS: валидация
ИНН/телефона/email при вводе, разбор банковских выписок и ответов внешних API,
нормализация кодов справочников.

## Контекст

В DSL нет регулярных выражений — проверено грепом по
`internal/dsl/interpreter/*.go` (коммит `3350679f`): ни `regexp`-builtin, ни
объекта. Сегодня разбор строк в конфигурациях пишется через `Найти`, `Сред`,
`СтрЗаменить` — на любой нетривиальной задаче (телефон в пяти форматах, разбор
строки выписки) это превращается в нечитаемый код, который конфигуратор
переписывает под каждый новый формат входных данных.

Заявлено как «Tier 2.5» в improvement-roadmap и как требование 7.6 в ТЗ на CMS
(генерация слагов, валидация полей публичных форм) — но полезность от CMS не
зависит.

## Что мешает в текущем коде (проверено по `3350679f`)

Ничего не мешает — фича аддитивная. Точки, которые нужно знать исполнителю:

1. **Глобальные builtins** — `var builtins = map[string]func(args []any, file
   string, line int) (any, error)` (`internal/dsl/interpreter/builtins.go:91`),
   заполняется из `init()` в `builtins_*.go`. Имена регистрируются парами
   (русское + английское), ключи в нижнем регистре.
2. **Конструктор `Новый Х`** — `evalNew` (`internal/dsl/interpreter/interpreter.go:625`):
   сперва switch по встроенным типам (`массив`, `соответствие`, `структура`,
   `таблицазначений`), затем поиск фабрики `__factory_<тип>` в окружении.
3. **Фабрики из окружения инжектируются НЕ везде.** `NewChartFunctions()`
   подмешивается только в `internal/ui/handlers_dsl.go:318`, `NewServiceFunctions()`
   — только в `internal/dslvars/dslvars.go:116`. Объект, зарегистрированный
   фабрикой, доступен в одних контекстах и отсутствует в других (регламентное
   задание, `procrun`, HTTP-сервис) — это существующая грабля платформы, и
   наступать на неё в этом плане не нужно (см. решение 1).
4. **Валидатора типов `Новый` нет** — `onebase check` не проверяет имя типа
   (грепы по `internal/configcheck/check.go` дают только «неизвестный тип
   графика»). Правок валидатора план не требует.
5. **Объекты DSL** реализуют `Get(field string) any`, `Set(field string, val any)`,
   `CallMethod(name string, args []any) any` — образец: `Array`/`Struct`/`Map`
   в `collections.go:133,279,352`, `dslFile` в `file_builtins.go:189`.
   `CallMethod` возвращает `nil` на неизвестный метод; ошибки времени
   выполнения поднимаются `RaiseUserError(...)`.

## Синтаксис

```
// Компиляция один раз, применение много раз
Рег = Новый Регекс("^\+7\d{10}$");
Если Не Рег.Совпадает(Телефон) Тогда
    ВызватьИсключение "Телефон должен быть в формате +7XXXXXXXXXX";
КонецЕсли;

// Флаги вторым аргументом: i — регистронезависимо, m — многострочный,
// s — точка захватывает перенос строки
Рег = Новый Регекс("^\s*итого:\s*(\d+[.,]\d{2})\s*$", "im");

// Одно совпадение: Структура или Неопределено
Найдено = Рег.Найти(СтрокаВыписки);
Если Найдено <> Неопределено Тогда
    Сумма = Число(СтрЗаменить(Найдено.Группы[1], ",", "."));
КонецЕсли;

// Все совпадения: Массив структур
Для Каждого Совп Из Рег.НайтиВсе(Текст) Цикл
    Сообщить(Совп.Значение + " на позиции " + Совп.Позиция);
КонецЦикла;

// Замена: $1 / ${имя} в шаблоне замены
Нормализованный = Рег.Заменить(Телефон, "+7$1");

// Разбор: Массив строк
Части = Новый Регекс("\s*[;,]\s*").Разделить("а, б;  в");

// Именованные группы
Рег = Новый Регекс("(?P<год>\d{4})-(?P<месяц>\d{2})");
Найдено = Рег.Найти("2026-08");
Сообщить(Найдено.ГруппыПоИмени["год"]);   // 2026

// Экранирование литерала (для сборки шаблона из пользовательского ввода)
Шаблон = "^" + РегексЭкранировать(Префикс) + "\d+$";
```

Английские имена: `New Regex(pattern, flags)`, методы `Matches`, `Find`,
`FindAll`, `Replace`, `Split`; builtin `RegexEscape`.

### Возвращаемые значения

| Метод | Возврат |
|---|---|
| `Совпадает(Текст)` / `Matches` | Булево |
| `Найти(Текст)` / `Find` | Структура или `Неопределено` |
| `НайтиВсе(Текст[, Предел])` / `FindAll` | Массив структур (пустой, если нет совпадений) |
| `Заменить(Текст, Замена)` / `Replace` | Строка |
| `Разделить(Текст[, Предел])` / `Split` | Массив строк |
| `Шаблон` (свойство, `Get`) | Строка — исходный шаблон, для сообщений об ошибках |

Структура совпадения: `Значение` (строка), `Позиция` (число, 1-based — как
`Найти` в DSL, а не 0-based Go), `Длина` (число), `Группы` (Массив строк, где
`[0]` — всё совпадение, `[1]` — первая группа), `ГруппыПоИмени` (Соответствие
имя → строка; пустое, если именованных групп нет).

**Позиция 1-based** — осознанно: в DSL `Найти("абв", "б")` возвращает 2, и
регекс обязан быть с этим согласован, иначе конфигуратор получит смещение на
единицу в коде, который выглядит корректным. Ненайденная группа даёт пустую
строку (не `Неопределено`) — чтобы конкатенация в шаблоне не падала.

## Принятые решения

1. **Тип регистрируется в `evalNew`, а не фабрикой в окружении.** Объект не
   имеет внешних зависимостей (ни БД, ни сервера), поэтому попадает в switch
   встроенных типов `interpreter.go:625` рядом с `таблицазначений`. Причина —
   пункт 3 раздела «что мешает»: фабрики через окружение доступны не во всех
   контекстах, и регекс, работающий в форме, но не работающий в регламентном
   задании, — худший из возможных результатов.
2. **Синтаксис — RE2 (стандартный `regexp` Go), без сторонних библиотек.**
   Значит нет обратных ссылок (`\1`) и lookahead/lookbehind. Взамен —
   гарантированное линейное время: конфигурация не может положить сервер
   «катастрофическим бэктрекингом» (ReDoS) на подобранной строке. Это выбор в
   пользу безопасности публичного контура, и его надо явно назвать в
   документации: пользователи, знакомые с PCRE из 1С (`ЗначениеИзСтрокиВнутр`,
   внешние компоненты) ждут lookahead.
3. **Флаги — вторым аргументом, строкой.** Поддерживаются `i`, `m`, `s`;
   разворачиваются в префикс `(?ims)` перед компиляцией. Неизвестная буква —
   ошибка компиляции с указанием буквы. Полный синтаксис `(?i)` внутри шаблона
   тоже работает (это RE2), флаги — просто удобный сахар.
4. **Ошибка компиляции — `RaiseUserError`**, текст: `Регекс: не удалось
   скомпилировать шаблон «<шаблон>»: <ошибка Go>`. Битый шаблон — ошибка
   разработчика конфигурации, а не пользователя, поэтому падаем сразу при
   `Новый`, а не молча возвращаем «не совпало».
5. **Лимиты (защита от исчерпания памяти):**
   - длина шаблона ≤ 4096 символов;
   - длина входной строки для любого метода ≤ 4 МиБ;
   - `НайтиВсе` без явного предела возвращает не более 10 000 совпадений;
     передан предел — не более него.
   Превышение — `RaiseUserError` с внятным текстом, не тихое усечение (тихое
   усечение даёт «отчёт с потерянными строками», который никто не заметит).
   Константы — пакетные, в одном месте файла, чтобы их было видно.
6. **Кэш компиляции — не делаем.** Объект компилирует шаблон один раз в
   конструкторе; правильный паттерн («создать до цикла») естественен и
   документируется примером. Глобальный кэш `map[string]*regexp.Regexp` под
   мьютексом — это разделяемое состояние между сессиями ради экономии
   микросекунд; вводить его без замеров не нужно.
7. **Песочница не ограничивается.** Регекс не трогает ни файлы, ни сеть, ни БД,
   RE2 не даёт ReDoS, лимиты покрывают память. Недоверенному коду (ИИ,
   marketplace) объект доступен так же, как `Массив`.
8. **`РегексЭкранировать(Текст)` — отдельный глобальный builtin** (`regexp.QuoteMeta`),
   не метод объекта: он нужен ДО того, как объект создан (при сборке шаблона из
   пользовательского ввода). Английское имя `RegexEscape`.
9. **Русские имена групп поддерживаются через ASCII-псевдонимы** (добавлено при
   реализации). RE2 разрешает в имени группы только `[A-Za-z0-9_]`, поэтому
   `(?P<год>\d{4})` не компилируется вовсе — «invalid named capture». В
   платформе, где вся прикладная лексика русская, конфигуратор напишет имя
   по-русски инстинктивно и получит ошибку на ровном месте. Поэтому перед
   компиляцией не-ASCII имя заменяется на `obN`, а наружу — в
   `ГруппыПоИмени` и в ссылках `${имя}` строки замены — возвращается исходное.
   Форма `$имя` без фигурных скобок не поддерживается принципиально: Go читает
   имя после `$` до первого не-word символа, кириллица там не распознаётся.

Сигнатуры:

```go
// NewRegexObject — конструктор для «Новый Регекс(Шаблон[, Флаги])».
func NewRegexObject(args []any) any

type dslRegex struct {
    re      *regexp.Regexp
    pattern string
}

func (r *dslRegex) Get(field string) any
func (r *dslRegex) Set(field string, val any)          // no-op: объект неизменяемый
func (r *dslRegex) CallMethod(name string, args []any) any
```

`Set` — намеренно no-op (шаблон после компиляции не меняется); попытка присвоить
`Рег.Шаблон = "..."` не должна выглядеть работающей — но и падать не обязана,
поведение как у прочих неизменяемых объектов DSL.

## Тесты

Файл `internal/dsl/interpreter/regex_builtins_test.go`. Проверка идёт **через
исполнение DSL-кода** (как требует CLAUDE.md: фикс проверяется публичной точкой
входа), образец запуска — существующие тесты пакета (`builtins_small_test.go`).

1. `TestRegex_Matches` — `Совпадает` true/false, регистр учитывается по умолчанию.
2. `TestRegex_Flags` — `"i"` даёт регистронезависимость; `"m"` — `^` на каждой
   строке; `"s"` — точка ловит `\n`; неизвестный флаг → ошибка с указанием буквы.
3. `TestRegex_Find` — Структура с `Значение`/`Позиция`/`Длина`/`Группы`;
   **`Позиция` 1-based** (совпадение в начале строки даёт 1, не 0);
   ненайденное совпадение → `Неопределено`.
4. `TestRegex_FindAll` — количество, порядок, пустой Массив при отсутствии
   совпадений, соблюдение явного предела.
5. `TestRegex_NamedGroups` — `ГруппыПоИмени` заполняется **русскими** именами
   (решение 9); `TestRegex_NamedGroupsASCII` — латинские имена не сломаны
   подменой; `TestRegex_NamedGroupsMixed` — смешанный шаблон; отсутствующая
   группа даёт пустую строку.
6. `TestRegex_Replace` — `$1` и `${имя}` подставляются; `$` без группы остаётся
   литералом.
7. `TestRegex_Split` — с пределом и без.
8. `TestRegex_BadPattern` — `Новый Регекс("(")` поднимает ошибку с текстом
   шаблона; ошибка ловится `Попытка/Исключение` (то есть это userError, а не
   паника Go).
9. `TestRegex_Limits` — шаблон > 4096, вход > 4 МиБ, `НайтиВсе` сверх 10 000
   совпадений: во всех случаях внятная ошибка, а не тихое усечение.
10. `TestRegex_AvailableEverywhere` — объект создаётся в контексте **без**
    инжектированных фабрик (голый `Interp.Run` с пустыми extraVars). Тест
    фиксирует решение 1: если кто-то позже перенесёт регистрацию в фабрику
    окружения, тест упадёт.
11. `TestRegexEscape` — `РегексЭкранировать(".*")` даёт литеральный поиск.

Интеграционные и матричные тесты не нужны: SQL и диалекты не затрагиваются.

Ручная проверка на конфигурации (обработка в любой тестовой базе):

```
Рег = Новый Регекс("(?P<код>[A-Z]{2})-(\d+)");
М = Рег.Найти("Заказ AB-1024 принят");
Сообщить(М.Значение + " | " + М.Позиция + " | " + М.ГруппыПоИмени["код"]);
// ожидаем: AB-1024 | 7 | AB
```

`onebase check --project <конфигурация>` на конфигурации с регексом — должен
проходить (валидатор типы `Новый` не проверяет, но модули он компилирует и
исполняет).

## Границы (чего не делаем)

- Не тащим PCRE-совместимую библиотеку ради lookahead — см. решение 2.
- Не делаем транслитерацию/`Слаг()` builtin'ом платформы: это прикладная
  лексика (нужна CMS, не нужна учёту), место ей — в конфигурации, на
  Соответствии. Если позже окажется, что её просят три конфигурации из трёх —
  завести отдельный план.
- Не добавляем `ЗаменитьФункцией` (замена через callback DSL): требует вызова
  интерпретатора из Go-кода внутри `ReplaceAllFunc`, что тянет вопросы
  контекста/таймаутов. Отдельная заявка, если понадобится.
