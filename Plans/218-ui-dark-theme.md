# Этап 218 — тёмная тема enterprise-UI

## Контекст

Палитра enterprise-UI зашита в шаблонах: базовый layout `internal/ui/templates.go`
(стилевой блок в `<head>`, ~120 цветов), управляемые формы, страницы администратора,
вкладки. Переключатель темы существует только для редакторов кода конфигуратора
(`internal/launcher/configurator_tmpl_shell.go`), и он про редакторы, не про
пользовательские экраны. Человек, работающий вечером на списках и формах, получает
яркий белый фон карточек и таблиц; настройки темы в интерфейсе базы нет.

Заявка не заводилась (маршрут: контрибуторская разработка, ветка
`experiment/ui-dark-theme` + Draft PR). Работа делится на каркас (этот срез) и
последующие оверрайды по поверхностям.

## Каркас (этот срез)

1. **Токены палитры.** В стилевом блоке базового шаблона `:root` объявляет
   CSS-переменные (фон, поверхности, тексты трёх уровней, границы, шапки таблиц,
   наведение строк, поля шапки, акценты); все правила базового layout переходят
   на `var(...)`. Значения light-режима точно равны нынешним цветам — светлая
   тема не меняется ни на пиксель.
2. **Тема на элементе документа.** `html[data-theme="dark"]` задаёт оверрайды
   переменных; `html[data-theme="light"]` и `html[data-theme="dark"]` ставят
   `color-scheme` — нативные контролы (select, дата) окрашиваются по теме.
3. **Выбор без сервера.** Режим (`light | dark | system`) хранится в
   `localStorage` (`obUITheme`), сервер о нём не знает. `internal/ui/static/ui.js`
   применяет тему в `<head>` до первой отрисовки — по образцу схлопывания панели
   объектов (`OB_NAV_COLLAPSED_KEY`), чтобы не мигать белым на каждой
   перезагрузке. В режиме `system` тема разрешается по `prefers-color-scheme` и
   следует за сменой системной темы.
4. **Переключатель.** В системном меню («Профиль и интерфейс») — группа
   «Тема оформления» с радиополями Светлая / Тёмная / Системная; выбор
   применяется сразу, без отправки формы.
5. **Клиентские поверхности среза.** Окно подбора (`_item-picker-modal`),
   контекстное меню и панель сообщений (`ob-msg-bar`) переставляют цвета на
   токены; серверные страницы (карточки, списки, таблицы, отчёты, форма, плитка,
   поиск) уже на токенах.

Границы среза каркаса: не трогаем Monaco/quill (редакторы конфигуратора),
страницы администратора, слайдеры, страницы виджетов с собственным `<head>`,
картинковый просмотрщик (тёмный по замыслу), инлайн-цвета в телах отдельных
страниц. Это следующие оверрайд-PR.

## Критерии приёмки

1. Светлая тема: все HTTP-тесты `internal/ui` проходят без изменений ожидаемой
   разметки; пиксельных изменений в светлой теме нет.
2. Базовый layout (шапка, меню подсистем, навигация, карточка, таблица, форма,
   кнопки, поля, плитка, поиск, breadcrumb) берёт цвета из переменных:
   `html[data-theme="dark"]` меняет фон и текст этих поверхностей.
3. Открытие страницы с `localStorage.obUITheme = "dark"` не даёт белого
   мигания: тема стоит на `<html>` до первой отрисовки.
4. Режим `system` меняет тему при смене системной темы без перезагрузки
   (media-listener), выбор переживает перезагрузку и закрытие вкладки.
5. Окно подбора, контекстное меню и панель сообщений в тёмной теме — тёмная
   поверхность с читаемым текстом; зебра и подсветка выделения строк сохраняют
   различимость.
6. Контраст текста на поверхностях тёмной темы ≥ 4.5:1 для обычных 13–15px
   надписей (значения токенов зафиксированы тестами).

## Тесты

- `internal/ui/theme_test.go`: HTTP-тесты базового шаблона (переключатель в
  системном меню, `data-theme`-оверрайды, отсутствие белого мигания —
  head-скрипт до содержимого страницы), проверки значений токенов и контраста.
- Статические проверки `internal/ui/static_test.go`: ключ `obUITheme`,
  применение темы в head ui.js, media-listener системного режима.
- Регрессия светлой темы: существующие HTTP-тесты `internal/ui` (шапка таблиц,
  панель отладки, карточки) проходят без правок ожидаемого.
- Прогон примеров: `onebase check/test --project examples/sppr` (и остальные
  примеры по CI) без изменений.

## Риски и договорённости

- Инлайн-цвета в телах страниц (`style="color:#..."`) — их много; каркас их не
  трогает. Оверрайд-PR покрывают поверхности по мере надобности; каждый —
  HTTP-тест конкретной страницы.
- Страницы администратора имеют собственный `<head>` без базового блока —
  токены им недоступны; их тема — отдельный срез.
- Выбранная светлая тема явно (`light`) не должна следовать за системной
  тёмной; `system` — следует. Тестируется обоими режимами.
- Токен-значения тёмной темы зафиксированы тестами; палитра тёмной темы
  согласуется с существующей тёмной шапкой (`#1e293b`), чтобы шапка и навигация
  не имели двух близких тёмных оттенков.
