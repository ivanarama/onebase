# План 155 — Excel как шаблон печатной формы

## Контекст

Обсуждение [#1109](https://github.com/ivanarama/onebase/discussions/1109): «собрать
бланк простейшей накладной в печатной форме — задача нетривиальная; можно ли
формировать форму из внешнего .xlsx с mustache-тегами, Carbone.io на минималках».

Половина просьбы в движке уже есть, и это надо назвать вслух, прежде чем что-то
строить:

- **Теги есть.** `printforms/*.layout.yaml` понимает `{{Номер}}`,
  `{{Дата | date}}`, `{{Склад.Наименование}}`, `{{Константы.X}}`, `{{@row}}`,
  `{{Итог.Товары.Сумма | number:2}}` — грамматика в `internal/printform/binding.go:17`,
  форматы в `formatters.go`. Строки ТЧ — `binding.repeat`, повтор шапки —
  `repeat_header`, лист вплоть до `229x162mm`.
- **Конвертер-прецедент есть.** «Создать макет из PDF»: `internal/pdfimport/` →
  `printform.LayoutTemplate`, ручка `internal/launcher/layout_import_pdf.go`,
  маршрут `internal/launcher/server.go:309`.
- **excelize v2.11 уже в зависимостях** (выгрузка списков и отчётов в xlsx).

Не хватает не тегов, а **редактора бланка**: расставить объединения, ширины,
границы и поля листа в YAML-редакторе дороже, чем нарисовать то же самое в Excel
за пять минут. Excel и есть этот редактор.

### Что выбрано и почему

Рассматривались три варианта (разбор — в ответе на #1109):

| | Где живёт истина | Плюс | Минус |
|---|---|---|---|
| A | `.layout.yaml` (импорт из xlsx однократный) | всё downstream — редактор, PDF, внешние формы, обмен — работает даром | нет обратного хода: правку бланка в Excel надо импортировать заново |
| B | `.xlsx` в конфигурации, читается на печати | круг замкнут, выгрузка в Excel получается сама | PDF всё равно рисует наш рендерер — воспроизводится подмножество оформления `sheet`; бинарник в git; во внешние печатные формы (только декларативный YAML) не влезает |
| C | A сейчас, B потом | общий кирпич `xlsx → LayoutTemplate` — 80% работы обоих | — |

**Делаем C, ступень 1 = вариант A.** Ступень 2 (`format=xlsx` на выходе печати)
и ступень 3 (`template: файл.xlsx` в рантайме) — отдельными планами, после того
как ступень 1 поживёт у людей. Обещание «в PDF будет ровно как в Excel» мы
сдержать не можем ни в одном из вариантов, поэтому импорт честно сообщает, что
именно он не перенёс.

## Синтаксис (что делает пользователь)

Рисует бланк в Excel как обычно — объединения, ширины колонок, границы, поля
листа. В ячейки пишет те же теги, что и в YAML-макете:

```
Накладная № {{Номер}} от {{Дата | date}}
Покупатель: {{Контрагент.Наименование}}
```

Строка табличной части — **одна** строка бланка, где теги написаны с именем ТЧ:

```
{{@row}} | {{Товары.Номенклатура}} | {{Товары.Количество}} | {{Товары.Цена | number:2}}
Итого: {{Итог.Товары.Сумма | number:2}}
```

Импорт превращает такую строку в область `Строка` с
`binding.repeat: [{area: Строка, source: Товары}]`, а теги внутри области —
в бесприставочные `{{Номенклатура}}`. Так уже пишет панель «Данные» визуального
редактора (`onDataFieldClick`, `configurator.js:1913`): внутри repeat-области
выражение колонки — её голое имя. Нового языка не вводим: `{d.rows[i].name}`
в стиле Carbone не нужен, префикс ТЧ и так однозначно отличает колонку от
ссылочного пути.

Приставки `Итог.` и `Константы.` за имя ТЧ не принимаются (это существующие
конструкции языка выражений).

**Как отличить `{{Товары.Номенклатура}}` (колонка ТЧ) от
`{{Склад.Наименование}}` (реквизит по ссылке).** Только по метаданным: импорту
передаётся список ТЧ документа. В конфигураторе он известен (форма привязывается
к документу полем `document:`), в CLI — читается из проекта. Без списка (пустой)
импорт не разворачивает repeat вовсе и делает плоский макет — честно и
предсказуемо, вместо угадывания.

### Разбиение на области

Приоритет — **имена Excel** (Формулы → Диспетчер имён): диапазон с именем
`Шапка`/`Строка`/`ШапкаТаблицы`/`Подвал` задаёт область явно. Это прямой аналог
именованных областей табличного документа 1С, и это единственный способ получить
предсказуемый результат на нестандартном бланке.

Если имён нет — автоматика по строкам:

1. строки до первой repeat-строки → `Шапка`;
2. repeat-строки (подряд идущие, по одной ТЧ) → `Строка`;
3. остальные → `Подвал`.

Плюс одна эвристика: если строка **непосредственно перед** repeat-строкой не
содержит тегов вовсе и имеет не меньше двух непустых ячеек — она выделяется в
`ШапкаТаблицы` и попадает в `binding.repeat_header` (шапка таблицы повторяется на
каждой странице). Это форма 99% бланков; ошибка эвристики видна только на
многостраничной печати и лечится правкой одной строки YAML или именем в Excel.

## Изменения в коде

### `internal/xlsximport` (новый пакет, по образцу `internal/pdfimport`)

```go
const MaxFileSize = 5 << 20

var ErrFileTooLarge, ErrParse, ErrSheetNotFound, ErrEmptySheet error

type Options struct {
    Sheet      string   // лист; пусто — первый
    TableParts []string // ТЧ документа: без них repeat не разворачивается
}

type Result struct {
    Layout   *printform.LayoutTemplate
    Warnings []string // что не перенесено (формулы, условное форматирование, …)
}

func ImportBytes(data []byte, opts Options) (*Result, error)
```

Переносится: тексты с тегами; объединения (`GetMergeCells` → colspan/rowspan);
из стиля — жирный/курсив/кегль/гарнитура/цвет текста/заливка/выравнивание
(гориз. и верт.)/границы по четырём сторонам с отображением толщины Excel
(1,3,4,7 → `thin`; 2,8,9,10 → `medium`; 5,6,11,12,13 → `thick`); ширины колонок
(символы → px) и высоты строк (пункты → px); ориентация, формат листа и поля
(дюймы → мм) из `GetPageLayout`/`GetPageMargins`; картинки ячеек (см. ниже).

Не переносится и попадает в `Warnings`: формулы (берётся вычисленное значение),
условное форматирование, повороты текста, диагональные границы, второй и далее
листы, закрепление областей, автофильтры.

### `printform.LayoutCell.Picture` (новое поле)

`sheet.Cell.Picture` умеет data-URI и http(s) (`internal/sheet/picture.go:36`),
рендерится и в HTML, и в PDF, но у `LayoutCell` поля нет — **декларативный макет
не может показать логотип вообще**, ни импортом, ни руками. Добавляем
`picture:` + строку в `layoutCellToSheet` (`declarative.go:220`). Импорт кладёт
картинку data-URI при размере до 256 КБ, иначе — предупреждение. YAML-редактор
конфигуратора поле не потеряет: он мутирует разобранный объект целиком
(`jsyaml.dump(s.data)`, `configurator.js:1613`), whitelist ключей ячейки у него
нет.

### Лаунчер

`internal/launcher/layout_import_xlsx.go` — ручка
`POST /bases/{id}/configurator/layout/import-xlsx` (поля `file`, `name`,
`document`, `sheet`), зеркало `layout_import_pdf.go`; список ТЧ берётся из
метаданных документа. Кнопка «Из Excel» рядом с «Из PDF»
(`configurator_tmpl_tree.go:983` и `:1884`), диалог `cfgImportXlsxLayout` в
`configurator.js` по образцу `cfgImportPdfLayout`. Предупреждения импорта
показываются в баннере результата — молча терять оформление нельзя.

## Тесты

- `internal/xlsximport`: бланк собирается excelize'ом **в самом тесте** (бинарный
  фикстур не нужен) — объединения, стили, ширины, поля листа, теги; проверяется
  полученный `LayoutTemplate`.
- Разворот repeat: строка с `{{Товары.X}}` → область `Строка` + binding, теги
  без префикса; `Итог.`/`Константы.` за ТЧ не принимаются; пустой `TableParts` →
  плоский макет без repeat.
- Имена Excel перебивают автоматику; эвристика `ШапкаТаблицы` + `repeat_header`.
- Сквозной: импортированный макет → `printform.BuildSheet` → HTML и PDF без
  ошибок; логотип доезжает до `sheet.Cell.Picture`.
- Битый/пустой файл, не тот лист, превышение размера → типизированные ошибки.
- Лаунчер: POST multipart создаёт `printforms/<имя>.layout.yaml` (file-mode и
  configdb), отказ при пустом имени/без документа/дубле — по образцу
  `layout_import_pdf_test.go`.
- CLI: `printforms import` пишет файл и печатает предупреждения.

   итог посчитан; логотип на месте.
5. То же через `onebase printforms import` на `examples/trade`.

## Что осталось за рамками (ступени 2–3)

- `format=xlsx` на выходе печати — печатные формы сейчас отдаются только HTML и
  PDF (`internal/ui/handlers_print.go`). Нужно и само по себе.
