# Этап 216 — Единое состояние readonly для Monaco и Quill в управляемой форме

## Контекст и выбранное решение

Ведущая заявка: [#1613](https://github.com/ivanarama/onebase/issues/1613).
Канонический triage: [5752497686](https://github.com/ivanarama/onebase/issues/1613#issuecomment-5752497686).
Выбран вариант 1 с последующим [уточнением владельца от 28.10.2026](https://github.com/ivanarama/onebase/issues/1613#issuecomment-6478877495):
сначала самостоятельный короткий план по #1613, затем реализация. Старую ведущую
#1612 не переоткрывать: её кодовый PR #1678 уже восстановил picker и обработчики
при условном запрете, но не интеграцию Monaco/Quill. Настоящий документ — план,
а не свидетельство выполненного исправления или разрешение на его поставку.

База обследования: `main@9d1db8a9871671faf8560a49ddc628cc80ce63b9`.
Проверены только границы состояния элемента, шаблонов, редакторов, применения
ответов формы и браузерного harness. Полный браузерный repro в этапе PLAN не
запускался; дефект подтверждён чтением кода. Перед реализацией сверить эти границы
с актуальным main и воспроизвести отрицательные контроли ниже.

Результат для пользователя: открытый редактор блокируется сразу после ответа
form-event, снимающего доступность, и снова допускает ввод после разрешающего
ответа. Начальная условная блокировка, поздняя загрузка библиотек и повторная
инициализация подчиняются тому же состоянию. Значение, право записи и dirty
не должны расходиться между видимым редактором и textarea.

## Синтаксис / YAML

Новые пользовательские свойства и новая форма ответа HTTP не нужны. Используем
существующие `readonly_when`, постоянный `readonly`, наследование контейнера,
`editable_admin_only`, `ПолеКода` и `ПолеВвода` для реквизита `richtext`.
Пример содержимого `elements` существующей управляемой формы:

```yaml
- kind: ПолеКода
  name: Код
  data_path: Объект.Код
  language: plaintext
  readonly_when: 'Режим = "Принята"'
- kind: ПолеВвода
  name: Описание
  data_path: Объект.Описание
  readonly_when: 'Режим = "Принята"'
```

`Код` — строковый реквизит, `Описание` — `richtext`; кнопка с обработчиком меняет
`Режим`, сервер возвращает существующие `elementStates.readonly` и `values`.
Значения карты адресуются `data-ob-el-path`, не именем реквизита или элемента.

## Наблюдаемая семантика и инварианты

1. Сервер определяет состояние. Внутренний DOM-признак постоянного запрета
   фиксируется рендером для конкретного размещения; туда входят собственный и
   унаследованный static readonly, admin-only и применимые права формы/поля.
   Начальный итоговый readonly берётся из рендера; явный новый итог приходит из
   `elementStates`. Отсутствующий ключ не означает false. Клиент не повторяет
   вычисление YAML-условий или серверных прав.
2. Одна операция применения к backing-контролу обновляет его доступность и
   зарегистрированный адаптер виджета. Эффективный запрет — постоянный запрет
   ИЛИ актуальный серверный итог. `false` никогда не снимает постоянный запрет.
   При монтировании читается текущее состояние этого же DOM-узла, не снимок
   времени запроса библиотеки. Обычные textarea без виджета работают как прежде.
3. Monaco переключается штатным `updateOptions({readOnly: ...})`; Quill —
   `enable(!readonly)`. Клавиатура, paste/drop, форматирование, toolbar и его
   клавиатурная активация не изменяют запрещённое значение. У Quill дополнительно
   блокируются соответствующие toolbar controls; визуальный disabled один не
   заменяет запрет ввода. Чтение, выделение и копирование остаются доступны.
4. Состояние применяется по размещению, не по `name`: соседний редактор,
   статически закрытый потомок и другое размещение того же реквизита не
   разблокируются побочно. Disabled fieldset/hidden_when не превращается в
   разрешение редактора; возвращение видимости повторно применяет текущий итог.
5. Переключение readonly не меняет содержимое и само не создаёт dirty/input/change.
   Серверное `values` обновляет backing и виджет одной программной операцией даже
   под запретом. Для Monaco сохраняется имеющийся syncing-guard; для Quill нужен
   silent-путь через текущий формат clipboard, без пользовательских событий.
   Нормализация HTML/списков остаётся существующей: сравнивать каноническое
   содержимое, не обещать побайтовую стабильность произвольного HTML после Quill.
6. Разрешённый пользовательский ввод синхронизирует backing, revision и dirty
   существующим путём; blur/ПриИзменении не дублируются. При запрещённом вводе
   пользовательское содержимое не попадает в backing или следующий запрос.
   Программное обновление не сбрасывает уже существующий dirty. `dirty:true`
   ответа сервера сохраняет прежний приоритет. Смена readonly не отменяет
   уже введённые до блокировки данные и правила merge позднего ответа.
7. На одну пару textarea/holder приходится один живой экземпляр, одна toolbar
   и один набор listeners. Повтор init/state — идемпотентен. Callback старого
   DOM-поколения не монтирует редактор в отсоединённый/заменённый holder и не
   меняет новый экземпляр. После удаления снимаются подписки/submit-handler,
   Monaco/model освобождаются согласно владению; старый Quill больше не пишет
   в backing. Потеря библиотеки оставляет рабочую textarea с тем же readonly.
8. Клиентский readonly не даёт прав: серверная eligibility события, partial
   write, RBAC и проверки записи сохраняются. Поддельный HTTP-запрос не получает
   нового разрешения. ТЧ, общий hidden_when и права не перепроектируются.

## Предлагаемая реализация и жизненный цикл

Названия ниже — проектируемые внутренние JS-функции, не существующий API.
Реестр привязывается к самому backing-узлу (WeakMap или его private property),
а не к глобальному имени поля. Общий узкий интерфейс:
`setReadOnly(bool)`, `setValue(value)`, `dispose()`; регистрацию завершает
немедленное применение текущего состояния. `applyElementStates` зовёт одну
`obApplyControlReadOnly(control, state)` вместо независимого управления виджетом.
Инициализаторы вызывают её же после регистрации; `applyValues` вызывает общий
программный setter, сохраняя фильтрацию и merge, уже выполненные этим проходом.
Существующий `_obSetCodeValue` можно оставить совместимой обёрткой до завершения
срезов; параллельный вычислитель readonly не вводить.

Общий helper определить в `ui.js` до потребителей managed.js, сохранив загрузку
автоформ без managed.js. Проверить действительный порядок script tags тестом GET.
В managed-шаблоне различить постоянный запрет и временный начальный итог.
Для условно блокируемого редактора (включая условного предка) отрисовать holder
сразу и монтировать его в readonly; постоянный запрет может сохранить нынешнюю
textarea без holder. Это расширение редакторных веток, а не повтор picker-фикса.
Общую статическую классификацию брать из существующего обхода формы.

Вынести инициализацию Monaco в повторяемую `obInitCodeEditors(root)`, сделать
`obInitRichText(root)` совместимой с вызовом без аргумента. На уровне текущей
managed-формы один ограниченный MutationObserver обслуживает добавленные/
удалённые editor-пары: init новых, dispose удалённых. Его область — holder и
backing-узлы этой формы; внутренние DOM-мутации библиотек не запускают повторное
монтирование. При полном уходе со страницы observer отключается. В обследованном
коде общего события замены editor DOM не найдено, поэтому нельзя ссылаться на
несуществующий lifecycle-hook. Observer нужен для явно требуемой замены DOM;
нового механизма вычисления состояния он не содержит.

Асинхронный AMD callback проверяет `isConnected`, ближайшую текущую форму,
идентичность пары и поколение регистрации. Значение и состояние считываются
перед create; повтор callback/замена узла не создают дубль. Обработчики
change/blur/submit проверяют живое владение. Ошибка create оставляет textarea
видимой, не устанавливает ready-флаг навсегда и не теряет значение.

## Тесты и Verification

Новый Go fixture `TestManagedEditorReadonlyBrowserAcceptance` размещается в
`internal/ui/managed_editor_readonly_browser_test.go`: изолированный loopback
server, настоящий loader YAML/.form.os, registry/storage, GET/event/save/read.
Добавить `e2e/acceptance/editor-readonly.spec.js` и явный запуск этой suite из
fixture; существующий `browseracceptance.Run` понимает только runtime/configurator,
поэтому расширить его whitelist либо повторить прямой запуск Playwright по образцу
hidden-copies. Новый Go-test явно включить в regexp job `e2e` с
`ONEBASE_BROWSER_ACCEPTANCE=1`; он не должен тихо skip при отсутствии browser/assets.
В fixture использовать реальные vendored Monaco/Quill, без CDN и stub-only API.

Матрица A/B проверяет оба редактора, оба направления переключения и старт в
readonly/editable. C выполняет её на SQLite и PostgreSQL через
`dbtest.ForEachDialect`; в обязательном e2e задать доступную PG-базу аналогично
существующему browser-acceptance шагу. Отсутствие PG локально отметить явно,
а не считать матрицу завершённой. Go render/event-тесты дополняют браузер, но
не заменяют его. Условный запрет предка и static readonly проверять раздельно.

Для каждого сценария проверять видимый текст, backing/FormData, фактический
HTTP payload, сохранённое/read-back значение и dirty до/после. Фикстура включает
чистую и уже изменённую форму; отдельный серверный handler обновляет оба текста
и ставит/снимает запрет в одном ответе. Новый разрешённый ввод после ответа не
может быть затёрт запоздавшим ответом по старой revision. Проверка dirty идёт
через пользовательский уход/вопрос о сохранении и реальные эффекты, без вызова
private JS функции. Копии одного реквизита проверяют раздельное состояние при
общей разрешённой программной синхронизации значения.

Гонки строить барьерами: перехватить запрос реального AMD/vendor-ресурса или
настоящий HTTP-ответ, дождаться нужного события/DOM, отпустить исходные bytes.
DOM-замена в lifecycle-тесте заменяет размещение свежей разметкой из реального GET;
она не изображает существующий продуктовый endpoint замены формы. Для повторного
init допустим вызов публичного initializer, а исходное состояние всё равно
приходит из GET/event. Не использовать фиксированный sleep, поддельный
`elementStates` или замену Monaco/Quill заглушками как доказательство приёмки.

Ручная проверка повторяет GET → ввод → запрет → попытки ввода/toolbar →
разрешение → новый ввод → запись → перезагрузка; затем запрет на первом GET,
замедленная библиотека, серверный новый текст и отказ загрузки vendor. Наблюдать
Network/form-event, отсутствие console errors/двух toolbar и сохранность dirty.

После каждого кодового среза: `go build ./...`, тесты `./internal/ui`, новая
браузерная fixture с `ONEBASE_BROWSER_ACCEPTANCE=1` после `npm ci` и установки
Playwright в `e2e/`, затем CI8: `build`, `lint`, `postgres-integration`, `vuln`,
`smoke`, `e2e`, `test-windows`, `launcher-webview-build`. Прогон новой browser
fixture на исходном main с тестовыми файлами должен дать целевые assertion
failures, а не missing dependency/timeout/skip. Записать команды и результат
контролей в кодовый PR. Для данного плана достаточно plannum, проверки ссылок
и diff только Plans/; зелёного кода/браузера этот документ не утверждает.

## Риски, откат и критерии завершения

Риски: неверная классификация постоянного запрета отпирает поле; silent setter
может потерять dirty/HTML; старый callback затрагивает новый DOM; observer
реагирует на внутренние мутации библиотек; Quill автоформ зависит от общего init.
Каждый риск привязан к публичному тесту выше. Изменение script order и утечки
model/listeners проверять повторным mount/remove, счётчиками подписок как
дополнительной диагностикой и пользовательским отсутствием двойных запросов.

Откат — revert кодовых срезов в обратном порядке C/B/A; DDL и преобразований
сохранённых данных нет. На время сбоя библиотек сохранять textarea с серверным
запретом. Откат возвращает известный исходный дефект; серверные права остаются
границей защиты. Нельзя лечить отказ виджета снятием постоянного запрета.

Готово, когда A–C приняты, оба реальных редактора проходят всю матрицу через
HTTP и save/read, отрицательные контроли подтверждены, CI8 зелёный, а постоянные
запреты и серверный отказ записи не ослаблены. README получает фактический статус
после поставки; слияние этого plan-PR лишь возвращает issue в FIX по протоколу.
