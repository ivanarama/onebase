# Заявки выбранного клиента на форме обращения

```
onebase check --project examples/related-lists
onebase run --project examples/related-lists --sqlite /tmp/related-lists.db --port 8187
```

Создайте клиентов A и B, затем по несколько заявок для каждого с датой,
номером и состоянием. Откройте новое обращение и выберите клиента: появятся
пять последних доступных заявок. Смените A → B → A и очистите клиента —
обращение при этом не записывается, комментарий сохраняется в форме.
Нажатие на номер или Enter открывает заявку в отдельной вкладке.

Для проверки прав создайте операторские роли: read/write на Обращение,
read на Клиент и Заявка; строковая политика read Заявка должна ограничивать
поле Оператор текущим login. Заполните семь заявок, часть для другого
оператора: лимит применяется к доступным строкам. Повторите с пользователем
без read на Заявка — строк не будет. Телефон клиента отмечен pii; ссылка
разрешается с учётом прав и маски связанной карточки, сырой телефон в выдачу
не включён. Обычный администратор видит все строки.

Список только читает данные. Обновление списка не вызывает обработчик формы,
не сохраняет обращение и не меняет его табличные части. При ошибке или запрете
доступа предыдущие строки очищаются. Для отката сначала удалите новый элемент
из YAML, затем возвращайте старый бинарь; прикладные данные сохраняются.
