# Адрес выезда обычными реквизитами

Самостоятельный пример к #1533: документ «Наряд» хранит город, улицу, дом,
корпус, квартиру, подъезд, этаж и домофон. Общий модуль `Адрес` задаёт одно
представление для печати и JSON-обмена. Это прикладная модель: встроенного типа
«Адрес», адресного виджета, классификатора и подбора «город → улица → дом» здесь
нет. Данные вводятся в отдельные поля.

## Запуск

Из корня репозитория (ниже `onebase` — собранный бинарь):

```sh
onebase check --project examples/address
onebase migrate --project examples/address --sqlite /tmp/address-demo.db
onebase procrun --project examples/address --sqlite /tmp/address-demo.db --proc ДемоАдреса
onebase run --project examples/address --sqlite /tmp/address-demo.db --port 8080
```

Откройте `http://localhost:8080/ui/`, затем документ «Наряд». Обработка создаёт
новый наряд при каждом запуске и выводит его номер. Можно создать наряд вручную
и заполнить адрес в форме. Сохраните документ: `ПриЗаписи` вызывает
`Адрес.Представление(this)` и записывает поле `АдресПредставление`. Поле в форме
доступно только для чтения; результат виден после сохранения и открытия наряда.
В меню печати выберите «НарядНаВыезд». Макет использует сохранённое представление,
а исходную строку показывает отдельно.

Для выгрузки подставьте номер, выведенный обработкой или показанный в карточке:

```sh
onebase procrun --project examples/address --sqlite /tmp/address-demo.db \
  --proc ЭкспортНаряда --set Номер=АД-00001
```

Обработка выводит JSON в сообщении `Сообщить`: это пример payload, который можно
передать прикладному интеграционному коду. Вывод этой обработки — одна строка
JSON; сообщения диагностики при ошибке не являются payload. Общий модуль
`Адрес.ДанныеДляОбмена`
возвращает соответствие из девяти исходных реквизитов и `АдресПредставление`.
Для обмена вычисление использует ту же функцию, что и хук записи; JSON сохраняет
части отдельно, чтобы принимающая система не разбирала строку представления.
Имена ключей сохраняют регистр; незаполненные (`NULL`) части в JSON передаются
пустыми строками.

Демонстрационное представление:

```text
г. Белград, ул. Примерная, д. 12А, корп. 2, кв. 07, подъезд 3, этаж 0, домофон 07#
```

Все части — строки: дом может быть «12А», квартира «07», этаж «0» или «-1».
Пустые части пропускаются, края заполненных частей убираются только в
представлении. Исходные реквизиты не нормализуются. Подписи и порядок принадлежат
этому примеру; для другой страны адаптируйте общую функцию, сохраняя единый
вызов в записи и обмене. Код домофона попадает в печать и обмен: в рабочем проекте
ограничьте доступ к нарядам и получателям payload.

## Перенос существующего строкового адреса

1. Сохраните резервную копию рабочей базы. В своей конфигурации добавьте части
   адреса и поле `ИсходныйАдрес`, сохранив прежний строковый реквизит.
2. Перенесите старую строку в `ИсходныйАдрес` без изменения символов; миграцию
   выполняйте отдельной прикладной обработкой. Пример не меняет рабочие проекты
   и не содержит автоматического разбора.
3. Пока части не заполнены, функция возвращает исходную строку целиком. Когда
   пользователь заполняет хотя бы одну непустую часть, представление строится
   только из структурных полей. Исходная строка остаётся отдельным реквизитом,
   попадает в JSON и печать; проверьте полноту переноса до переключения потребителей.
4. Проверьте вручную адреса с корпусом, буквой в доме, нулевым этажом и неполными
   частями. Не удаляйте старые значения до сверки печати и обмена.

Классификатор можно позже подключить средствами своей конфигурации. Этот пример
не поставляет его данные и не гарантирует актуальность или уникальность адресов.
Не меняйте типы действующих реквизитов и не делайте автоматический разбор строки
при импорте из 1С.

## Проверка сценария

```sh
go test ./internal/ui -run TestAddressExample_SavePrintAndExchange -count=1
```

Тест загружает именно этот пример, сохраняет наряды через HTTP-форму, запускает
экспорт через публичный runner обработок и получает печатную форму через HTTP.
Проверяются создание и редактирование наряда, полный, частичный, пустой и
перенесённый строковый адреса, сохранение «0»/«07», отсутствие лишних разделителей и совпадение представлений в трёх путях.
