# Как работать с проектной базой СППР

Это конфигурация OneBase, описывающая проектируемое решение как данные. Она не
содержит кода конфигурации — код лежит в YAML и `.os` целевого проекта; здесь
живёт модель: функции, связи, объекты метаданных, трассировка, сценарии,
правила, задачи, затраты.

## Порядок работы агента

1. Прочитай конфигурацию целевого проекта: `onebase describe --project <путь>`.
   Результат — перечень справочников, документов, регистров, отчётов; из него
   заполняются справочники «Объекты метаданных», «Подсистема», «Роль».
2. Заведи функцию (справочник «Функция») со статусом «Черновик», опиши
   результат для бизнеса и родителя. Переводы статуса: Черновик →
   НаСогласовании → Утверждена. Гейт этапов запрещает перескок.
3. Опиши связи функции в регистре «Связи функций» (Источник, Выход,
   Управление, Ресурс) — это стрелки IDEF0.
4. Привяжи объекты метаданных и файлы через регистр «Трассировка»: функция,
   объект, путь к файлу, коммит.
5. Заведи тестовый сценарий (вид «Сценарий») с шагами; функция без сценария
   попадает в результаты аудита.
6. Заведи задачу по функции; статусы идут по маршруту Новая → Принята →
   ВРаботе → НаПроверке → Выполнена. Проведение пишет историю в регистр
   «История статусов задач».
7. Запусти аудит: обработка `АудитПравил` (регламентное задание по расписанию)
   применяет опубликованные правила и пишет результаты; читай их отчётом
   «Результаты аудита».

## Правила записи

* Статусы объектов меняются только по маршруту этапов: запись вне маршрута
  отклоняется слоем хранения.
* Правило аудита — самодостаточный запрос без параметров; его изменения
  публикуются документом «Публикация правила», старые результаты не меняются.
* Тесты каркаса: `onebase test --project examples/sppr --sqlite :memory:`
  (`kind: test`, проверяет гейт этапов, права ролей, трассировку, аудит).
* Проверка конфигурации после каждой правки: `onebase check --project examples/sppr`.

## Права ролей

* Проектировщик — функции, объекты метаданных, сценарии, связи, трассировка.
* Разработчик — задачи, объекты метаданных, трассировка, учёт времени,
  проведение ошибок.
* Тестировщик — сценарии, проведение ошибок, чтение результатов аудита.
* Руководитель — утверждение функций, публикация правил, планирование занятости.
