# Тестовые сценарии Gherkin

Тестовый сценарий описывает поведение каркаса шагами на естественном языке и
компилится в тест-обработку (kind: test), которую гоняет тестовый раннер
`onebase test`. Страницы со списком тестов в UI пока нет: обработка видна в
каталоге обработок, результат — в выводе команды и JUnit-отчёте. Сценарий
лежит в `features/`, реестр шагов — `features/шаги.yaml`.

Шаг связывается с DSL реестром: шаг «действие» выполняет код, шаг «проверка»
вычисляет значение и даёт проверку `Утверждать.Равно`, `.Истина` и другие из
раннера. Параметры шага пишутся `<Имя>`; значение подставляется с учётом места:
внутри строкового литерала DSL (текст запроса) значение уходит SQL-литералом в
одинарных кавычках, вне литерала — строкой DSL.

Компиляция:

    onebase gherkin compile --project examples/sppr

Каждый сценарий и каждая строка Примеров дают свою обработку с именем
`Тест<Функция>_<Сценарий>[_<Строка>]`; пара файлов — `processors/` и `src/`.
Шаг-таблица печатается в модуле комментарием: правка модуля руками рвёт связь
с `.feature`. Строка Примеров получает суффикс своих значений, две строки не
сливаются в одну обработку.

Компиляция отказывается, если хоть один шаг не сопоставлён с реестром или
сценарий не содержит шагов-проверок. Отказ отменяет запись всего прогона:
половина теста записанного компилятора нет.

Скомпилированные обработки каркаса: `ТестРасстановкаФункций_Объект` (объект
закрепляется за узлом, функция объекта и запись трассировки) и две обработки из
строк Примеров для узлов `2.2` и `2.4`. Прогон:

    onebase test --project examples/sppr --sqlite <файл>

JUnit-отчёт: `onebase test --format junit`. Сценарий закрепления объекта за
функцией нужен потому, что мост метаданных импортирует объекты и функцию
объекту не назначает: выбор узла декомпозиции — решение проектировщика, и оно
должно быть закрыто тестом. Обработка ТестРасстановкаФункций_Объект видна
как карточка обработок.
