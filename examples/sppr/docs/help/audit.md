# Аудит формальных правил

Правило проверки — данные: код, объект проверки, важность (Блокирующее,
Предупреждение, Информация), текст запроса, сторона проверки (База,
ЦелевойПроект) и ссылка на источник. Текст запроса самодостаточен: параметров
в нём нет, условие записано литералом.

Действующая версия правила публикуется документом «Публикация правила».
Срез последних по регистру «Действующие правила» даёт версию, активную на
дату проверки, поэтому переиздание правила не меняет уже зафиксированные
результаты.

Регламентное задание «Аудит формальных правил» применяет опубликованные
активные правила стороны «База» и пишет строки в регистр «Результаты
проверки». Правила стороны «ЦелевойПроект» исполняются над срезом целевого
проекта обработкой «ЗаписатьИтогПрогона» (headless procrun) и пишут результат
в тот же регистр: регистра write-маршрута REST v2 нет. Отчёт «Результаты
аудита» показывает нарушения по коду правила и объекту.
