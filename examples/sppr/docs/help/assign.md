# Расстановка функций по импортированному описанию

Мост переносит объекты целевого проекта в проектную базу без функции. Функция —
единственный владелец объекта в декомпозиции, её назначает проектировщик под
своей ролью: это проектное решение, а не результат разбора описания.

Порядок наполнения проектной базы:

```bash
onebase procrun --project examples/sppr --sqlite <файл базы> --proc ЗаполнитьДемоданные
onebase procrun --project examples/sppr --sqlite <файл базы> --proc ИмпортОписания \
  --file Файл=desc.json --set Проект=<id проекта> --set КорневаяФункция=<id функции>
onebase procrun --project examples/sppr --sqlite <файл базы> --proc ЗавестиДеревоФункций \
  --file Файл=дерево.json --set Проект=<id проекта>
onebase procrun --project examples/sppr --sqlite <файл базы> --proc ЗаписатьСвязи \
  --set Список="потребитель;источник;Вход;данные~…"
onebase procrun --project examples/sppr --sqlite <файл базы> --proc РасставитьФункции \
  --set Пары="кодфункции=имя:тип;имя:тип|…"
onebase procrun --project examples/sppr --sqlite <файл базы> --proc АудитПравил
```

`ЗаполнитьДемоданные` заводит дерево механизмов самой базы (узлы 4.x) — каркас
проектирует и себя. `ЗавестиДеревоФункций` заводит дерево целевого проекта по
JSON-массиву узлов `{"код","наименование","родитель","результат","трудозатраты"}`:
узлы идемпотентны по коду, заводятся статусом «Черновик» — утверждение остаётся
за руководителем. Логика в модуле `Наполнение`, обработка — тонкая оболочка.

`ЗаписатьСвязи` кладёт стрелки ICOM в регистр «СвязиФункций»: записи
`потребитель;источник;вид;данные`, разделитель записей `~`, идемпотентность по
паре измерений. `РасставитьФункции` без параметра `Пары` обрабатывает зашитые
узлы каркаса; с параметром — пары целевого проекта.

Расстановка задаёт пары «имя:тип», разделённые точкой с запятой. Имя объекта
одного типа может совпадать с именем объекта другого: регламентное задание
«АудитПравил» и обработка «АудитПравил» — два разных объекта целевого проекта,
и выборка по одному имени перетащила бы функцию на оба. пара задаёт и объект
табличной части postings, который описания `describe` не показывает по имени:
модуль проведения документа носит имя документа (`Задача:Модуль`).

Объект, которому функция назначена, получает контроль «Проверено» и строку
регистра «Трассировка» с путём файла из карточки объекта. Объект, пары которому
нет, остаётся без функции и попадает под правило аудита «Объект целевого
проекта без функции» — это и есть проектный долг: узел декомпозиции, за который
файл не закреплён.

Отчёт «Покрытие функций» считает объекты, сценарии и задачи отдельными
различными ссылками. Функция, соединённая с тремя источниками одним запросом,
даёт произведение строк, и обычный `КОЛИЧЕСТВО()` пересчитал бы каждую пару
«объект × сценарий». Отчёт «Функции без объектов» (виджет) и правило аудита
«Утверждённая функция без задачи» дополняют картину: узел, который утверждён,
но ничем не закрыт.
