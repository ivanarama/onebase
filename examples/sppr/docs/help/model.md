# Функциональная модель

Функция — узел дерева декомпозиции: код вида `1.2.3`, наименование, результат
для бизнеса, тип (функция/механизм), ответственный, трудозатраты. Родительская
функция задаётся полем «Родительская функция».

Связи между функциями живут в регистре «Связи функций». Вид связи:

* **Источник** — что поступает в функцию (вход);
* **Выход** — что функция отдаёт потребителю;
* **Управление** — кто задаёт условия работы функции;
* **Ресурс** — чем функция обеспечивает работу.

Статус функции проходит маршрут: Черновик → НаСогласовании → Утверждена.
Гейт переходов стоит в слое хранения, поэтому утвердить функцию «в обход»
маршрута нельзя: запись вне маршрута отклоняется.

Функция считается утверждённой, когда у неё есть тестовый сценарий: правило
аудита фиксирует отсутствие сценария как нарушение.
