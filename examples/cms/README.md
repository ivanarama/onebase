# Пример «cms» — сайт на OneBase

Конфигурация показывает, как вести публичный сайт в той же базе, где идёт учёт:
контент правится обычными формами платформы, а страницы отдаются HTTP-сервисом.

Состояние: **готов к обкатке** (слайсы C1–C12 плана
`Plans/129-cms-site-configuration.md`). Есть роутер, меню, список и карточки
новостей, редиректы, 404, `robots.txt`, `sitemap.xml`, canonical и Open Graph.
Из плана остались только необязательные пункты: параметры блоков (C3.5) и
дополнительные готовые стили.

## Установка

```bash
onebase check --project examples/cms
onebase migrate --project examples/cms --sqlite cms.db
onebase procrun --project examples/cms --sqlite cms.db --proc ЗаполнитьТестовуюБазу
onebase settings set net.enabled вкл --sqlite cms.db   # предохранитель сети (план 62)
onebase run --project examples/cms --sqlite cms.db --port 8080
```

Сайт открывается по `http://localhost:8080/hs/site/`. Проверенные адреса:

| Адрес | Ответ |
|---|---|
| `/hs/site/` | главная (страница со слагом `главная`) |
| `/hs/site/about` | страница по слагу |
| `/hs/site/o-kompanii` | `301` на `/hs/site/about` — правило из справочника «Редиректы» |
| `/hs/site/нет-такой` | `404` со страницей ошибки в оформлении сайта |
| `/hs/site/news` | список новостей с анонсами и датами |
| `/hs/site/news/<слаг>` | карточка публикации |
| `/hs/site/sitemap.xml` | карта сайта по опубликованным адресам |
| `/hs/site/robots.txt` | содержимое из реквизита сайта |
| `/hs/site/style.css` | CSS сайта отдельным файлом |

Сайт живёт под префиксом `/hs/site/`. Чтобы отдавать его в корне домена,
поставьте перед OneBase reverse proxy (nginx, Caddy) с правилом
`/ → /hs/site/`: разрешать сервисам занимать корень платформы означало бы
конфликт с `/ui`, `/api` и статикой.

> **За прокси перестаёт работать ограничение по адресу.** `rate_limit` в
> сервисах считается по адресу соединения и намеренно не доверяет заголовку
> `X-Forwarded-For` (подделать его может кто угодно, если фронт не свой). За
> прокси адрес соединения у всех запросов один, поэтому лимит из
> «60 отправок формы с одного посетителя» превращается в «60 со всех разом»:
> один бот исчерпает квоту, и остальные получат 429. Пока в платформе нет
> списка доверенных прокси, ограничивайте частоту на самом прокси —
> `limit_req` в nginx, `rate_limit` в Caddy — по настоящему адресу клиента.

## Устройство

Раздел **«Сайт»** — то, что правит контент-менеджер:

| Объект | Назначение |
|---|---|
| `Страницы` | Статические страницы («О компании», «Контакты»), иерархия |
| `Новости` | Публикации с датой, категорией и анонсом |
| `КатегорииКонтента` | Рубрики новостей и статей |
| `Меню` | Многоуровневые меню, сгруппированные по `КодМеню` |
| `Медиа` | Файлы сайта; наружу отдаются ссылкой `/pub/<токен>` |

Раздел **«Оформление и адреса»** — то, что правит редактор:

| Объект | Назначение |
|---|---|
| `Сайты` | Домен, язык, ссылки на стиль и шаблон, содержимое `robots.txt` |
| `СтилиСайта` | Палитра и дополнительный CSS |
| `ШаблоныСайта` | HTML-макет страницы для объекта `ШаблонHTML` |
| `Блоки` | Переиспользуемые фрагменты разметки (шапка, подвал, баннер) |
| `МаршрутыURL` | Правила адресов: шаблон → тип контента |
| `Редиректы` | Старый адрес → новый (301), чтобы переезд не обнулил поиск |

Роли: `КонтентМенеджер` — только контент, `РедакторСайта` — контент и
оформление. Разделение осознанное: ошибка в макете ломает сайт целиком, а
тексты правятся ежедневно.

### Общий контентный контур

У «Страниц», «Новостей» и будущих товаров одинаковый набор реквизитов: `Слаг`,
`СтатусПубликации`, `ДатаПубликации`, `ЗаголовокSEO`, `ОписаниеSEO`,
`OGКартинка`, `Сайт`. Один набор имён — один код роутера и рендера на все типы
контента (идея инфоблоков Битрикса, но без второго уровня «тип инфоблока»).
Отложенная публикация работает без регламентного задания: роутер показывает
только `Опубликовано` с `ДатаПубликации <= сейчас`.

## Правила, которых держится конфигурация

1. **HTML собирается только объектом `ШаблонHTML`** (план 125). Никакой склейки
   строк: значения из базы обязаны экранироваться по контексту вставки, иначе
   наименование товара с `<script>` исполнится у посетителя.
2. **Готовая разметка проходит через `БезопасныйHTML(...)`** — санитайзер
   вырезает скрипты и обработчики событий, оставляя форматирование.
3. **Картинки живут в базе** и отдаются публичными ссылками `/pub/<токен>`
   (план 127), а не внешним CDN.
4. **Публичный сервис кэшируется** (план 126, только `auth: none`), а
   инвалидация — обязанность конфигурации: `СброситьКэшСервисов("Сайт")` из
   `ПриЗаписи` контентных справочников.

## Перенос сайта с 1С-Битрикс

Каталог переносится YML-выгрузкой — её умеет отдавать почти любая российская
CMS, включая Битрикс. Доступ к чужой базе и конвертер инфоблоков не нужны:

```bash
onebase procrun --project examples/cms --sqlite cms.db   --proc ИмпортИзYML --file Файл=examples/cms/demo/catalog.yml
```

Импорт создаёт группы и товары, восстанавливает иерархию категорий и собирает
слаги транслитерацией («Насос циркуляционный НЦ-25» → `nasos-cirkulyacionnyy-nc-25-101`).
Повторный запуск обновляет позиции по внешнему коду, а не плодит дубли — при
переезде выгрузку запускают повторно чаще, чем кажется.

Картинки из выгрузки не скачиваются: сохраняется только адрес. Тянуть чужой
сервер в момент миграции — лишняя точка отказа; перенос картинок в медиатеку
делается отдельным шагом.

Соответствие остальных понятий: инфоблок → справочник, символьный код → слаг,
типы меню → `КодМеню`, композитный сайт → кэш ответов, агенты → регламентные
задания, веб-формы → «Формы обратной связи».

## Медиатека

Файлы сайта лежат в базе, а не на внешнем CDN. Картинка кладётся в поле карточки
«Медиа», а публичный адрес выдаёт хук `ПриЗаписи`:

```
ЭтотОбъект.ПубличнаяСсылка = ОпубликоватьКартинку(ЭтотОбъект.Файл, Опции);
```

Публикация происходит при записи, а не при рендере: GET-запрос посетителя не
должен писать в базу. Снятие галки «Активен» отзывает ссылку — адрес перестаёт
работать сразу, а не после чистки кэша.

Адрес содержит случайный токен, подобрать его нельзя. В разметку он попадает
через обычное поле данных, поэтому шаблон экранирует его как URL.

## Кэш и его инвалидация

Публичный сервис кэширует ответы на 60 секунд. Правка контента сбрасывает кэш
сама — в модулях объектов контентных справочников есть `ПриЗаписи` с вызовом
`СброситьКэшСервисов("Сайт")`.

**Важное свойство:** кэш живёт в памяти процесса сервера, поэтому сбрасывает
его только правка, сделанная ЭТИМ процессом — то есть через веб-интерфейс или
REST. Изменения из отдельного процесса (`onebase procrun`, регламентное задание
в другом экземпляре, прямая правка базы) сервер увидит лишь по истечении `ttl`.
Это проверено: правка заголовка через `procrun` не изменила выдачу до
истечения срока. Если сценарий требует мгновенного обновления из внешнего
процесса — уменьшайте `ttl` или дёргайте сайт после записи.

## Тесты конфигурации

```bash
onebase test --project examples/cms --sqlite cms.db --format tap
```

`ТестРоутера` проверяет подбор контента — ту часть, где ошибка не видна глазом:
страница открывается, но не та, либо черновик утекает наружу. Тест сразу нашёл
настоящий дефект: `НайтиСтраницу` не нормализовала входной адрес, и слаг в
другом регистре не находился.

## Поиск по сайту

Строка поиска в шапке ведёт на `/hs/site/search?q=…`. Под ней — полнотекстовый
индекс платформы: состав задан блоком `fulltext:` в метаданных «Страниц» и
«Новостей», отдельный индекс сайту не нужен.

Выдача фильтруется дважды: по типу объекта (адрес на сайте есть только у
страниц и новостей) и по публикации — индекс знает о черновике, но посетителю
его показывать нельзя.

## Формы обратной связи

Форма привязывается к странице реквизитом «Форма» и отправляется обычным
`<form method="post">` — без JavaScript. Приём вынесен в ОТДЕЛЬНЫЙ сервис
`Формы` (`/hs/forms/submit/<код>`): у «Сайта» анонимное чтение с кэшем, здесь
анонимная запись, и настройки одного не должны молча распространяться на другой.

Проверка полей — регулярными выражениями (план 124). Правила намеренно мягкие:
задача не отсеять почту по букве RFC, а поймать очевидный мусор. Подозрительное
не выбрасывается молча — заявка сохраняется со статусом «Спам», потому что живой
человек с необычным адресом не должен исчезать бесследно.

Защита от ботов — honeypot: поле, скрытое стилями (`position:absolute;
left:-9999px`, а не `type=hidden` — скрытое по типу бот распознаёт и пропускает).
Заполненная ловушка даёт ответ «спасибо» без записи в базу: иначе бот поймёт,
что попался, и подстроится.

Проверено живой отправкой: корректная заявка → 200 и запись в базе; кривой
контакт → 422 с внятным текстом; honeypot → 200 без записи; сообщение со
ссылкой → сохранено со статусом «Спам».

## Три грабли, на которых стоит эта конфигурация

1. **Ссылка из результата запроса не разыменовывает реквизиты** в контексте
   HTTP-сервиса: `ЗначениеРеквизитаОбъекта(Ссылка, "Домен")` молча возвращает
   `Неопределено`, и в `canonical` уезжает `https://<nil>/…`. Поэтому параметры
   сайта берутся ОДНИМ запросом с разыменованием через точку
   (`Стиль.CSS КАК CSS`), а роутер отдаёт структуру, а не ссылку.
2. **CSS нельзя вставлять в `<style>` шаблоном**: `html/template` в
   CSS-контексте заменяет произвольное значение на `ZgotmplZ` — и правильно
   делает. CSS отдаётся отдельным файлом `/style.css`, заодно кэшируется
   браузером и позволяет держать `style-src 'self'` без `unsafe-inline`.
3. **Функции внутри одного `.service.os` не видят друг друга** — вспомогательная
   процедура рядом с обработчиком падает в рантайме с «unknown function».
   Общий код живёт в `*.module.os`; сборка страницы-подтверждения поэтому
   лежит в `Рендер`, а не рядом с обработчиком формы.
4. **Латиница в публичных адресах и именах полей формы.** Кириллический сегмент
   шаблона URL сопоставляется только с процентным кодированием, а имя поля,
   присланное внешним клиентом, легко приходит не в UTF-8. Подписи для
   посетителя при этом остаются русскими — они в разметке.
5. **`Строка(Неопределено)` даёт «<nil>», а не пустую строку.** Непереданное
   поле формы выглядело заполненным, из-за чего honeypot считался сработавшим
   и КАЖДАЯ заявка молча отбрасывалась с видом успеха. Поля читаются через
   функцию `Поле()`, которая возвращает пустую строку.
6. **XML не собирается объектом `ШаблонHTML`**: он экранирует XML-декларацию
   как текст, и `sitemap.xml` перестаёт быть XML. Карта сайта собирается
   строкой с явным экранированием — правило простое: `ШаблонHTML` только для
   HTML.
