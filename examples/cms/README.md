# Пример «cms» — сайт на OneBase

Конфигурация показывает, как вести публичный сайт в той же базе, где идёт учёт:
контент правится обычными формами платформы, а страницы отдаются HTTP-сервисом.

Состояние: **модель данных** (слайсы C1–C2 плана
`Plans/129-cms-site-configuration.md`). Заведены оформление, контент, медиатека,
меню, маршруты и редиректы; роутер, рендер и SEO добавляются следующими
слайсами.

## Установка

```bash
onebase check --project examples/cms
onebase migrate --project examples/cms --sqlite cms.db
onebase run --project examples/cms --sqlite cms.db --port 8080
```

## Устройство

Раздел **«Сайт»** — то, что правит контент-менеджер:

| Объект | Назначение |
|---|---|
| `Страницы` | Статические страницы («О компании», «Контакты»), иерархия |
| `Новости` | Публикации с датой, категорией и анонсом |
| `КатегорииКонтента` | Рубрики новостей и статей |
| `Меню` | Многоуровневые меню, сгруппированные по `КодМеню` |
| `Медиа` | Файлы сайта; наружу отдаются ссылкой `/pub/<токен>` |

Раздел **«Оформление и адреса»** — то, что правит редактор:

| Объект | Назначение |
|---|---|
| `Сайты` | Домен, язык, ссылки на стиль и шаблон, содержимое `robots.txt` |
| `СтилиСайта` | Палитра и дополнительный CSS |
| `ШаблоныСайта` | HTML-макет страницы для объекта `ШаблонHTML` |
| `Блоки` | Переиспользуемые фрагменты разметки (шапка, подвал, баннер) |
| `МаршрутыURL` | Правила адресов: шаблон → тип контента |
| `Редиректы` | Старый адрес → новый (301), чтобы переезд не обнулил поиск |

Роли: `КонтентМенеджер` — только контент, `РедакторСайта` — контент и
оформление. Разделение осознанное: ошибка в макете ломает сайт целиком, а
тексты правятся ежедневно.

### Общий контентный контур

У «Страниц», «Новостей» и будущих товаров одинаковый набор реквизитов: `Слаг`,
`СтатусПубликации`, `ДатаПубликации`, `ЗаголовокSEO`, `ОписаниеSEO`,
`OGКартинка`, `Сайт`. Один набор имён — один код роутера и рендера на все типы
контента (идея инфоблоков Битрикса, но без второго уровня «тип инфоблока»).
Отложенная публикация работает без регламентного задания: роутер показывает
только `Опубликовано` с `ДатаПубликации <= сейчас`.

## Правила, которых держится конфигурация

1. **HTML собирается только объектом `ШаблонHTML`** (план 125). Никакой склейки
   строк: значения из базы обязаны экранироваться по контексту вставки, иначе
   наименование товара с `<script>` исполнится у посетителя.
2. **Готовая разметка проходит через `БезопасныйHTML(...)`** — санитайзер
   вырезает скрипты и обработчики событий, оставляя форматирование.
3. **Картинки живут в базе** и отдаются публичными ссылками `/pub/<токен>`
   (план 127), а не внешним CDN.
4. **Публичный сервис кэшируется** (план 126, только `auth: none`), а
   инвалидация — обязанность конфигурации: `СброситьКэшСервисов("Сайт")` из
   `ПриЗаписи` контентных справочников.

## Перенос сайта с 1С-Битрикс

Готовится отдельным слайсом (импорт каталога из YML-выгрузки). Соответствие
понятий: инфоблок → справочник, символьный код → слаг, типы меню → `КодМеню`,
композитный сайт → кэш ответов, агенты → регламентные задания.
