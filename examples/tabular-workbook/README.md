# Одна XLSX-книга из нескольких ТабличныхДокументов

Для служебной записки по нескольким направлениям создайте
`КнигаТабличныхДокументов` (`SpreadsheetWorkbook`). Каждый `ДобавитьЛист`
(`AddSheet`) сохраняет снимок документа: исходный ТабДок можно очистить и
переиспользовать для следующего направления.

```bsl
Книга = Новый КнигаТабличныхДокументов;
Документ = Новый ТабличныйДокумент;
Документ.Ячейка(1, 1).Значение = 111;
Документ.Ячейка(1, 1).ЦветФона = "#ff0000";
Книга.ДобавитьЛист("СМ", Документ);

Документ.Очистить();
Документ.Ячейка(1, 1).Значение = 222;
Документ.Ячейка(1, 1).ЦветФона = "#00ff00";
Книга.ДобавитьЛист("ХД", Документ);

СодержимоеBase64 = Книга.Записать("служебная-записка.xlsx", "xlsx");
```

Результат — base64 одной книги с листами `СМ`, `ХД` в порядке добавления.
Значения 111/222 остаются числами, заливки — красной/зелёной. Сохраняются
оформление, объединения, ширины/высоты, размер/ориентация страницы и fit-to-width,
закрепление областей, повтор шапки, уровни и свёрнутое состояние групп.
Используется тот же писатель листа, что у одиночного ТабДок.

`Записать` (`Write`) принимает имя и необязательный формат `xlsx`; возвращает
содержимое, как `ТабДок.Записать`. Имя — аргумент сериализации: метод не открывает
и не создаёт файлы на сервере или клиенте. Передача полученных байтов пользователю
или вложению остаётся за вызывающей обработкой. `Количество` (`Count`) возвращает
число добавленных листов. Пустая книга не выгружается; пустой ТабДок можно добавить.

Имена задаются явно, от 1 до 31 символа Unicode. Пустые/пробельные имена,
`[]:*?/\`, управляющие символы и апостроф по краям запрещены. Совпадения имён
без учёта регистра отклоняются. Имена не обрезаются и не переименовываются.
Ошибки доступны штатной конструкции `Попытка/Исключение`; неудачное добавление
не меняет книгу.

Ограничения приложения на **всю книгу**: 256 листов, 1 000 000 единиц работы
(сумма прямоугольников содержимого с объединениями плюс посещения строк групп),
1 000 000 записей ячеек/геометрии, 16 МиБ суммарных строковых данных оформления
и содержимого. Разреженная ячейка в далёкой строке учитывается по всему
прямоугольнику. Также проверяются границы Excel: 1 048 576 строк, 16 384 столбца,
включая объединения, размеры и закрепление. Эти лимиты проверяются до снимка
и формирования книги.

Для T8 конфигурация передаёт штатно подготовленный ТабДок каждого направления.
Расписания и доставка готовой книги настраиваются в прикладном слое.


## Скачивание и обновление из формы

В обработчике кнопки **Сформировать новый файл** передайте собранную книгу:

```bsl
СкачатьКнигуExcel("Отчёт 400.xlsx", Книга);
```

В обработчике кнопки **Дописать файл** передайте путь из константы приложения:

```bsl
Если ЗаменитьЛистыExcel(Константы.ПутьКОтчёту400, Книга) Тогда
    Сообщить("Книга обновлена");
КонецЕсли;
```

Администратор задаёт сервису абсолютный путь `ONEBASE_REPORT_XLSX_DIR`.
Выделите отдельный каталог для отчётов этого приложения и дайте процессу
OneBase права на чтение и замену файлов в нём. В константе можно указать имя
файла либо полный путь в этот каталог. XLSX должен уже существовать.
Вложенные каталоги и символические ссылки на файлы не поддерживаются.
Доступ определяется правами на форму и её команды. Функции доступны в
событии `Нажатие` управляемой формы конфигурации. Команда отдаёт одну книгу
в текущий браузер после успешного завершения обработчика.

Для отчёта 400 добавьте в книгу снимки листов `Итого`, `07Итого`, `14Итого`,
`21Итого` и лист последнего месяца. Совпавшие листы заменяются на месте,
новые добавляются в конец в порядке добавления в книгу. Конфликт регистра
в имени считается ошибкой. Лимит файла до и после обновления — 32 МиБ.
Другая операция OneBase ждёт освобождения каталога до 10 секунд. Каждый
успешный запрос получает свой снимок книги для скачивания.
Перед обновлением закройте рабочую книгу в Excel.
