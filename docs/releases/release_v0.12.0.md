## 🎯 Главное

`v0.12.0` — минорный релиз после `v0.11.0`. Три возможности пришли из рабочей
конфигурации колл-центра, где каждая обходилась костылём: доступность полей
формы теперь описывается условием, а не переписывается в хуке; признак ПДн
закрывает поле сам, а не ждёт, пока про него вспомнят в каждой роли; у параметра
отчёта появилось умолчание, из-за отсутствия которого отчёт молча приходил
пустым.

Остальное — почти сорок исправлений, из которых заметная часть меняет поведение
уже написанных конфигураций: обязательное поле формы перестало быть
декоративным, ссылочная колонка запроса перестала быть строкой, а дата из
запроса перестала съезжать на часовой пояс. Раздел «Изменения поведения» ниже
стоит прочитать до обновления рабочей базы.

## ✨ Условная доступность элементов формы

Из [#1172](https://github.com/ivanarama/onebase/pull/1172). Запрет, который живёт
в бизнес-логике (хук `ПриЗаписи`, проверка в модуле), на форме не был виден: поле
выглядело редактируемым, а отказ прилетал исключением уже при записи; кнопка,
недоступная в текущем состоянии, отвечала ошибкой на нажатие вместо того чтобы не
показываться.

```yaml
- kind: ПолеВвода
  name: ПолеУлица
  data_path: Объект.Улица
  readonly_when: 'СтадияОформления = "Принята"'

- kind: Кнопка
  name: КнопкаПринять
  hidden_when: 'СтадияОформления = "Принята"'
```

- **Язык выражений — тот же**, что у `when` условного оформления; отдельного
  диалекта не заводится.
- **Условия пересчитываются после каждого события формы**, а не только при
  отрисовке: команда, изменившая состояние объекта, сразу меняет доступность
  полей — перезагрузка не нужна.
- **Ошибка в условии элемент не запирает.** Молча запертое поле объяснить
  пользователю нечем, поэтому условие игнорируется, а конфигуратор получает
  предупреждение — как и в условном оформлении. Опечатка в имени поля ошибкой не
  считается (неизвестный идентификатор = пустое значение), такое условие просто
  никогда не срабатывает.
- **Собственный `readonly` элемента не заменяется, а дополняется** — условие
  только добавляет ограничение.

Якоря состояния получили и те элементы, что раньше пересчёт игнорировали:
`Надпись`, обе ветки `ПолеКартинки` и декларативная `КоманднаяПанель`
([#1208](https://github.com/ivanarama/onebase/issues/1208)) — у панели условие
адресовано фактическим кнопкам, потому что сама ветка дерева ничего не рисует.

Рядом — `link:` у KPI-виджета: счётчик «Передачи в карантине: 3» больше не
тупик, значение ведёт к самим данным.

## 🔒 Признак ПДн закрывает поле по умолчанию

Из [#1173](https://github.com/ivanarama/onebase/pull/1173). Маскирование ПДн
объявлялось только в ролях, и у этого две обратные стороны: новый реквизит с
телефоном открыт всем, пока про него не вспомнили в каждой роли по отдельности, а
роль без `field_access` видит значения целиком и без следа в журнале раскрытий.

Теперь `pii: true` у реквизита переворачивает умолчание:

```yaml
fields:
  - name: Телефон
    type: string
    pii: true
```

Роль, которая читает объект и **не высказалась** о таком поле, получает маску
`mask_all` — не раскрывающую ни значения, ни длины. Выход из fail-closed есть, но
он явный: роль пишет `read: full` (или свою стратегию — `mask_tail` и т. п.) и тем
самым принимает решение о раскрытии на себя. Семантика прежняя — наименее
ограничивающая роль побеждает, поэтому одна роль с явным `full` открывает поле.

Признак заодно перестал молча теряться: `pii` на поле табличной части — теперь
ошибка, а не тихий ноль; `pii` у поля бухрегистра — отказ; сам признак переживает
сохранение объекта в конфигураторе.

## 📊 Умолчание параметра отчёта

Из [#1174](https://github.com/ivanarama/onebase/pull/1174). Линт принимал ключ
`default` у параметра отчёта, а модель отчёта его не знала — значение молча
терялось. Отчёт с необязательной датой приходил пустым: условие вида
`ГДЕ Срок < &НаДату` при незаполненном параметре сравнивается с NULL и не
выбирает ничего.

```yaml
params:
  - name: НаДату
    type: date
    default: "{{today}}"
```

Умолчание понимает ту же грамматику подстановок, что параметры виджетов и
регламентных заданий (`{{today}}`, `{{now|-7d}}`). Подставляется оно **по
отсутствию значения, а не по пустоте** — очищенный пользователем параметр
остаётся очищенным, и умолчание не возвращается после сохранения настроек.

## 🧠 DSL и запросы

- **Ссылочная колонка результата запроса приходит ссылкой, а не строкой**
  ([#1150](https://github.com/ivanarama/onebase/issues/1150)) — подробности в
  «Изменениях поведения».
- **Дата из запроса больше не теряет время суток**
  ([#1170](https://github.com/ivanarama/onebase/pull/1170)). `Час()`, `Минута()`,
  `Год()` над датой, прочитанной запросом, считали по UTC: записанное «17:25»
  читалось как «14:25». Момент пишется в UTC, а `ТекущаяДатаВремя()` и интерфейс
  работают с местным временем — теперь так же работает и чтение.
- **`Формат(..., ДФ=…)` согласован с остальными датными функциями**
  ([#1211](https://github.com/ivanarama/onebase/issues/1211)): разбор идёт через
  общий `toTime`, поэтому `Формат` и `День` видят одну календарную дату на
  границе суток, а строковые даты SQLite форматируются как даты, а не выводятся
  сырой строкой.
- **Пропущенный аргумент в вызове — как в 1С**
  ([#1160](https://github.com/ivanarama/onebase/issues/1160)). Вызов вида
  `ЗаписьЖурналаРегистрации(Событие, Уровень,,, Комментарий)` больше не падает с
  `unexpected "," in expression`. Это чинит загрузку конфигураций, выгруженных из
  БСП, — конструкция там встречается в общих модулях
  ([#1256](https://github.com/ivanarama/onebase/issues/1256)).
- **`Документы.X.Провести(Ссылка)`** появился у менеджера документов симметрично
  `ОтменитьПроведение(Ссылка)` ([#1168](https://github.com/ivanarama/onebase/issues/1168)).
  Раньше вызов уходил в откат на модуль менеджера, не находил там одноимённой
  процедуры и возвращал `Неопределено` **без ошибки**: документ оставался
  непроведённым, движений не было, исключения тоже.

## 📋 Управляемые формы

- **`required: true` действительно проверяется**
  ([#1186](https://github.com/ivanarama/onebase/issues/1186)) — см. «Изменения
  поведения».
- **Ранний запрет не мешает хуку записи**
  ([#1235](https://github.com/ivanarama/onebase/issues/1235)): браузер проверял
  метаданный флаг до отправки формы и не давал выполнить `ПередЗаписью`, хотя
  серверный инвариант намеренно применяется после хуков.
- **Условный `readonly` больше не спорит с постоянным**: событие формы не снимает
  собственный `readonly` элемента, а условное ограничение считается поверх него.
- **Скрытая условием табличная часть не теряет строки при записи**, а скрытые
  условием флажок и вкладка перестали игнорировать `hidden_when`.
- **`onebase check` предупреждает об обработчике на событие, которого движок не
  вызывает** ([#1153](https://github.com/ivanarama/onebase/issues/1153)).
  Перечень таких событий вычисляется как «известные минус браузерные минус
  серверные», а не хранится вторым списком: в день, когда событие реализуют,
  предупреждение исчезнет само.

## ⚠️ Изменения поведения

**`required: true` у элемента управляемой формы блокирует запись**
([#1186](https://github.com/ivanarama/onebase/issues/1186)). До этого релиза флаг
рисовал звёздочку, но не мешал сохранить пустое значение — конфигурация
объявляла обязательность, получала подтверждение в интерфейсе и не получала
защиты. Теперь пустое значение отклоняется, поэтому форма, где `required` стоял
«для вида», перестанет сохраняться до заполнения поля.

Два флага различаются намеренно, и различие важно при отладке:

| Где объявлено | Когда проверяется | Что значит |
|---|---|---|
| `required` у **элемента формы** | в браузере, до отправки | правило конкретной формы |
| `required` у **реквизита** метаданных | на сервере, **после** хуков записи | глобальный инвариант финального состояния |

Метаданная обязательность проверяется по итоговому состоянию, поэтому
`ПередЗаписью` вправе заполнить поле сам — ранний браузерный запрет на такое поле
больше не ставится ([#1235](https://github.com/ivanarama/onebase/issues/1235)).
Обязательность реквизита при этом отражается в managed-форме автоматически
звёздочкой. Если нужен ещё и ранний браузерный запрет пустого submit, `required`
на элементе формы ставится дополнительно — нативный HTML-атрибут даёт именно он. Сохранены `0`, `Ложь`, readonly-поля,
form attributes, скрытые вкладки и авто-нумеруемые «Код»/«Номер».

**Ссылочная колонка результата запроса стала ссылкой**
([#1150](https://github.com/ivanarama/onebase/issues/1150)). `ТипЗнч(Выборка.Ссылка)`
отвечал «Строка», хотя руководство обещает квалифицированное имя типа, — код,
написанный по руководству, молча не срабатывал. Обёрнуты ровно две вещи:

| Написано в запросе | Колонка результата | Было | Стало |
|---|---|---|---|
| `ВЫБРАТЬ Ссылка` | `id` | `Строка` | `ДокументСсылка.Приход` |
| `ВЫБРАТЬ Проект.Ссылка КАК ПроектСсылка` | `проектссылка` | `Строка` | `СправочникСсылка.Проект` |
| `ВЫБРАТЬ Проект` | `проект` | `Строка` | `Строка` (представление, по устройству) |

Голый ссылочный реквизит в списке выборки по-прежнему разворачивается в
наименование связанной сущности, и «Строка» там правильный ответ. Совместимость —
часть правки: наименование ссылки остаётся UUID'ом, поэтому `Строка(Выборка.Ссылка)`,
конкатенация и печать отдают то же значение, что и раньше, а сравнение со строкой
UUID работает через приведение `*Ref` к идентификатору. Цена известна и её надо
знать: **`Выборка.Ссылка.Наименование` вернёт UUID**, а не настоящее
представление — вытащить его значило бы запрос на каждую строку. Значение, не
похожее на UUID, не оборачивается: подменённое маской ПДн значение ссылкой не
является.

**`ЗаписатьJSON` у ссылки отдаёт голый UUID** вместо разложенной структуры
([#1352](https://github.com/ivanarama/onebase/issues/1352)) — следствие того же
изменения. Модуль, выгружавший результат запроса в JSON и рассчитывавший на
объект с полями, получит строку идентификатора.

**Дата из запроса считается по местному времени**
([#1170](https://github.com/ivanarama/onebase/pull/1170),
[#1211](https://github.com/ivanarama/onebase/issues/1211)). Момент по-прежнему
хранится в UTC, меняется настенное представление, по которому считают
`Час`/`НачалоДня`/`Формат`. Модуль, который компенсировал сдвиг вручную —
прибавлял часы после чтения или держал час отдельным числовым реквизитом, —
получит двойную поправку; такие обходные пути надо снять. Не-дата по-прежнему
остаётся `Неопределено`: молчаливое приведение мусора к дате хуже.

**Признак `pii: true` закрывает поле для роли, которая о нём не высказалась**
([#1173](https://github.com/ivanarama/onebase/pull/1173)). Существующие
конфигурации это не затрагивает: признак ставит конфигуратор, и полей с ним пока
нет. Но конфигурация, которая проставит `pii` и не поправит роли, увидит маску
вместо значений — это и есть смысл fail-closed: маркер ПДн, который по умолчанию
не защищает, был бы просто комментарием.

**`onebase check` выдаёт новые предупреждения** на обработчики событий формы,
которых движок не вызывает
([#1153](https://github.com/ivanarama/onebase/issues/1153)). Это предупреждение,
а не ошибка: такие обработчики уже лежат в рабочих конфигурациях — конвертер 1С
их переносит, потому что в 1С эти события настоящие. Проверка перестала быть
чистой там, где раньше молчала, но `onebase check --project examples/trade`
по-прежнему без предупреждений.

**`Провести(Ссылка)` у менеджера уступает дорогу прикладной процедуре.** Если в
модуле менеджера объявлена `Процедура Провести(Ссылка)` — а объявить её могли
только в обход этого самого пробела, — вызывается она, а не встроенный метод.
Иначе новый метод молча подменил бы работающий обход. Сам встроенный метод
запускает только `ОбработкаПроведения`: `ОбработкаЗаписи` не вызывается, как и у
парного `ОтменитьПроведение`. Записать и провести за одну операцию по-прежнему
можно объектным путём `Ссылка.ПолучитьОбъект().Провести()`.

**Cookie корзины примера «Сайт» получила `Path` сервиса магазина**
([#1190](https://github.com/ivanarama/onebase/issues/1190)). Новая cookie
ставится с `Path=/hs/shop` и к кэшируемой витрине больше не ходит. Корзина,
набранная до обновления, у посетителя **сохраняется**: прежняя cookie была
выставлена с `Path=/` и по правилу совпадения пути (RFC 6265) продолжает
отправляться на `/hs/shop` — узкий путь новой cookie старую не отменяет. Для
таких посетителей до истечения `Max-Age` сохраняется и обход кэша витрины.
Заказы это не затрагивает.

## 📦 Установка

### Windows

1. Скачайте `onebase-windows-amd64.zip` (на Windows ARM —
   `onebase-windows-arm64.zip`)
2. Распакуйте в любую папку, например `C:\onebase\`
3. На amd64 запустите `onebase-gui.exe`

В arm64-архиве `onebase-gui.exe` нет: запустите `onebase.exe start`, лаунчер
откроется в браузере.

### Linux

```bash
tar xzf onebase-linux-amd64.tar.gz
./onebase-linux-amd64/onebase start
```

Для Raspberry Pi, ARM-мини-ПК и NAS используйте `onebase-linux-arm64.tar.gz`.

### macOS

```bash
tar xzf onebase-darwin-arm64.tar.gz
./onebase-darwin-arm64/onebase start
```

Для Intel Mac используйте `onebase-darwin-amd64.tar.gz`.

При обновлении установленной копии замените бинарь в `PATH`, затем проверьте:

```bash
onebase version
```

### Требования

- PostgreSQL 14+ нужен только для многопользовательского режима
- Для SQLite-режима дополнительных зависимостей нет
