# Заметки к версиям

Полные заметки выпущенных версий платформы. Краткая сводка со ссылками сюда —
в [`CHANGELOG.md`](../../CHANGELOG.md) в корне репозитория.

Имя файла — `release_vX.Y.Z.md` — не декоративное: по нему `release.yml` находит
тело релиза при публикации по тегу (шаг «Resolve release body»). Переименование
файла оставит релиз с дефолтным текстом вместо написанного.

Формат заметки — [`../release-template.md`](../release-template.md). Первая
строка обязана быть маркером `<!-- summary: … -->`: сайт onebase.site берёт из
него текст карточки релиза, а без маркера показывает «Автосборка…».

## Проверка полноты

При публикации тега `release.yml` запускает `tools/releasecheck`: он читает весь
first-parent диапазон от предыдущего стабильного тега и требует ссылку `#N` на
каждый вошедший PR. Проверка намеренно не ограничивает число коммитов и поэтому
ловит пропуск начала диапазона, как в `v0.10.2`.

Если PR осознанно не относится к содержимому заметки, исключение записывается в
ней поштучно и с причиной. Комментарий не виден в опубликованном Markdown:

```markdown
<!-- release-check: omit #1234 reason=этот PR подготовил саму заметку -->
```

Классы целиком (`docs`, `ci` и т. п.) не исключаются: один PR может одновременно
менять служебный гейт и пользовательское поведение. Локальная проверка перед
тегом:

```bash
go run ./tools/releasecheck -from v0.10.1 -to v0.10.2 \
  -notes docs/releases/release_v0.10.2.md
```

Заметок здесь 19 — по числу версий от `v0.5.0` до `v0.11.0`. Пять из них
(`v0.6.0`, `v0.7.0`, `v0.8.0`, `v0.8.1`, `v0.9.0`) до августа 2026 существовали
только как тела релизов на GitHub и восстановлены оттуда. Ранние версии
(`v0.2.0` — `v0.4.7`, апрель–май 2026) заметок в репозитории не имеют — они
остались на [странице Releases](https://github.com/ivanarama/onebase/releases).
