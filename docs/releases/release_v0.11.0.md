## 🎯 Главное

`v0.11.0` — минорный релиз после `v0.10.2`. Три возможности пришли прямо из
показов и обратной связи: бланк печатной формы теперь рисуют в Excel, а не
собирают в YAML; конструктор табличной части перестал обещать то, чего в
рантайме не было; пример «Сайт» научился принимать заказы.

Отдельно стоит прочитать раздел «Изменения поведения»: в DSL поменялось
сравнение незаполненного числа, и это затрагивает уже написанные модули.

## 🧾 Печатная форма из бланка Excel

Из обсуждения [#1109](https://github.com/ivanarama/onebase/issues/1109):
«собрать бланк простейшей накладной в редакторе макета — задача нетривиальная».
Половина решения в движке была всегда — `printforms/*.layout.yaml` понимает
`{{Номер}}`, `{{Дата | date}}`, `{{Склад.Наименование}}`, `{{@row}}`. Не хватало
удобного редактора бланка: объединения, ширины и границы дешевле расставить в
Excel. Excel и стал редактором
([#1124](https://github.com/ivanarama/onebase/issues/1124)).

- **Импорт `.xlsx` с тегами `{{…}}`** переносит объединения (colspan/rowspan),
  границы с толщиной, шрифты, заливку, выравнивание, ширины колонок и высоты
  строк, формат листа и поля в миллиметрах, картинки ячеек.
- **Строки табличной части выводятся из самих тегов**: ячейка со
  `{{Товары.Количество}}` делает свою строку repeat-областью по `Товары`, а
  внутри области приставка снимается до `{{Количество}}`. Нового языка разметки
  не заводится. Состав ТЧ берётся из метаданных документа — отличить колонку ТЧ
  от поля по ссылке (`{{Склад.Наименование}}`) по написанию невозможно, поэтому
  без метаданных разворот не делается вовсе и импорт говорит об этом вслух.
- **Разметка областей — по именам Excel** (Диспетчер имён), прямой аналог
  именованных областей табличного документа 1С. «Сквозные строки» листа
  становятся повтором шапки таблицы. Без явной разметки работает автоматика
  Шапка / ШапкаТаблицы / Строка / Подвал.
- **Что не перенеслось — говорится сразу.** Формулы (берётся вычисленное
  значение), условное форматирование, повороты текста, диагональные линии,
  лишние листы возвращаются списком предупреждений в баннере результата и в
  выводе команды. PDF рисует собственный рендерер и воспроизводит подмножество
  оформления — про это сказано заранее, а не обнаруживается после печати.
- **Точки входа:** кнопка «Из Excel» рядом с «Из PDF» — в тулбаре редактора
  макета и в блоке печатных форм сущности, либо команда:

  ```bash
  onebase printforms import --file бланк.xlsx --name ТоварнаяНакладная \
      --document РеализацияТоваров [--sheet Лист1]
  ```

Это ступень 1 из трёх плана `Plans/155-excel-print-template.md`; вывод печати в
`xlsx` и рантайм-режим `template:` описаны там же и в релиз не входят.

По дороге нашлись и починены две дыры, из-за которых пострадали бы и
существующие формы ([#1125](https://github.com/ivanarama/onebase/issues/1125)):
`{{Итог.<ТЧ>.<Поле>}}` **всегда давал 0**, а `| number:N` молча не применялся к
числовым полям — числа приходят из хранилища как `decimal.Decimal`, а
преобразование знало только `float64/int/string`. Поставляемый пример
`АктСписания` в `examples/trade` печатал «Итого: 0.00» при непустой табличной
части. Заодно у ячейки макета появилось поле `picture`: логотип в шапке
накладной декларативная форма не могла показать вообще, ни импортом, ни правкой
YAML руками.

## 📋 Табличная часть: состав колонок и события на колонке

Из обратной связи: «хотелось бы визуальный конструктор табличных частей — вывод
полей, которых надо, и событий на каждое поле». Конструктор форм есть, но по
обоим пунктам он обещал то, чего в рантайме не существовало: чекбоксы «Колонки
(показывать)» писали в форму детей `kind: Колонка`, а managed-форма всё равно
рисовала все реквизиты. Предпросмотр конструктора это признавал вслух — «в
рантайме иначе показываются все поля» (план 154).

- **Состав и порядок колонок.** Дети `kind: Колонка` задают, что показывать и в
  каком порядке. Ни одной колонки-ребёнка = все реквизиты, как раньше.
- **Событие на колонке.** `events: ПриИзменении` на `kind: Колонка` срабатывает
  на правку ячейки именно этой колонки, с обычным контекстом строки
  (`ИмяТабличнойЧасти`, `НомерСтроки`, `ТекущаяКолонка`, `ТекущаяСтрока`).
  Раньше обработчик был один на всю таблицу и колонку различали внутри него.
- **`auto_sum` и все шесть событий ТЧ** появились в панели свойств
  конструктора: `auto_sum` существует с #215.1 и используется в пяти примерах, а
  в панели его не было; из шести событий панель предлагала одно.

Конструктор заодно перестал показывать ТЧ без явных колонок как пустую: рантайм
считает «колонок не объявлено» = «показать все», а конструктор понимал это как
«не показывать ничего»
([#1123](https://github.com/ivanarama/onebase/issues/1123)).

## 🌐 Пример «Сайт»: корзина и заказ

Вопрос с показа: «а корзину почему не сделали?». Сделана — целиком на прикладном
слое, без правок движка (план 156).

- Кнопка **«В корзину»** в карточке товара, ссылка на корзину в шапке, страницы
  `/hs/shop/cart`, `/hs/shop/checkout`, `/hs/shop/order/<UUID>`.
- Документ **«Заказ с сайта»** с нумератором, справочник «Корзины», перечисление
  статусов, права у обеих ролей примера.
- На рабочем столе — счётчик новых заказов и список последних.
- Самопроверка `ТестМагазина` — 36 утверждений: цена берётся из базы, чужая
  корзина недоступна, границы количества, идемпотентность оформления, изоляция
  сайтов, переключатель приёма заказов.

**Приём заказов выключен по умолчанию** — это реквизит сайта «Принимать заказы с
сайта (корзина)». Сайт-визитка и витрина с корзиной живут в одной базе, и
обновление конфигурации не должно ставить кнопку «В корзину» там, где её не
ждали. Снятый флаг убирает кнопку и **закрывает адреса `/hs/shop`** (404), а не
просто прячет ссылку: адрес из закладки иначе продолжал бы принимать POST.
Демо-сайту флаг поднимает «Заполнить демо-контент сайта».

Оплаты, фискализации, резервирования остатков и регистрации с паролем нет
намеренно: это витрина плюс заказ, а не магазин из коробки. Личный кабинет с
паролем упирается в то, чего в движке пока нет — сессии посетителя и хэш-функций
в DSL.

## 🖥 Интерфейс

- **Левая панель объектов схлопывается на широком экране**
  ([#1122](https://github.com/ivanarama/onebase/issues/1122)). Кнопка-гамбургер
  была заперта в мобильном медиазапросе, а класс, который она ставит, на широком
  экране не был адресован ни одним правилом CSS — переключатель существовал, но
  не значил ничего. Состояние запоминается в браузере и переживает переход на
  другую страницу. Полное скрытие, а не узкая полоса с иконками: у пунктов меню
  объектов иконок нет, полоса была бы столбиком безымянных заглушек.
- **Белорусский язык интерфейса** (`be`) — двенадцатая локаль.

## 🧠 DSL

- **Незаполненное число сравнивается с нулём**
  ([#1136](https://github.com/ivanarama/onebase/issues/1136)) — подробности в
  разделе «Изменения поведения» ниже.
- **`ТипЗнч()` и `Тип()` понимают объекты конфигурации**
  ([#1137](https://github.com/ivanarama/onebase/issues/1137)). Раньше `ТипЗнч()`
  знал семь примитивов и три коллекции, а всё остальное отдавал Go-именем типа:
  ссылка на документ приходила как `*interpreter.Ref`, объект — как
  `*runtime.Object`. Проверка вида «документ-основание такого-то типа» в
  `ОбработкаЗаполнения` была **всегда Ложь**, и обойти это было нечем.

  | Значение | было | стало |
  |---|---|---|
  | объект документа | `*runtime.Object` | `Документ.РеализацияТоваров` |
  | ссылка на документ | `*interpreter.Ref` | `ДокументСсылка.РеализацияТоваров` |
  | объект справочника | `*runtime.Object` | `Справочник.Номенклатура` |
  | ссылка на справочник | `*interpreter.Ref` | `СправочникСсылка.Номенклатура` |

  `Тип()` принимает и 1С-написание `ДокументОбъект.X` / `СправочникОбъект.X`.
  Известная граница: регистр имени объекта значим — `Тип("документ.ЗаказПокупателя")`
  работает, `Тип("Документ.заказпокупателя")` нет.

## 📚 Документация

- `docs/dsl-reference.md`: **ссылка в запросе — это представление, а не
  идентификатор** ([#1131](https://github.com/ivanarama/onebase/issues/1131)).
  `Строка(Ссылка)` даёт наименование; идентификатор берётся как
  `Стр.Товар.УникальныйИдентификатор()`, а в запросе — разыменованием через
  точку (`Заказ.Ссылка КАК ИдЗаказа`). Ошибка стоила двух заходов при разработке
  корзины, поэтому описана явно.
- `AGENTS.md` (`onebase ai-guide`): разделы о событиях управляемых форм и о
  семантике пустых значений ([#1135](https://github.com/ivanarama/onebase/issues/1135)).
- `docs/self-update.md`: источник обновлений — GitHub-репозиторий, а не сервер
  разработчика.

## ⚠️ Изменения поведения

**Незаполненное число в сравнении считается нулём**
([#1136](https://github.com/ivanarama/onebase/issues/1136)). Пустая ячейка числа
доезжает до модуля как `Неопределено` (в базе NULL) и раньше сравнивалась
строково: `Цена = 0` давала Ложь, а `Цена > 0` и даже `Цена > 5` — Истину.
Теперь в операторах `=`, `<>`, `<`, `>`, `<=`, `>=` незаполненное число ведёт
себя как ноль, то есть идиома 1С `Если Стр.Цена = 0` работает.

- Модуль, полагавшийся на `Цена > 0` как на признак «цена введена», получит Ложь
  вместо Истины — это и есть починка.
- Цена решения: `Неопределено = 0` теперь Истина, поэтому признак «не найдено» у
  `Найти`/`Получить` больше нельзя проверять сравнением — ни с нулём, ни с
  `Неопределено`; для этого есть `ТипЗнч`.
- То же правило действует в утверждениях `Утверждать.Равно`/`НеРавно` и
  `Утверждать.МаскаПоля` — самопроверки конфигурации намеренно видят то же, что
  и модуль. Поэтому `Утверждать.НеРавно(Инд, 0)` как проверка «нашлось» после
  обновления начнёт падать, а `Утверждать.Равно(Ф(), 0)` пройдёт независимо от
  того, вернула функция ноль или `Неопределено`.
- Поиск и сортировка коллекций (`Массив.Найти`, `ТаблицаЗначений.НайтиСтроки`) и
  ключи `Соответствия` не изменились: там «нет значения» по-прежнему отличается
  от нуля, и отбор незаполненных строк работает как раньше.

**`ТипЗнч()` возвращает другие строки.** Модуль, сравнивавший результат с
Go-именем (`"*interpreter.Ref"`, `"*runtime.Object"`), перестанет находить
совпадение. Такой код мог существовать только как обходной путь и по сути был
сломан: сравнение с осмысленным именем типа до этого релиза всегда давало Ложь.
Объект и ссылка — разные типы: `ТипЗнч(ДанныеЗаполнения) = Тип("ДокументСсылка.X")`
по-прежнему Ложь, потому что хук получает объект. Рабочих написаний два:
`Тип("Документ.X")` для объекта либо `ТипЗнч(ДанныеЗаполнения.Ссылка) = Тип("ДокументСсылка.X")`.

**Колонки табличной части.** Форма без детей `kind: Колонка` показывает все
реквизиты — как раньше. Но форма, у которой такие дети уже были прописаны
(конструктором или импортом из 1С), до этого релиза их игнорировала, а теперь
покажет **только перечисленные колонки**. Скрытая колонка при этом не
выбрасывается из записи: она остаётся в полезной нагрузке и продолжает
сохраняться — «просто не рисовать» её означало бы затирать реквизит при каждой
записи, молча и во всех строках сразу.

**Обработчик колонки не отменяет обработчик таблицы.** Если объявлены оба, они
выполняются последовательно: колонка → `ПриИзменении` таблицы. Иначе добавление
события на колонку молча гасило бы уже работающий обработчик ТЧ.

**Приём заказов у примера «Сайт» выключен по умолчанию** — обновление
конфигурации не включает корзину само.

## 📦 Установка

### Windows

1. Скачайте `onebase-windows-amd64.zip` (на Windows ARM —
   `onebase-windows-arm64.zip`)
2. Распакуйте в любую папку, например `C:\onebase\`
3. На amd64 запустите `onebase-gui.exe`

В arm64-архиве `onebase-gui.exe` нет: запустите `onebase.exe start`, лаунчер
откроется в браузере.

### Linux

```bash
tar xzf onebase-linux-amd64.tar.gz
./onebase-linux-amd64/onebase start
```

Для Raspberry Pi, ARM-мини-ПК и NAS используйте `onebase-linux-arm64.tar.gz`.

### macOS

```bash
tar xzf onebase-darwin-arm64.tar.gz
./onebase-darwin-arm64/onebase start
```

Для Intel Mac используйте `onebase-darwin-amd64.tar.gz`.

При обновлении установленной копии замените бинарь в `PATH`, затем проверьте:

```bash
onebase version
```

### Требования

- PostgreSQL 14+ нужен только для многопользовательского режима
- Для SQLite-режима дополнительных зависимостей нет
