## Что нового

`v0.9.7` делает многопользовательскую работу заметно живее: списки могут
автоматически обновляться после изменений, а серверные обработки — показывать
пользователю оповещения, открывать формы и запрашивать обновление списка. Сигналы
живого списка адресуются с учётом RLS, поэтому пользователь получает обновления
только для доступных ему данных. Релиз также закрывает гонку FIFO-списания между
несколькими серверами и исправляет ряд проблем запросов, DSL, конфигуратора и
первоначальной настройки пользователей.

## Новое

- **Живые списки** — `notify_changes` и `list_refresh_on` включают обновление
  списка без F5 после записи, проведения, удаления и пометки на удаление.
- **RLS-адресация обновлений** — сигнал получают только онлайн-пользователи,
  которым строка доступна до или после изменения; при ошибке проверки прав
  доставка закрывается безопасно.
- **Оповещения пользователю** —
  `ПоказатьОповещениеПользователя()`/`ShowUserNotification()` показывает обычный
  или важный тост и может открыть связанную форму по клику.
- **Команды интерфейсу** — события `ui.обновитьСписок` и `ui.открытьФорму`
  позволяют серверной обработке перечитать список или открыть объект во вкладке.
- **Гибкий формат чисел в отчётах** — знак `#` после десятичного разделителя
  задаёт необязательные разряды: формат `#,##0.00####` показывает от двух до
  шести знаков без лишних хвостовых нулей.

## Надёжность и исправления

- Блокировка `Заблокировать()` теперь берёт PostgreSQL advisory lock до чтения
  остатков внутри проведения. Конкурентное FIFO-списание из разных процессов
  сериализуется и больше не списывает одну партию дважды.
- Параметры дат в SQLite-запросах нормализуются в формат хранения, включая
  сравнения и `МЕЖДУ` в часовых поясах, отличных от UTC.
- Конфигуратор в database-режиме снова читает сохранённые формы, сохраняет
  состав подсистем и атомарно удаляет объекты вместе с формами, макетами и
  модулями.
- Readonly-ссылки в управляемых формах больше нельзя изменить через кнопки
  выбора или открытия карточки.
- Платформенная функция аудита больше не перехватывает одноимённую прикладную
  процедуру конфигурации.
- `ПриЗаписи` документа, вызванная из DSL, получает заполненную
  `ЭтотОбъект.Ссылка`; сообщения `ПриЗаписи` и `ОбработкаПроведения` возвращаются
  из обработчиков пользователю.
- Результаты запросов публикуют системный `id` под зарезервированными именами
  `Ссылка`, `Reference` и `Ref`, не перезаписывая явные одноимённые поля.
- Пользовательские ошибки DSL в UI и REST показываются без внутреннего пути к
  `.os`-файлу и номера строки; диагностический контекст остаётся в логах и
  инструментах разработчика.
- Первый пользователь базы обязан быть администратором; формы создания заранее
  предупреждают об этом и включают соответствующий флаг.
- Уведомления из DSL корректно передают поля `Структуры` и `Соответствия`, в том
  числе данные телефонии и ссылки для открытия формы.
- Обновлена зависимость `excelize`, закрывающая достижимую уязвимость; CI
  проверяет примеры, интеграционные сценарии PostgreSQL и известные уязвимости.

## Важные изменения поведения

> [!IMPORTANT]
> Включение авторизации начинается с создания администратора. Первую запись в
> `_users` без флага администратора платформа отклонит, чтобы не заблокировать
> доступ к управлению пользователями.

- Живое обновление списков не включается автоматически для всех сущностей.
  Укажите `notify_changes: true` у источника изменений и события в
  `list_refresh_on` у списка.
- Скрытая вкладка не перечитывает данные в фоне: она запоминает изменение и
  обновляется после возврата пользователя. Несколько близких событий
  объединяются debounce-механизмом.
- Для межпроцессной блокировки проведения нужен PostgreSQL. SQLite, как и
  раньше, сериализует транзакции одним соединением.

## Установка

### Windows
1. Скачайте `onebase-windows-amd64.zip` и файл
   `onebase-windows-amd64.zip.sha256`
2. Проверьте контрольную сумму и распакуйте архив, например в `C:\onebase\`
3. Запустите `onebase-gui.exe`

### Linux
```bash
tar xzf onebase-linux-amd64.tar.gz
./onebase-linux-amd64/onebase start
```

### macOS
```bash
tar xzf onebase-darwin-amd64.tar.gz
./onebase-darwin-amd64/onebase start
```

### Offline-обновление
```bash
onebase update --from D:\flash\onebase-windows-amd64.zip --sha256 <ожидаемый-hex> --id <база>
```
