## 🎯 Главное

`v0.10.2` — патч-релиз после `v0.10.1`. Главное в нём — механизм, которого не
было вовсе: реквизит может объявить значение по умолчанию, а объект — хук
`ПриСозданииНового`. Остальное собрано по следам живой эксплуатации и показов:
запуск обработки перестал выглядеть как «ничего не произошло», Конфигуратор
больше не подменяет типы полей при сохранении, неполная миграция чинится за один
проход, а пример «Сайт» стал похож на витрину магазина.

## ✨ Значения по умолчанию у реквизитов

Повод — вопрос с внедрения: «в конфигурации одна организация, почему её не
подставляют в новый документ?». Механизма не существовало: у реквизита не было
ключа `default`, хук «при создании нового» не вызывался ниоткуда, а единственная
подстановка (дата документа, признак активности) была зашита в обработчик формы
и не видна никакому другому пути
([#1101](https://github.com/ivanarama/onebase/pull/1101)).

- **`default:` у реквизита** с закрытым списком источников: литерал,
  `сегодня`/`сейчас`, `константа.<Имя>`, `текущийпользователь`, `единственный`.
- **Хук `ПриСозданииНового(Объект)`** в модуле объекта. Порядок применения:
  `default` → хук → `ОбработкаЗаполнения`/копирование; хук перебивает умолчание,
  а уже заданное значение не перетирается никогда.
- **Одна точка применения на все пути создания** — форма, `Документы.X.Создать()`,
  `Справочники.X.Создать()` и REST. Раньше подстановка была только у формы.
- **Ошибка приходит на `onebase check`, а не в рантайме**: проверяются
  совместимость с типом реквизита, существование константы и значения
  перечисления. Частая опечатка `константы.X` вместо `константа.X` отвергается
  отдельно — иначе она прошла бы как литерал и молча не сработала.
- `единственный` подставляет элемент, только если он в самом деле один: не
  помечен на удаление, не группа, активен и виден пользователю по строковым
  политикам.

## 🧾 Формы и интерфейс

- **Запуск обработки виден.** Кнопка выключается с подписью «Выполняется…» и
  индикатором, повторный запуск той же работы поверх первой закрыт. Повод —
  показ, где человек нажал «Выполнить», минуту не видел никакой реакции, нажал
  второй раз и получил ошибку про ключ командной строки, стоя перед формой в
  браузере. У параметра обработки появился `required`: поле помечено звёздочкой,
  а сервер проверяет то же самое до запуска
  ([#1111](https://github.com/ivanarama/onebase/pull/1111)).
- **F5 в режиме вкладок возвращает на ту же вкладку**, а не на первую: активная
  вкладка запоминается отдельно от их списка
  ([#1107](https://github.com/ivanarama/onebase/pull/1107)).

## 🛠 Конфигуратор

- **Список типов перестал терять то, чего сам не предлагает.** Тип, лежащий в
  конфигурации, всегда присутствует в списке отдельным пунктом и остаётся
  выбранным, поэтому сохранение реквизитов больше не подменяет его соседним
  значением. Заодно в списке появились «картинка» и «форматированный текст» —
  раньше такое поле заводилось только правкой YAML руками
  ([#1099](https://github.com/ivanarama/onebase/pull/1099)).
- **Перечисление у поля регистра выбирается, а не только хранится.** Пункт
  «перечисление →» появился у измерений, ресурсов и реквизитов регистров
  накопления и сведений. Заодно отклоняется поле со ссылочным типом без
  выбранного объекта — раньше в файл уходил несуществующий тип `reference` или
  `enum` без имени ([#1103](https://github.com/ivanarama/onebase/pull/1103)).
- **Правка из Конфигуратора не оставляет конфигурацию незагружаемой**
  ([#1100](https://github.com/ivanarama/onebase/pull/1100)).

## 🚀 Запуск и миграция

- **Гейт уникальности кода не оставляет схему на полпути.** Раньше `Migrate`
  выходил на первом же объекте, не прошедшем преконтроль, и ни одна таблица за
  ним схему не получала: `onebase renumber` не мог прочитать отставшие объекты,
  и лечение шло кругами «дозаполнили → перезапустили → догнали → дозаполнили».
  Теперь отказы копятся, схема доводится до конца по всем объектам, а ошибка
  возвращается один раз и сразу со всеми виновниками
  ([#1112](https://github.com/ivanarama/onebase/pull/1112)).
- Кнопка «Дозаполнить коды» работает и на половинчатой миграции
  ([#1106](https://github.com/ivanarama/onebase/pull/1106)).
- Ошибка разбора `app.yaml` называет время изменения файла — видно, свежую ли
  правку не удалось прочитать
  ([#1102](https://github.com/ivanarama/onebase/pull/1102)).

## 🌐 Пример «Сайт»

- **Демо-сайт выглядит магазином, а не отладочной страницей**: белая шапка с
  меню и поиском, витрина карточками с картинками и ценой, карточка товара в две
  колонки ([#1110](https://github.com/ivanarama/onebase/pull/1110)).
- **Главная стала витриной**: под текстом страницы идут разделы каталога и
  свежие новости. У раздела появились обложка — от первой опубликованной позиции
  внутри — и счётчик позиций вместо подписи «Раздел каталога»
  ([#1114](https://github.com/ivanarama/onebase/pull/1114)).
- База со старым макетом получает новый CSS раньше, чем новую разметку, поэтому
  прежние классы приведены к тому же виду: между двумя обновлениями сайт не
  выглядит хуже, чем до них
  ([#1113](https://github.com/ivanarama/onebase/pull/1113)).
- Импорт каталога больше не приезжает без картинок и не завышает отчёт; сайт
  отвечает по всем своим адресам, и полная база не выглядит пустой
  ([#1104](https://github.com/ivanarama/onebase/pull/1104),
  [#1097](https://github.com/ivanarama/onebase/pull/1097)).

## ⚠️ Изменения поведения

- **`default:` — опт-ин.** Реквизит без этого ключа ведёт себя как прежде.
- **Умолчания формы ввода остались только у формы.** Дата документа и
  `Активный = true` подставляются при открытии формы, но не в `Создать()` и не в
  REST — распространить их на программные пути значило бы молча изменить
  поведение всех существующих конфигураций. Конфигурации, которой дата нужна и
  в программном пути, достаточно написать `default: сейчас`.
- **`default` в табличной части отвергается на `onebase check`** с объяснением:
  строка ТЧ добавляется из трёх разных мест, общей точки у них нет, и принять
  ключ, не применяя его, значило бы вернуть тот самый молчаливый отказ.
- **Миграция при непройденном преконтроле по-прежнему неуспешна, база не
  стартует.** Изменилось одно: схема доводится до конца по всем объектам, и один
  прогон `onebase renumber` теперь видит все проблемные объекты сразу, а не по
  одному за перезапуск.
- **Демо-контент сайта обновляется при повторном «Заполнить демо-контент
  сайта»** — но только если тексты страниц не правили руками: содержимое
  сверяется с тем, что клали прежние сборки, любое отличие считается правкой
  человека и сохраняется.

## 📦 Установка

### Windows

1. Скачайте `onebase-windows-amd64.zip` (на Windows ARM —
   `onebase-windows-arm64.zip`)
2. Распакуйте в любую папку, например `C:\onebase\`
3. На amd64 запустите `onebase-gui.exe`

В arm64-архиве `onebase-gui.exe` нет: запустите `onebase.exe start`, лаунчер
откроется в браузере.

### Linux

```bash
tar xzf onebase-linux-amd64.tar.gz
./onebase-linux-amd64/onebase start
```

Для Raspberry Pi, ARM-мини-ПК и NAS используйте
`onebase-linux-arm64.tar.gz`.

### macOS

```bash
tar xzf onebase-darwin-arm64.tar.gz
./onebase-darwin-arm64/onebase start
```

Для Intel Mac используйте `onebase-darwin-amd64.tar.gz`.

При обновлении установленной копии замените бинарь в `PATH`, затем проверьте:

```bash
onebase version
```

### Требования

- PostgreSQL 14+ нужен только для многопользовательского режима
- Для SQLite-режима дополнительных зависимостей нет
