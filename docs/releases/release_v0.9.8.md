## Что нового

`v0.9.8` — релиз про инженерную зрелость платформы. Конфигурацию теперь можно
тестировать штатно: `onebase test` даёт дискавери тестов, изоляцию данных,
подменяемые часы, моки внешних эффектов и машиночитаемый отчёт для CI. Картинки
и вложения умеют жить в S3-совместимом хранилище, регистр бухгалтерии получил
предрасчёт итогов, а горячий путь HTTP переработан под организацию со 100+
активными пользователями.

Отдельная часть релиза не видна в интерфейсе, но заметна в надёжности: в CI
включены `errcheck` и `gosec` как блокирующие линтеры. Их разбор — 968 и 1522
находки — нашёл настоящие дефекты: обход пути в конфигураторе, пароль от
PostgreSQL в реестре баз с правами `0644`, неполные резервные копии, которые
отдавались с кодом «успех», и fail-open в проверке прав.

## Новое

- **Тесты уровня конфигурации** — команда `onebase test`: дискавери обработок
  `kind: test`, встроенный `Утверждать`, транзакционная изоляция каждого теста по
  умолчанию (`--isolation schema` — эфемерная схема PostgreSQL), тест-профиль с
  моками `Мок.Email/Http/ОС/ИИ` и подменяемыми часами `Часы.Установить`, вывод
  `--format pretty|tap|junit --out <файл>` для CI.
- **Ассерты прав прямо в тестах** — `Утверждать.РольМожет/РольНеМожет` проверяет
  матрицу ролей, `ПолеМаскируется/МаскаПоля` — маскирование ПДн,
  `СтрокиОграничены` — применение RLS-фильтра. Ассерты гоняют тот же код, что и
  боевой enforcement, а не его копию.
- **Управление пользователями из CLI** — `onebase user add/list/passwd/rm` и
  `user role assign|revoke` без веб-админки: сгенерированные, демо- и тестовые
  базы больше не требуют ручного заведения пользователя. Плюс
  `user add --show-in-list` и подкоманда `user show-in-list`.
- **S3-совместимое хранилище** — картинки (`image`) и вложения к
  документам/справочникам можно держать в S3 (AWS S3, MinIO, Ceph RGW, B2,
  Wasabi) третьим режимом рядом с «на диске» и «в базе». Клиент встроенный, без
  внешних зависимостей; раздача идёт через приложение, поэтому проверка прав и
  защита от IDOR сохраняются. Опция `stream: true` включает раздачу Range-потоком
  без копирования файла на диск.
- **Off-site автобэкап в S3** — резервная копия по расписанию уезжает в бакет,
  а не только на локальный диск.
- **Итоги регистра бухгалтерии** — предрасчёт остатков (план 80 распространён с
  регистров накопления на `акк_*`): итоги двигаются инкрементально в той же
  транзакции, что и проводки, `Остатки()`, `Остатки(&Момент)` и обороты читаются
  из предрасчёта вместо скана всей истории. Включается флагом `totals:` у
  регистра; полный пересчёт — `onebase recalc-totals`.
- **Команды и пикеры управляемой формы без ручной разметки** — форма сама рисует
  кнопки команд и пикеры реквизитов формы; валидатор (`W014`/`W015`)
  предупреждает о командах и пикерах, которые не будут работать.
- **Заголовок вкладки и карточки — представление записи**, а не имя сущности.
- **Своя подпись кнопки «Провести»** — `post_caption` у документа.

## Быстрее

Ревью масштабируемости на 100+ активных пользователей (план 111) закрыто по
всем найденным местам горячего пути:

- **Пул PostgreSQL** — вменяемый дефолт (20 соединений вместо `max(4, NumCPU)`
  от pgx) и настройка в `app.yaml`: секция `db:` с `pool_max_conns` /
  `pool_min_conns`. Явные `pool_*` в DSN по-прежнему уважаются.
- **Авторизация без трёх round-trip'ов на запрос** — кэш `HasUsers` и ролей на
  горячем пути миддлвары.
- **Списки и регистры без N+1** — ссылки разворачиваются батчем
  (`GetFieldsByIDs`) вместо `GetByID` в цикле.
- **Встроенная статика вынесена из-под auth-миддлвары** — Monaco, ECharts,
  SlickGrid и Quill больше не проходят проверку прав на каждый файл.
- **Выгрузка списка в Excel потоком** — XLSX пишется на ходу, а не собирается
  целиком в памяти.
- **Метрики без глобального мьютекса** — атомарные серии на горячем пути.
- **SSE за реверс-прокси** — опциональный h2c к апстриму снимает лимит браузера
  «6 соединений на origin»; настройка описана в `docs/reverse-proxy.md`.

## Надёжность и исправления

- Деньги бухотчётности считаются в `decimal`, а не `float64`. На PostgreSQL
  точность `NUMERIC` терялась уже на стороне Go, и округление осело бы в базе
  навсегда — из этих остатков строятся опорные проводки свёртки.
- Свёртка базы пересчитывает итоги регистров в той же транзакции. Раньше
  свёрнутые движения удалялись мимо механизма итогов, и быстрый путь запроса
  отдавал задвоенные остатки, хотя сами регистры сворачивались верно.
- Веб-хуки срабатывают на DSL-пути записи документов: документ, записанный
  обработкой, HTTP-сервисом или регламентным заданием, теперь порождает события
  `document.save/post/unpost` — интеграции их больше не пропускают.
- `onebase check` предупреждает о формах, которые платформа не загружает
  (`form.not-loaded`). Проверка нашла 15 из 24 файлов форм в самой поставке:
  весь `examples/trade` и `examples/finance` лежали не в
  `forms/<сущность>/`, то есть годами не рендерились.
- Реквизиты формы доходят до обработчиков и возвращаются в форму; пикер
  реквизита не рисуется без загруженных опций; опции поля сущности не
  подменяются, команды автопанели не глушатся.
- REST отдаёт `422` «ссылка на несуществующий объект» вместо `500` с сырым
  текстом драйвера. Ошибка классифицируется по коду (SQLite 787, PostgreSQL
  23503), а не по тексту сообщения.
- Локальный вызов в `.proc.os` резолвится по файлу вызова: межмодульный вызов в
  аргументе больше не приводит к `unknown function`.
- Строковый доступ (RLS) получил strict-чокпоинт в `store.List`.
- `report/widget explain --sample` получает диалект БД; `user` не теряет пароль
  при сбое `--show-in-list`.
- Разбор `errcheck` закрыл целый класс тихих сбоев: проверка прав, работавшая
  fail-open при ошибке чтения текущих ролей; ложные записи в аудите;
  восстановление поверх базы, которая не остановилась; резервные копии без
  каталога `config/`, отдаваемые с HTTP 200; усечённый блоб, зарегистрированный
  как целый файл; сироты в табличных частях; `{"ok":true}` без сохранения.
- Разбор `gosec` закрыл обход пути при сохранении формы сущности и перечисления
  (проверки имени не было в семи обработчиках из двенадцати), права `0644` на
  реестре баз со строкой подключения к PostgreSQL и отсутствие предела размера
  тела в 68 обработчиках форм.

## Важные изменения поведения

> [!IMPORTANT]
> Дефолт пула PostgreSQL изменился: теперь 20 соединений на процесс базы вместо
> `max(4, NumCPU)`. Если PostgreSQL обслуживает много баз OneBase на одном
> сервере, проверьте `max_connections` или задайте `db.pool_max_conns` в
> `config/app.yaml`.

- Итоги регистра бухгалтерии не включаются сами: нужен блок
  `totals: { enabled: true }` у регистра и `onebase migrate`. Для существующей
  базы итоги наполнятся при миграции.
- `onebase check` начал выдавать предупреждение `form.not-loaded`. Оно **не
  блокирует** проверку, но означает, что форма не рендерится: перенесите файл в
  `forms/<имя-сущности-в-нижнем-регистре>/`. Имя берётся из поля `name` в YAML
  сущности, а не из имени файла.
- Для контрибьюторов: `errcheck` и `gosec` теперь блокируют merge. Полный
  прогон `golangci-lint` на всём коде даёт `0 issues` — новые находки придётся
  разбирать, а не откладывать. Права файлов задаются константами
  `internal/fsmode`, а не литералами.

## Установка

### Windows
1. Скачайте `onebase-windows-amd64.zip` и файл
   `onebase-windows-amd64.zip.sha256`
2. Проверьте контрольную сумму и распакуйте архив, например в `C:\onebase\`
3. Запустите `onebase-gui.exe`

### Linux
```bash
tar xzf onebase-linux-amd64.tar.gz
./onebase-linux-amd64/onebase start
```

### macOS
```bash
tar xzf onebase-darwin-amd64.tar.gz
./onebase-darwin-amd64/onebase start
```

### Offline-обновление
```bash
onebase update --from D:\flash\onebase-windows-amd64.zip --sha256 <ожидаемый-hex> --id <база>
```
