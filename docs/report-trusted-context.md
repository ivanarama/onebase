# Доверенный контекст штатного отчёта (П7)

Параметр с `context` задаётся сервером из текущей аутентифицированной сессии.
Значения GET/POST/REST, export URL и сохранённых настроек не используются для
таких параметров. В форме, ссылках выгрузки и списке входных параметров OpenAPI
они отсутствуют. Без контекста существующие отчёты работают как раньше.

```yaml
name: МоиЗадачиПодразделения
params:
  - name: Actor
    type: string
    context: {user: login}
  - name: ActorID
    type: reference:_users
    context: {user: id}
  - name: Unit
    type: reference:Подразделения
    context:
      user_card:
        catalog: Сотрудники
        account_field: УчетнаяЗапись
        field: Подразделение
query: |
  ВЫБРАТЬ Наименование ИЗ Справочник.Задачи
  ГДЕ Исполнитель = &ActorID И Подразделение = &Unit
```

`user: login` требует `type: string`; `user: id` допускает `string` либо
`reference:_users`. ID — UUID учётной записи, а не ссылка произвольного
прикладного справочника. Для ссылки прикладного пользователя или подразделения
объявляется `user_card`: `account_field` обязан быть `reference:_users`,
`field` — обычным скалярным реквизитом совпадающего типа. Табличные части и наборы
для П7 пока не поддерживаются. Краткая форма `user_card: Сотрудники.Подразделение`
допустима, если в справочнике ровно один реквизит `reference:_users`.

Используется существующий инфраструктурный reader карточки: ровно одна
непомеченная на удаление карточка, связанная с **серверным UUID** учётной записи.
Отсутствующая, неоднозначная или пустая карточка, ошибка reader и отсутствие
аутентифицированного пользователя останавливают построение/выгрузку. Клиентское
значение и `default` не служат запасным вариантом. `default`, `options` и
`period_end` вместе с `context` запрещены; ошибку конфигурации показывает check.
Этот узкий reader не открывает пользователю произвольный просмотр справочника.

Контекст разрешается для запуска UI, REST v2, Excel/PDF и фонового экспорта.
Фоновая выгрузка сохраняет request actor и повторно читает карточку при выполнении.
Внешним загруженным отчётам `_ext_reports` инфраструктурный контекст недоступен:
описание источника относится к доверенной конфигурации. Сами источники запроса
по-прежнему проходят RBAC/RLS и маскирование полей; контекст не даёт новых прав.

Наличие ключа не добавляет отбор автоматически: автор штатного запроса должен
использовать `&Actor` / `&Unit` в нужном условии. Обычные пользовательские отборы
не заменяют серверный контекст. Ручной запуск без actor должен явно получить
аутентифицированный серверный контекст, иначе отчёт закрывается отказом.
