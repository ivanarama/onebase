# Условная видимость и дневные умолчания параметров отчёта

Ссылки на другой булев параметр задаются в `visible_when`. Это настройка
показа: скрытое поле сохраняет своё значение, участвует в отправке и серверной
типизации. Условия запроса определяются сервером, а не состоянием DOM.

```yaml
params:
  - name: ПоЧасам
    type: bool
  - name: Начало
    type: date
    default: "{{today}}"
    visible_when: {param: ПоЧасам, equals: false}
  - name: Конец
    type: date
    default: "{{today}}"
    period_end: true
    visible_when: {param: ПоЧасам, equals: false}
  - name: НачалоВремя
    type: datetime
    default: "{{today | start_of_day}}"
    visible_when: {param: ПоЧасам, equals: true}
  - name: КонецВремя
    type: datetime
    default: "{{today | end_of_day}}"
    visible_when: {param: ПоЧасам, equals: true}
```

Переключение флажка сохраняет обе независимые пары; оно не формирует отчёт
автоматически. Запрос/модуль отчёта по типизированному `ПоЧасам` выбирает
единственную активную пару для вычислений. `visible_when` не является
серверным разрешением на чтение или заменой этому выбору.

`param` должен ссылаться на другой единственный параметр типа `bool`,
`equals` указывается явно и имеет тип bool. Неизвестный источник, другой тип,
самоссылка и отсутствие `equals` блокируют обычный `onebase check`.
Конфигуратор сохраняет условие по имени параметра при редактировании формы.

`start_of_day`/`end_of_day` — преобразования шаблона умолчания, аналогичные
существующим `start_of_month`/`end_of_month`. Они сохраняют календарную дату и
часовой пояс исходного момента и задают 00:00:00/23:59:59. Это не обработка
введённого времени. `period_end` по-прежнему относится только к `date`.

Первый показ формы раскрывает оба умолчания. Существующее различие «ключа нет»
и «ключ явно очищен» сохраняется: последующее формирование, экспорт/фон и API
не подменяют переданное время или пустое значение умолчанием. При прямом
запросе без ключа применяется прежний контракт отсутствующего параметра.
Переименование часового пояса при хранении/выгрузке не должно менять момент.

Новые фильтры не вводят цепочку преобразований: несколько календарных шагов
остаются отдельной возможностью. Составные календарные defaults не следует
заменять на today только ради обхода отсутствующей поддержки.
