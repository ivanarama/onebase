# Пользовательская справка конфигурации

Руководство принадлежит конфигурации и хранится в `docs/help/`: оглавление
`index.yaml`, статьи Markdown и иллюстрации. Оно открывается через меню
«Система → Руководство пользователя», а из формы — кнопкой «Справка», если
для неё или объекта указана статья. Кнопка доступна и в управляемой, и в
автоматической форме, включая формы во вкладках и окнах выбора.

## Начать

`onebase init <каталог>` создаёт каркас и инструкции для ИИ в `AGENTS.md`.
Для существующей конфигурации:

```sh
onebase docs init --project ./my-config
onebase ai-guide --project ./my-config --output ./my-config/AGENTS.md
```

`docs init` сохраняет существующие статьи и оглавление. Перед заменой старого
`AGENTS.md` перенесите свои правила в отдельный проектный файл с указателем
на него. Генератор `ai-guide` заменяет файл, указанный в `--output`.

Агент дополняет руководство в той же задаче, в которой меняет поведение.
Это инструкция для агента, а не фоновый генератор: сама платформа не вызывает
LLM при записи документа, открытии справки или запуске приложения. Результат
проверяется вместе с кодом; наличие статьи не доказывает её правильность.

## Оглавление и связи

```yaml
title: Руководство колл-центра
enabled: true
auto_update: true
chapters:
  - id: operator
    title: Работа оператора
    file: operator.md
  - id: calls
    title: Работа со звонками
    file: operator/calls.md
    parent: operator
    objects: [document/А_Звонок]
    forms: [document/А_Звонок/объекта]
```

`id` постоянный: латиница, цифры, дефис и подчёркивание. `file` — путь
относительно `docs/help/`. `parent` ссылается на предыдущую главу: это задаёт
иерархию без циклов. Порядок — как в списке. `objects` используют `kind/name`
(`document/`, `catalog/`, `processor/`), `forms` — `kind/name/form-name`.
Связи регистронезависимые; точная связь формы имеет приоритет над объектом.
Кнопка выводится в формах документов, справочников и управляемых обработок.
Дублирующиеся связи разрешаются по порядку глав — первая подходящая.

Главы описывают назначение, действия и результат, условия доступности,
ошибки и ограничения. Ссылки на статьи и изображения относительные к статье:

```markdown
[Работа оператора](../operator.md)
![Новый звонок](../images/call-new.png)
```

Поддерживаются Markdown-таблицы, списки, код и заголовки. HTML из статей
не исполняется. Иллюстрации — локальные PNG, JPEG, GIF, WebP; удалённые
изображения и произвольные файлы не публикуются. Загружаются только картинки,
на которые есть ссылки. Лимиты: статья 2 MiB, картинка 8 MiB, картинки книги
в сумме 64 MiB. Ссылки через симлинки не могут выйти за каталог конфигурации.

## Отключение и диагностика

- `enabled: false` отключает просмотр, экспорт и публикацию руководства.
- `auto_update: false` оставляет справку доступной, но просит агента её не вести.
- Отсутствие `docs/help/` нормально для существующих конфигураций.
- Ошибки справки — предупреждения, не ошибки запуска или `onebase check`.

```sh
onebase docs check --project ./my-config --json
```

Отчёт содержит состояние, число доступных глав и предупреждения. Команда
не отказывает из-за плохой статьи или оглавления. Явно вызванные `export`,
`capture` и `publish` сообщают ошибки своей операции обычным ненулевым кодом;
они не вызываются автоматически из сборки или проверки конфигурации.

## Скриншоты

Необязательная команда требует Node.js, пакет `playwright` и установленный
Chromium. Устанавливайте браузерные инструменты вне исходников конфигурации:
обычная загрузка конфигурации в БД переносит файлы её каталога, включая
посторонние зависимости. Передавайте абсолютный путь к установленному модулю
через `--playwright-module`; например, к `doc-tools/node_modules/playwright`
в отдельном каталоге инструментов. Chromium устанавливается командой
`playwright install chromium` из этого окружения.
Сценарий хранится в конфигурации, например `docs/help/screenshots.json`:

```json
{
  "base_url": "http://127.0.0.1:8080",
  "locale": "ru-RU",
  "viewport": { "width": 1440, "height": 1000 },
  "screenshots": [{
    "file": "call-new.png",
    "path": "/ui/document/А_Звонок/new",
    "wait_for": "#main-form",
    "selector": "main",
    "hide": [".topbar"],
    "steps": [{ "action": "fill", "selector": "input[name='ФИОКлиента']", "value": "Тестовый клиент" }],
    "mask": ["input[name='Телефон']"]
  }]
}
```

Замените имена полей на реальные. Действия: `fill`, `click`, `select`, `wait`.
`hide` скрывает выбранные элементы только на снимке (например, закреплённую
шапку, перекрывающую начало области). `mask` закрашивает выбранные данные.
Используйте демонстрационную базу с синтетическими данными. `click` может
записать данные: сценарии должны явно описывать допустимые действия.

```sh
onebase docs capture --project ./my-config --scenario docs/help/screenshots.json \
  --playwright-module /absolute/path/doc-tools/node_modules/playwright
```

Результат — `docs/help/images/*.png`. Для входа под нужной ролью передайте
`--storage-state <секретный-файл-сессии-Playwright>` вне репозитория. Если пакет
установлен в другом месте, есть `--playwright-module <абсолютный-путь-к-модулю>`.
Без браузера агент обновляет текст и сообщает, какие иллюстрации не обновлены.

## Файлы, БД, версии и резервные копии

Справка переносится существующими механизмами конфигурации: deploy/import,
экспорт, `_onebase_config`, снимки версий, rollback и универсальный `.obz`.
Иллюстрации сохраняются как двоичные файлы. Загрузка из БД считывает книгу
в память до удаления временной выгрузки. При `--watch` изменения в
`docs/help/` публикуются вместе с новой генерацией конфигурации.

Для базы из реестра `docs check`, `docs export` и `docs publish` поддерживают
`--id <ID>`. `docs init` и `docs capture` работают с исходниками на диске;
в конфигурацию БД результат затем загружается обычным deploy.

## HTML и универсальный комплект

```sh
onebase docs export --project ./my-config --output ./my-config-manual
```

Результат: `index.html` с поиском по тексту, страницы глав, `assets/` и
`bundle.json` версии 1. HTML работает без сети. Каталог вывода должен находиться
вне исходников конфигурации. Перед распространением новой сборки используйте
новый пустой каталог: экспорт не удаляет старые файлы удалённых глав.

ID глав должны различаться не только регистром: при `Topic` и `topic`
экспорт завершится ошибкой с обоими ID до создания каталога или записи файлов.
Переименуйте одну из глав в оглавлении и обновите её связи `parent`.
Проверка одинакова на всех платформах, чтобы готовый сайт можно было переносить
на файловую систему без учёта регистра.

`bundle.json` содержит статьи (постоянный id, parent, связи, Markdown и HTML)
и картинки (путь, MIME, Base64). Это независимый от поставщика контракт:
его может читать агент с MCP для Confluence или издатель другого портала.
MCP-сервер должен предоставлять операции записи для публикации.

## Confluence

Встроенный издатель использует REST: Server/Data Center v1 или Cloud v2
(вложения — v1). Специальный MCP не требуется. Корень URL включает контекст
установки: например `https://wiki.example.org/confluence` либо
`https://tenant.atlassian.net/wiki`.

Сначала план, без сетевых запросов:

```sh
onebase docs publish --project ./my-config
```

Для Server/DC передайте ключ пространства, существующую корневую страницу
и PAT в переменной `ONEBASE_CONFLUENCE_TOKEN`:

```sh
onebase docs publish --project ./my-config --url https://wiki.example.org/confluence \
  --space CC --parent 12345 --state ./cc-publication.json --apply
```

Пустой `--user` выбирает Bearer PAT. Для Basic Auth добавьте `--user <логин>`;
в переменной тогда должен быть пароль или API token. `--token-env` меняет имя
переменной. Cloud требует `--cloud`, числовой `--space` и URL с `/wiki`.
Креды не записываются в статьи, комплект или состояние публикации.

Храните файл `--state` между запусками и исключите его и `.lock` из Git:
он связывает id глав с ID и версиями страниц конкретного назначения.
Повторная публикация обновляет те же страницы; неизменённые главы пропускает.
Картинки имеют имена по хешу содержимого. Изменённая в Confluence версия
вызывает конфликт: сначала согласуйте ручные правки с исходниками. Автоматического
объединения нет. При переносе главы к другому parent нужна явная сверка и
обновление состояния. Удалённые локально главы не удаляются из Confluence.

Публикация не является общей транзакцией Confluence. Состояние сохраняется
после каждой созданной и обновлённой страницы; повтор продолжает работу.
После аварии строго между успешным ответом сервера и записью состояния может
потребоваться восстановить ID/версию в файле вручную. При потере состояния
не запускайте публикацию вслепую — восстановите сопоставление существующих
страниц. Отдельного автоматического поиска по названиям нет.
