# Доменный вход в OneBase на Ubuntu

Сотрудник входит в Windows под доменной учётной записью и открывает HTTPS-адрес
базы. OneBase на Ubuntu проверяет билет Kerberos для этого сайта и находит
пользователя базы по SID из билета. Роли и второй фактор задаются в OneBase.
Поддерживается вход пользователей из настроенного домена Active Directory.
Для работы с локальной базой на Windows по-прежнему достаточно лаунчера.

## Подготовка сервера

Ниже используются примеры `erp.example.com` для сайта, `EXAMPLE.COM` для
Kerberos realm и `EXAMPLE` для короткого имени домена. Подставьте свои значения.

1. Настройте DNS и синхронизацию времени с доменом. На Ubuntu настройте
   Samba Winbind для доступа к Active Directory. Проверьте от имени службы
   OneBase, что `wbinfo --name-to-sid 'EXAMPLE\operator'` возвращает SID
   доменного пользователя. [Подключение Ubuntu к AD через Winbind](https://ubuntu.com/server/docs/how-to/samba/member-server-in-an-ad-domain/).
2. Установите системные пакеты `python3-gssapi`, `python3-samba`,
   `winbind` и `krb5-user`. Последний содержит утилиту `klist` для проверки
   настройки.
3. Попросите администратора AD зарегистрировать уникальный SPN
   `HTTP/erp.example.com` и выдать отдельный keytab для этой службы.
   Поместите его, например, в `/etc/onebase/http.keytab` и дайте пользователю
   службы право чтения. Команда `klist -kte /etc/onebase/http.keytab` должна
   показать `HTTP/erp.example.com@EXAMPLE.COM`. Keytab содержит секретные ключи.
4. Опубликуйте базу через HTTPS с действительным для доменных компьютеров
   сертификатом. Разместите обратный прокси на том же сервере и направьте его
   на OneBase по loopback. Прокси должен передавать заголовок запроса
   `Authorization` и заголовок ответа `WWW-Authenticate`. Разрешите встроенную
   аутентификацию в браузере сотрудников для имени сайта.

## Параметры OneBase

Откройте Конфигуратор этой базы под администратором. Выберите **Меню →
Параметры базы → Доменный вход** и заполните поля.

| Поле | Пример значения |
| --- | --- |
| Публичный HTTPS-адрес базы | `https://erp.example.com` |
| Имя службы Kerberos (SPN) | `HTTP/erp.example.com` |
| Домен Kerberos (realm, для Linux) | `EXAMPLE.COM` |
| Путь к keytab на сервере Linux | `/etc/onebase/http.keytab` |

Нажмите **Сохранить настройки** и перезапустите процесс OneBase, который
обслуживает эту базу. Для службы systemd используйте имя службы вашей установки.
Файл keytab остаётся на Ubuntu. Если Конфигуратор работает на другом компьютере,
всё равно укажите путь на сервере. Для редактирования откройте базу с доступом
к её хранилищу. Запись лаунчера типа «Клиент» открывает опубликованный сайт.

У существующих установок при пустых полях действуют значения службы
из `ONEBASE_PUBLIC_URL`, `ONEBASE_WINDOWS_SPN`, `ONEBASE_KRB5_REALM` и
`ONEBASE_KRB5_KEYTAB`. Чтобы вернуть этот режим, очистите все четыре поля,
сохраните и перезапустите базу.

## Проверка с доменного Windows-ПК

1. В Конфигураторе откройте **Меню → Пользователи**. В строке обычного
   пользователя базы нажмите **Аутентификация Windows**. Поставьте галочку,
   введите `EXAMPLE\operator` и нажмите
   **Сохранить привязку**. Эта же привязка видна в Предприятии в карточке
   **Система → Администрирование → Пользователи**. Для следующего шага
   используйте отдельный профиль браузера, чтобы начать новый сеанс.
2. Войдите на рабочую станцию под этим сотрудником. Откройте
   `https://erp.example.com/ui`. При настроенном втором факторе пройдите
   его. В **Система → О программе** должно появиться имя связанного
   пользователя OneBase. Доступные операции соответствуют его ролям.
3. Снимите привязку и повторите проверку в новом сеансе браузера.
   OneBase должен предложить оставшиеся способы входа, разрешённые в базе.

Если карточка на Ubuntu не предлагает привязку, проверьте realm и путь
к keytab в «Параметрах базы». При пустой форме проверьте окружение службы.
Если привязка сохранена, но вход не
происходит, на Windows выполните `klist get HTTP/erp.example.com` под сотрудником.
Так можно отдельно проверить, выдаёт ли домен билет для имени сайта. Ввод
имени локального пользователя рабочего ПК не подтверждает его личность на сервере.
