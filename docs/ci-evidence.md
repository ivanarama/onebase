# Проверки при изменении состояния PR

События `opened`, `synchronize`, `reopened` и `edited` запускают обычный CI.
В частности, редактирование описания сохраняет обязательную проверку
`prclosecheck` внутри `build`: описание разрешает закрытие заявок из сообщений
коммитов, поэтому изменение текста может поменять результат этой проверки.

При переводе Draft в Ready отдельный workflow `CI metadata` исполняет только
код точного доверенного base. Он вычитывает объекты коммитов PR без checkout
его кода и проверяет closing references. Затем проверяет свидетельство уже
выполненного полного CI: точные HEAD/base/merge SHA, workflow, попытку,
окружение, тело PR и все восемь настоящих успешных обязательных jobs.
Свидетельство старше шести часов, частичная история, другой workflow,
изменённый классификатор или генератор свидетельства, пропущенный/отменённый
job и более новый неуспешный запуск не дают права переиспользовать успех.

При совпадении входов старые реальные проверки сохраняются. Новый workflow
не публикует и не подделывает их статусы. Если тот же полный CI ещё идёт,
дополнительный запуск не создаётся и успех не заявляется. При недостатке
доказательств собственная ветка получает настоящий `workflow_dispatch`
существующего CI. Повторный Ready сохраняет идущий `workflow_dispatch` при
совпадении его настоящих входов: HEAD checkout, base, workflow, ветка,
репозиторий и окружение. Его пустое тело события не подменяет тело PR;
closing references проверяет доверенный metadata workflow. Такой dispatch
не используется как доказательство завершённого CI merge-коммита PR.
Если свидетельство идущего dispatch ещё не появилось или не совпадает,
metadata явно требует дождаться результата, сохраняя текущий запуск.

Для fork без доказанного полного CI metadata завершается ошибкой без записи
в GitHub: сопровождающий должен обеспечить безопасный полный PR-прогон
точного HEAD/base перед повторным Ready. Изменение исходников обычно
запускает его событием `synchronize`. Повтор docs-only запуска сохраняет
исходную классификацию и не умеет принудительно включать полный набор;
такой транспорт здесь не поддерживается. Конфликты, обязательное
обновление от `main`, независимое ревью и `ship` проверяются обычным путём.

`classify` сохраняет `ci-inputs-<run_id>-<run_attempt>` с JSON входов. Этот
артефакт сам по себе не является PASS. Он используется только вместе с
результатами всех обязательных jobs той же попытки. `CI_ENVIRONMENT_EPOCH`
можно изменить при смене внешних условий исполнения, чтобы аннулировать
переиспользование прежних результатов. Имена и состав обязательных CI jobs,
их команды, линтеры, полные тесты, лимиты и защита ветки сохраняются.

Тесты `pipelinehealth` компилируют публичный CLI и ghstub один раз на процесс
пакета. Каждый сценарий по-прежнему запускает новый настоящий subprocess
с отдельными fixture и прежними assertions. Ответы CLI, test results и
решения конвейера не кэшируются. Бинари удаляются после `m.Run`.
