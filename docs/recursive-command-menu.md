# Рекурсивное командное меню

Статус: проект контракта в Draft; поддержка и SDK ещё проверяются. Новый YAML
нельзя применять к движку, который поддерживает только `items` / `groups`.

Заказ: сохранить порядок команд и папок исходного командного интерфейса,
включая три папки до команды. Соответствие исходных команд объектам задаёт
конфигурация; движок принимает существующие типизированные `target`.

```yaml
menu:
  sections:
    - id: otk-reports
      title: Отчеты
      nodes:
        - id: otk-search
          target: report:FullSearch
          title: Полный поиск
        - id: otk-masters
          title: Мастера
          roles: [ОТКРуководитель]
          nodes:
            - id: otk-held
              title: Заявки на руках
              nodes:
                - id: otk-held-full
                  target: report:HeldFull
                  title: Полный
        - id: otk-other-command
          target: processor:OtherCommand
```

`menu` остаётся на верхнем уровне подсистемы; для глобального меню — в
`config/home_page.yaml`. Существующие `contents` / `nav` / `nav_by_role`
сохраняют назначение и ограничивают состав.

`sections` — упорядоченные корневые папки. В новом формате `nodes` — один
упорядоченный список команд и папок. Узел с `target` — команда, без `target` —
папка с `title` и `nodes`. Команда не имеет дочерних узлов. Произвольные URL,
JS и обработчики в узлах не допускаются.

ID задаются явно, уникальны во всём меню и соответствуют
`[a-z][a-z0-9-]{0,62}`; `other` зарезервирован. ID не зависит от подписи,
пути папок или цели. Для исходного UUID можно использовать `cmd-<uuid>`.
Повторные входы к одной цели сохраняют разные ID. Повтор цели внутри одного
родителя сохраняет обе команды и выдаёт предупреждение проверки.

Глубина — не более восьми папок, считая корневую секцию. Общие пределы:
100 секций, 500 вложенных папок, 5000 команд. Превышение, неизвестные поля,
повтор ID и смешивание `nodes` с `items` / `groups` внутри одного контейнера
дают ошибку. Старые меню без `nodes` сохраняют прежнюю структуру, порядок и ID.

`roles` у секции или нового узла — необязательный список ролей видимости.
Внутри одного списка достаточно любой роли пользователя; ограничения предков
действуют одновременно. Несколько назначенных ролей дают объединение только
явно разрешённых для них веток. Пустой/отсутствующий список не добавляет
ограничения роли. Администратор видит разрешённый метаданными общий состав.
Эта настройка не предоставляет право запуска: серверные ACL и существующая
проекция `nav_by_role` применяются дополнительно. Персональная перестановка
не снимает исходные ограничения роли при переносе команды из папки.

Недоступные команды и пустые после фильтрации папки скрываются на любой
глубине. Прямые маршруты продолжают проверять собственные права. Конфигурация
операторских ролей и их старое меню не меняются этой возможностью.

Каждая папка сворачивается отдельно мышью и клавиатурой. Состояние хранится
для пользователя, контекста подсистемы и стабильного ID папки; отражается
в `aria-expanded`. При переходе к активной команде раскрываются все её предки,
сохранённые настройки соседних ветвей остаются прежними.

Общие и персональные слои поддерживают вложенные папки, смешанный порядок,
перенос, скрытие, восстановление и удаление собственного контейнера вместе
с потомками. Циклические переносы и превышение глубины отклоняются атомарно.
Исчезнувшие ID остаются устаревшими правилами; они не создают новые цели.
Round-trip сохраняет все узлы. Слои не меняют исходный target или ограничения
роли. Старые слои старого меню продолжают работать.

Приёмка: публичная загрузка YAML и check; HTTP с разными и пересекающимися
ролями; браузерное дерево с тремя папками, смешанным порядком, сохранением
свёртывания, клавиатурой и раскрытием активных предков; отказ прямого открытия
недоступной цели; пустые ветви; round-trip/перестановки/скрытие/восстановление
слоёв; старые плоские и section-group меню. SDK и точные результаты проверки
публикуются отдельно перед применением конфигурации.
