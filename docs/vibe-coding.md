# Разработка конфигурации OneBase с ИИ-агентом

Этот справочник ведёт от установленного CLI до проверки конфигурации через
MCP. Работа ручная: создание YAML и `.os`, просмотр изменений и проверка
результата. Автонастройка из [плана 202](../Plans/202-vibe-init.md) — отдельная
работа; эти инструкции её наличия не требуют.

## Подготовка проекта

1. Установите CLI по [QUICKSTART → Установка](../QUICKSTART.md#установка).
   Проверьте `onebase --version`. Запишите абсолютный путь к исполняемому
   `onebase` (Windows: `onebase.exe`) и версию ИИ-клиента. MCP-клиент может
   иметь другой PATH, чем терминал.
2. Создайте **новый** учебный проект. В примерах `/work/OneBase demo` замените
   своим абсолютным путём:

   ```bash
   onebase init --template tasks "/work/OneBase demo"
   onebase check --project "/work/OneBase demo"
   onebase describe --project "/work/OneBase demo" --compact
   ```

   Ожидаются `OK: ошибок не найдено`, справочники `Исполнитель` и `Проект`,
   документ `Задача`. В корне должны появиться `AGENTS.md` и `CLAUDE.md`:
   создание руководств в `init` выполняется best-effort, поэтому проверьте
   файлы отдельно.
3. Для **существующего** проекта не повторяйте `init`. Сначала сохраните
   пользовательские инструкции, затем сгенерируйте руководство в отдельный
   файл и перенесите нужные изменения в `AGENTS.md` после сравнения:

   ```bash
   onebase ai-guide --project "/work/OneBase demo" --output "/work/OneBase demo/AGENTS.generated.md" --claude
   ```

   `--output` перезаписывает указанный файл. `--claude` создаёт рядом указатель
   `CLAUDE.md`, только если его ещё нет; существующий файл не меняет.
   Указатель ссылается на `AGENTS.md`, поэтому завершите перенос перед работой
   агента. Само `ai-guide --claude` без `--output` файл не создаёт.
4. Откройте в клиенте именно корень конфигурации. Первым заданием попросите
   прочитать `AGENTS.md`, назвать путь проекта и вызвать MCP `check`, затем
   `describe` с `compact: true`. Сверьте реальные ответы с шагом 2.

Общий контракт запуска, список tools/resources и write-флаги находятся в
[docs/mcp.md](mcp.md). OneBase запускается как локальный **stdio**-процесс:
в конфиге нужны отдельные `command` и аргументы, а не URL или shell-строка.
В JSON используйте пути вроде `C:/OneBase/onebase.exe` либо экранируйте `\\`.
Пробел внутри пути не требует дополнительных кавычек внутри строки JSON/TOML.

## Codex CLI: проверенный рецепт

Codex загружает проектный `AGENTS.md`; учитывайте предел размера и более
приоритетные инструкции. Порядок загрузки описан в
[официальной документации AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Добавьте отдельную секцию в `~/.codex/config.toml`, сохранив остальные настройки
и существующие серверы. Если `onebase` уже объявлен, сначала сравните его
настройки; вторую одноимённую секцию не добавляйте:

```toml
[mcp_servers.onebase]
command = "/opt/onebase/onebase"
args = ["mcp", "--project", "/work/OneBase demo"]
```

Замените оба пути. Затем откройте новую сессию `codex` из каталога проекта,
проверьте сервер через `/mcp` и выполните задание из шага 4. Разрешите именно
два вызова `check` и `describe`, если клиент запросит подтверждение.
[MCP-конфигурация и команды Codex](https://learn.chatgpt.com/docs/extend/mcp)
— источник формата; проектная `.codex/config.toml` применяется только для
доверенного проекта.

В живом прогоне такая же секция передана временным CLI-переопределением `-c`,
без изменения пользовательского config. Для headless-проверки разрешены только
`check`/`describe` через их `tools.<имя>.approval_mode = "approve"`;
это не требуется для обычной интерактивной сессии. В ответах tools получены
`OK: ошибок не найдено` и имена `Исполнитель`, `Проект`, `Задача`.

## Claude Code

**Полная проверка клиента не выполнена.** Версия 2.1.273 увидела OneBase как
`connected`, но недействительный OAuth-токен дал 401 до вызова `check`/`describe`.
Восстановление входа и повторный прогон нужны перед публикацией рабочего рецепта.

Проектный MCP-файл — `.mcp.json`, секция `mcpServers.onebase` с
`type: "stdio"`, `command` и `args`. Формат совпадает с
[общим примером](mcp.md#client-config); места хранения и согласование доверия —
[Claude Code MCP](https://code.claude.com/docs/en/mcp#project-scope).

Сгенерированный OneBase `CLAUDE.md` предлагает прочитать `AGENTS.md` словами:
само наличие ссылки не гарантирует загрузку полного текста. Попросите его
прочитать явно. Если нужен импорт, добавьте `@AGENTS.md` в существующий
`CLAUDE.md`, сохранив свои инструкции. Правила версий и импорта —
[Claude Code memory](https://code.claude.com/docs/en/memory#share-one-file-with-other-coding-tools).

## OpenCode

**Полная проверка клиента не выполнена.** Версия 1.18.14 подключила MCP,
но провайдер модели вернул 403; вызовы `check`/`describe` не подтверждены.
Следующий прогон требует доступной модели и повторной проверки tools.

OpenCode использует проектный `opencode.json`/`opencode.jsonc`: запись
`mcp.onebase`, `type: "local"`, массив `command` из абсолютного пути бинаря и
аргументов `mcp`, `--project`, пути проекта; `enabled: true`.
Это другой формат, чем `mcpServers`.
Источник: [OpenCode MCP, local servers](https://opencode.ai/docs/mcp-servers/#local).
Не создавайте второй конфиг поверх существующего JSONC.

Проектный `AGENTS.md` читается как инструкции; `CLAUDE.md` служит fallback,
если `AGENTS.md` отсутствует. Подробности —
[OpenCode rules](https://opencode.ai/docs/rules/#claude-code-compatibility).

## Cursor

**Проверка клиента не выполнена.** Официальные места хранения:
проектный `.cursor/mcp.json` или глобальный `~/.cursor/mcp.json`, секция
`mcpServers`. Для OneBase нужен stdio-процесс с абсолютными путями.
Источник: [Cursor MCP](https://cursor.com/docs/mcp#configuration-locations).
Поддержка проектного `AGENTS.md` описана в
[Cursor rules](https://cursor.com/docs/rules#agentsmd).
Рабочие команды и результат `check`/`describe` для конкретной версии здесь
не заявлены; после установки проверьте их по шагу 4.

## ZCode

**Проверка клиента не выполнена.** Здесь ZCode — клиент с
[zcode.network](https://www.zcode.network/en/docs/mcp-services/), выбранный
[планом 202](../Plans/202-vibe-init.md), а не синоним OpenCode.
Проектный native-файл `.zcode/config.json` использует `mcp.servers.onebase`.
Совместимый `.agents/mcp.json` использует `mcpServers.onebase`, но загружается
только при отсутствии MCP-серверов в native-конфиге этого scope.
Даже native-запись с `enable: false` отключает fallback целиком.
Не добавляйте native-сервер поверх рабочего `.agents` без проверки остальных
подключений. Источник —
[ZCode load rules](https://www.zcode.network/en/docs/mcp-services/#load-rules-and-priority).
Автозагрузка `AGENTS.md` этим клиентом здесь не подтверждена: попросите явно
прочитать файл. Рецепт и результат tools требуют отдельной проверки.

## ChatGPT web

**Проверка клиента не выполнена.** Веб-интерфейс использует доступные ему
удалённые MCP-tools через плагины и не читает локальный Codex config.
Локальная команда `onebase mcp` сама по себе такого подключения не создаёт:

## ChatGPT desktop

## Рабочий цикл и разрешение записи

Начните с задания: «Прочитай AGENTS.md, получи схему и примеры, предложи
минимальные изменения для задачи. После каждой правки запусти check;
покажи дифф и фактический результат проверки».

1. Обзор: `describe`, `schema`, `examples`; при поддержке resources —
   `onebase://ai-guide` и `onebase://describe/compact`.
2. Агент правит YAML/`.os` доступными ему файловыми средствами; проверяйте дифф
   и запускайте `onebase check --project <путь>`. Read-only MCP скрывает свои
   mutating tools, но не ограничивает редактор и shell самого агента.
3. Для переименований/удалений сначала используйте `impact`/`refactor_preview`.
   После одобрения нужной записи измените запуск сервера отдельным действием:
   например, добавьте `--allow-refactor-write` в массив аргументов, перезапустите
   подключение и проверьте появление только нужного write-tool. Верните
   read-only запуск после работы. Полная таблица флагов — [MCP tools](mcp.md#tools).
4. Для проверки обработок используйте учебную копию базы. Создайте
   `processors/Самопроверка.yaml`:

   ```yaml
   name: Самопроверка
   module: Самопроверка
   ```

   И `src/Самопроверка.os`:

   ```bsl
   Процедура Выполнить()
     Сообщить("smoke OK");
   КонецПроцедуры
   ```

   Затем выполните:

   ```bash
   onebase check --project "/work/OneBase demo"
   onebase migrate --project "/work/OneBase demo" --sqlite "/work/demo-test.db"
   onebase procrun --project "/work/OneBase demo" --sqlite "/work/demo-test.db" --proc Самопроверка
   ```

   Ожидается `smoke OK`. `migrate` меняет схему, `procrun` исполняет обработку и
   может менять данные. Для MCP-версии `procrun` требуется отдельный
   `--allow-procrun`; при работе с базой также передайте серверу её
   `--sqlite`/`--db`. Read-only `check`/`describe` для файлового проекта этого
   подключения к постоянной базе не требуют.
5. Перед записью конфигурации в базе получите `config_versions`, сохраните ID
   снимка и проверьте дифф. После изменений повторите `check` и пользовательский
   сценарий; откат версии доступен отдельно через `--allow-config-rollback`.

Общие CLI-команды и JSON-RPC запуск из этого раздела проверены на указанном
OneBase: `ai-guide`, `check`, `describe`, `migrate`, `procrun`; прямой MCP также
подтвердил отсутствие `fmt_write`, `refactor_write`, `config_rollback`, `procrun`
в read-only списке. Эти проверки не заменяют проверку каждого ИИ-клиента.

## Если подключение не работает

| Симптом | Что проверить |
|---|---|
| Бинарь не найден | Абсолютный `command`, права запуска, `--version` вне клиента |
| Видна другая конфигурация | `--project` и корень открытого проекта; пути переданы отдельными аргументами |
| Сервер connected, tools не вызываются | Доступ к модели и разрешения клиента; 401/403 не являются ошибкой OneBase check |
| Нет write-tool | Нужный точечный флаг запуска и перезапуск MCP; read-only — исходный режим |
| `check` сообщил ошибку | Исправить первую диагностику и повторить `check`, не считать ответ агента доказательством успеха |
| Руководство устарело | Сгенерировать отдельный файл через `ai-guide`, сравнить и сохранить пользовательские инструкции |

При новой проверке фиксируйте дату, ОС, версии клиента/OneBase, конфиг без
секретов, имена реально вызванных tools и их ответы. Следующий подтверждённый
рецепт можно добавить отдельным PR.
