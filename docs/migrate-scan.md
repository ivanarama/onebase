# Замер BSL перед переносом конфигурации 1С

В Конфигураторе 1С выгрузите конфигурацию в каталог XML-файлов с исходными
модулями `*.bsl`. Укажите этот каталог команде:

```sh
onebase migrate-scan /path/to/export
onebase migrate-scan /path/to/export --json > scan.json
```

Команда читает файлы, не исполняет BSL и не изменяет выгрузку или базу.
Файлы `.cf`, `.dt`, архивы и внутренний формат EDT не являются её входом.
Каталог должен содержать хотя бы один модуль BSL. Символьные ссылки
отклоняются, чтобы состав замера не зависел от файлов вне выгрузки.

## Состав БСП и объём

Все `*.bsl` учитываются в объёме конфигурации. Принадлежность библиотеке
определяется через `Subsystems/СтандартныеПодсистемы.xml`: `Content` (`Contents`
также принимается), ссылки `Subsystem.*` и дочерние `ChildObjects/Subsystem`
обходятся транзитивно. Общий модуль, справочник, документ и другие объекты,
включённые в состав БСП, передают принадлежность своим модулям, включая формы.
Объект определяется по стандартному пути `CommonModules/<имя>/…`,
`Catalogs/<имя>/…`, `Documents/<имя>/…` и аналогичным путям выгрузки.
Неполная, циклическая или повреждённая цепочка подсистем завершает команду
ошибкой без частичного отчёта.

Без подсистемы `СтандартныеПодсистемы` все модули считаются прикладными.
Имя `ОбщегоНазначения` само по себе ничего не доказывает. В число подсистем
входит корень; в число общих модулей БСП входят все ссылки состава, в том
числе модули без BSL. Строки считаются физически, включая пустые строки и
комментарии; завершающий перевод строки не создаёт дополнительную строку.
CRLF, LF и CR дают одинаковое число строк.

## Частоты и концентрация

В прикладных модулях считаются лексические обращения
`ИмяОбщегоМодуля.ИмяМетода(` к общим модулям БСП. Регистр и пробелы вокруг
точки/скобки не влияют на группировку. Вызовы внутри строк, комментариев и
цепочек вроде `Объект.Модуль.Метод()` исключаются; код вне процедур также
учитывается. Каждое повторное обращение на одной строке считается отдельно.
Колонка «Файлов» показывает число разных прикладных файлов с этим обращением.

Это кандидаты вызовов: анализ не разрешает области видимости, локальные
переменные с именами общих модулей, препроцессор или динамические вызовы.
Внутренние вызовы самой БСП в таблицы прикладных обращений не входят.

Отчёт содержит полный рейтинг модулей и пар «модуль.метод», отдельную
агрегацию имён методов по всем модулям, число методов с одним-двумя вызовами
и доли топ-10/25/50/100 методов. Полный рейтинг позволяет построить кривую
концентрации для любого размера топа. Точки входа каждой подсистемы считаются
по её составу вместе с потомками; подсистемы могут пересекаться, поэтому
их строки нельзя складывать как независимые группы.

## W040 и совместимость

`raw_w040_profile: "plan179-w040-v1"` фиксирует 30 исторических фрагментов
W040, по которым составлялся план 179. Импортер уже проверяет часть
конструкций по сигнатуре; изменение его диагностик не меняет этот профиль.
Считаются все точные, чувствительные к регистру вхождения на строках,
которые после удаления начальных пробелов не начинаются с `//`. Строковые
литералы и хвостовые комментарии в этой сырой метрике остаются. Это
воспроизводимый поиск фрагментов, а не синтаксическая диагностика.

`compatibility_status: "not_evaluated"` и пустой список
`confirmed_incompatibilities` означают, что проверка совместимости **не
проводилась**. Пустой список не означает совместимость всей конфигурации.
Реестр проверенных сигнатур и исполняемых примеров — отдельный срез плана.

Исторические числа УТ 10.3 и УТ 11.5 в плане 179 остаются первичными данными
автора ручного замера. Публичная синтетическая фикстура проверяет алгоритм
команды; она не подтверждает эти числа. Для независимой сверки нужны обе
исходные выгрузки и согласование правил ручного подсчёта с этим профилем.

## Кодировки и формат отчёта

`--encoding auto` выбирает UTF-8, UTF-16LE или UTF-16BE по BOM. Без BOM
валидный UTF-8 принимается как UTF-8, остальные байты — как Windows-1251.
Это эвристика: для неоднозначного ввода задайте кодировку явно:

```sh
onebase migrate-scan /path/to/export --encoding windows-1251 --json
onebase migrate-scan /path/to/export --encoding utf-16le --json
```

Допустимы `auto`, `utf-8`, `windows-1251`, `utf-16le`, `utf-16be`.
Явный выбор применяется к XML и BSL; противоречащий BOM, неверный UTF-8,
непарный суррогат UTF-16 и неопределённый байт Windows-1251 вызывают ошибку.
Для смешанных файлов используйте `auto` с BOM у UTF-16.

JSON имеет `schema_version: 1`, одинаковый порядок массивов и относительные
пути с `/` на всех платформах. Частоты сортируются по убыванию количества,
при равенстве — по имени; пути и подсистемы — по имени. Отчёт не содержит
времени замера, абсолютного каталога, содержимого или хешей исходников.
`sources` содержит путь, кодировку, число строк и принадлежность БСП для
каждого модуля. Имена объектов и относительные пути могут быть клиентскими
данными — учитывайте это при публикации отчёта.
